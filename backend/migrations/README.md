# 数据库迁移（代码基线）

本目录中的数字迁移面向 PostgreSQL 16+，必须按连续文件名顺序执行；部署预检会动态发现当前最高序号并拒绝缺号，不在代码或本文档硬编码迁移上限。当前代码基线到 `0073`，迁移不含任何真实案件数据。已在当前本机受管测试栈连续前向应用至 `0073`，并对关键 JSON 形状、最小权限、失败恢复、已验证律师决策包来源白名单与确定性文书版本链执行真库正反例检查。以上只证明对应本地 schema/合同可执行，不表示迁移已应用到生产，也不证明真实 OIDC/MFA、生产私有 S3、真实客户案件、多律师并发或生产备份恢复已达到 `PROVEN`。

迁移包含的安全语义：

- `firm_id` 作为所有案件数据的直连租户键；
- 强制 RLS，应用事务必须用 `SET LOCAL app.firm_id = '<firm uuid>'` 建立租户上下文；
- 乐观并发由 `matters.version` 支撑；
- 幂等键范围固定为“律所、案件、调用者、命令、键”；
- 审批绑定版本、对象哈希、批准人和权限快照；
- 只允许每案一个有效的锁定提交包；
- `audit_events` 用数据库触发器拒绝更新和删除；
- 事务 Outbox 供异步 Worker 在提交后消费。
- 证据派生任务以短租约、最多三次恢复、Manifest 哈希和双 `VERIFIED` 输出门控制完成状态。
- 正式利息计算只引用已批准案件法律规则包与已确认交易/付款分类，保存逐期明细、逐笔冲抵、人民币币种、输入输出哈希和独立复算哈希；上游正式变化会使依赖结果失效。
- 正式法源保存官方 URL、精确条款位置、抓取时间、内容哈希、加密对象引用、核验/许可状态和替代链；LPR 倍数规则将司法解释依据快照与中国货币网利率参数快照分开绑定，规则利率由数据库公式派生，浏览器不能向正式计算提交利率。
- `0020` 仅在复核通过的中国货币网 LPR 抓取被服务端从已认证加密原件重新解析后，追加保存各期一年期/五年以上 LPR 观察记录；规则只能按同一快照的精确定位读取一年期数值，观察记录受 RLS 和禁止更新/删除触发器保护。
- 法源登记命令还必须配置本机加密对象读取器，登记前完成解密认证和明文哈希复核；仅凭数据库对象键不能建立正式来源。
- 规则所需事实键必须由主办律师绑定到同案、已有证据且状态为 `CONFIRMED` 的事实；法律事件、事实绑定、规则版本、来源快照和连续期间全部齐备后才能批准案件规则包。
- 法院提交 ZIP 只接收同案、已批准、内容寻址的 PDF 成品，并锁定证据 Manifest、法律规则包、计算结果和最终文本审批；内部哈希清单作为单独加密对象保存，不混入法院文件。
- 官方法源抓取任务绑定律师授权、完整 URL、查询哈希、一次执行、短租约、响应哈希、加密对象和解析输出；抓取成功只进入 `REVIEW_REQUIRED`，另有不可变律师复核记录后才可进入正式来源登记。
- 新登记正式法源必须保存律师核对的公开访问/加密保存/案内使用依据及哈希；旧快照缺少这组许可复核时不能支撑新的规则或规则包审批，系统不会为历史记录虚构依据。
- 本地案卷盘点只保存相对路径、文件哈希、类型、变化类别和批准谱系；绝对路径、短时文件夹 grant 与会话令牌不进入数据库。新盘点先为候选，只有主办律师批准后才替代当前案卷范围并使依赖旧范围的交付链失效。
- 材料接收任务只引用已批准盘点及相对路径，逐文件短租约处理；正式登记前必须保存本机恶意文件扫描器及定义版本、结构检查哈希和明确结果。非 PDF 不伪造页数，进入转换/人工处理队列。
- Word/Excel 草稿必须把可编辑加密对象和隔离渲染 PDF 一并登记；两份对象、渲染回执和共同复核哈希均受内容寻址约束，入库前重验容器/PDF。数据库只允许从候选状态转换为绑定共同哈希的律师确认，不允许删除或其他改写。
- 外部模型、OCR 与 MCP 调用账本的次数和成本上限必须附 ISO 4217 币种；为不改写既有追加记录，历史迁移只标 `XXX`（未计价），应用层拒绝新增未明确币种的预授权。
- 文书一致性审查只保存当前已批准 PDF 工作产物、审查输入/输出和字段/来源引用的哈希，以及阻断/警示代码；它不保存文书正文、确认值或提示词。提交 QA 只能引用覆盖完全相同工作产物集合、绑定当前案件版本且无阻断项的审查记录。
- Agent 文书候选只保存加密对象引用、内容/执行/复核哈希、技能工具、律师决定和最终 Agent 提案关联；候选正文与模型提示词不进入 SQL，候选只能被一次性批准或驳回。
- `0027` 的 ZIP 材料包只保存服务器校验后的归档哈希、受限逐文件清单和私有对象绑定；`OBJECT_STORED` 仅表示待后台逐文件处理，不表示 PDF 证据已经入卷。
- Web Agent 材料整理任务以精确证据页绑定、律师外部调用授权、代理身份/程序上下文哈希、短租约、最多三次领取、提交已开始账本和只读候选控制；未确认代理身份时只可排队中性盘点，不得外发模型，模型结果始终等待律师复核。
- `0029` 将当事人、程序、程序地位与律所委托分别版本化并合成当前代理态势；它不把“原告/被告”映射成固定材料或固定文书。
- `0030` 保存由当前代理态势、已确认诉请/程序事实、官方法源和律师目标驱动的动态办案计划。无当前依据的建议只能标为待研究或待补信息；法院提交包的必要文书必须精确投影自当前已确认计划，而非浏览器参数或固定答辩状假设。
- `0031` 将目标、Agent Run、不可变事件、任务图/依赖、审批、尝试租约、外部提交开始标记、结果回执、成果、检查点和 Agent 命令审计纳入统一控制平面。事件必须通过代码 Supervisor 归约后写入；任务头和 Run 头只是可重建投影。外部边界开始标记一经写入不可改写，结果不明只进入核验，不得自动重发；SYSTEM_WORKER 必须是 `users` 中 ACTIVE、且同案只获单一 Worker 角色的服务身份，不能创建律师目标或批准结果。Agent 事件版本与案件台账版本是两个独立版本域，不写入既有 `audit_events` 的案件版本列。
- `0032` 将 Agent 工作记忆、同案长期记忆、律师个人知识、律所知识和公共法源记忆保存为不可变版本、当前头、来源引用与先行撤权/墓碑；同案和律所记忆使用显式权限组，跨案知识只引用经双人审查的脱敏发布对象，公共法律记忆只绑定当前已核验且许可有效的官方快照。检索必须在同一受控事务中先从当前案件角色、版本和未撤销组成员资格构造短时授权集合，只在该集合内执行 PostgreSQL FTS，再重读授权和权威记录后返回；向量检索尚未实现，不能对外宣称混合 RAG 已就绪。
- `0033` 以同事务触发器把 Agent Run 新建和每次事件版本前进投影到可恢复 inbox；通知仅用于加速，持久行才是重启恢复依据。首批可执行文件白名单只是已登记 PDF 页与扫描后入库的 DOCX/XLSX；PPTX、RTF、TXT、CSV、HTML、EML 和图片仍需独立受控适配器，不能宣称“任意文件”已完成。技能输出只以加密对象+哈希元数据进入待律师复核候选区，不写入正式事实、交易或法律结论。
- `0034` 以与执行 Worker 不同的 `SYSTEM_WORKER` 身份建立独立验证尝试，将重读受管对象后的逐制品格式/哈希/谱系回执与 `VERIFICATION_PASSED` 或 `VERIFICATION_FAILED` 在同一数据库事务中追加；未知存储故障只保留 `STARTED` 供恢复，不猜测成功或失败。一次性本地迁移不代表真实对象库、独立验证进程或生产运行时已接通。
- `0035` 将律师对当前 Agent 任务的“不批准”记录为来源绑定、版本化的结构化纠正信号，并在同一事务追加 `LAWYER_PLAN_CORRECTION_RECORDED` 事件；旧任务和成果随即过期，持久 Worker 只能根据新的权威规划快照重新规划。浏览器不能提交计划分类、状态、来源、哈希、Tool 或替代任务图，自由说明也不能成为命令。
- `0036` 把 ACL-first FTS 检索的最小摘要、权威来源引用和哈希作为独立的规划前增强回证，精确绑定 Run 创建律师、目标、案件版本、基础规划快照、完整查询契约和最终授权时间。Worker 必须从数据库解析并复核 Run 创建者的当前角色和权限组；撤权、案件版本或记录版本变化即丢弃旧回证。回证不保存查询原文、索引全文、对象键或 URL；同案客户摘要默认只留在服务端，只有外部 Planner 契约和精确外发授权同时有效时才可进入外部规划投影。这个垂直切片暂不向浏览器投影长期记忆内容，也不代表运行时已接通。
- `0037` 将当前同案争点/动态办案计划/已核验法源缺口绑定为服务端私有问题和最小公开词，只允许已由律师批准的 A3/`LAWYER_REVIEW` 任务对 `api.search.brave.com` 发出一次无跳转 HTTPS GET。它复用 `0031` 的 `SUBMISSION_STARTED` 边界，另行保存一次性 egress grant、DNS/连接 peer 回证、私有 S3 精确响应封存和追加式 outcome；结果不明只能核对该确定性封存键，不得重发。搜索结果始终是待律师复核的公开研究线索，不是正式法源。
- `0038` 新增已入卷单页 JPEG/PNG 原生图片的私有对象绑定，并为 Qwen 视觉 OCR 增加一次性 exchange/outcome 恢复账本。Worker 必须重新校验当前 Run/任务/尝试、律所/案件/页面、原件哈希和对象元数据；只有 `0031` 的 `SUBMISSION_STARTED` 已可见才能插入 exchange 并发起一次固定 Qwen HTTPS POST。响应按字节哈希私有留存，不明结果只读账本不重发；对外仍只能产生 `NEEDS_LAWYER_REVIEW` 候选。模型、浏览器均不能提交路径、URL、提示词、provider 或密钥。
- `0055` 将 Qwen OCR 已收到的完整 HTTP/响应拒绝与网络结果不明分开：前者以受控错误码终止为 `FAILED`，后者仍为 `UNKNOWN_SUBMISSION` 且只能查账本、不得重发。失败账本不保存响应正文、异常文本、凭据或案卷内容。
- `0056` 为 Qwen OCR 的 `UNKNOWN_SUBMISSION` 仅增加 DNS、连接、发送、响应头、响应体五个受控阶段码；状态仍只读恢复且不得重发，账本不保存异常文本、地址、请求/响应正文、凭据或案卷内容。
- `0057` 修复 Qwen OCR 成功回执的 PostgreSQL provider request ID 约束：字符集合与 1..500 长度分开校验，避免数据库 ARE 对 `{1,500}` 的非法区间拒绝；已有未知请求保持追加式且不得重发。
- `0058` 为已由管理员核实的 Qwen 本地成功回执持久化故障增加追加式解决回证。原 `UNKNOWN_SUBMISSION` 不改写；Worker 只能读取该回证并把任务终结为本地失败，不能恢复正文、伪造供应商成功或重发请求。
- `0059` 将 Qwen OCR exchange 的数据库防篡改触发器更新为当前运行时策略哈希，并把该哈希加入 Worker 启动预检；OCR 提示词/来源绑定策略变更后若未先做显式前向迁移，Worker 会在启动时失败关闭，而不是运行到发送边界后留下未知任务。
- `0071` 仅允许无任何外部调用、无未知结果的本地可恢复失败以追加式新执行尝试重用同一已激活计划，不重跑已付费规划模型，不改写历史执行。
- `0072` 将「已验证律师决策包」作为唯一新来源类型加入文书包数据库白名单；形状、哈希、版本、来源唯一性与不受控类型拒绝规则保持失败关闭。
- `0073` 为已独立验证的文书包增加追加式确定性版本链、幂等更新请求、可恢复 Worker inbox 与独立复核回执。只有精确重读后 `PASSED` 的后继版本才能成为当前交付件；失败或结果不明的旁路尝试永久保留审计，但不占用已验证链位置，也不会让旧模板文书继续可下载。
- `0039` 将动态办案计划中的文书事项展开为服务端授权来源清单，并把来源类型、版本、权威哈希、文本摘要、模板哈希、代理态势和当前计划共同绑定到不可变文书包。每个包同时保存结构化候选、可编辑 DOCX/XLSX 和隔离 PDF 预览的私有对象回执；执行时和独立复核时都必须重新核对当前计划、代理身份和来源有效性。三件套始终为 `NEEDS_LAWYER_REVIEW`，不写入正式事实、法律结论、提交包或法院状态。
- `0042` 将独立验证通过的事实/交易成果自动落入私有、追加式律师复核区；暂存事件不写 `audit_events`/Outbox、不推进 `matters.version`。服务端按来源回读、置信度、模型风险和现有台账碰撞固定划分完整低风险组与例外组；主办律师只能一次确认整个低风险组，浏览器不能挑选候选子集、页 ID、正文或哈希。确认事务重读来源并只把低风险候选写入正式事实/交易台账，同时推进一次案件版本。
- `0043` 只允许 SYSTEM_WORKER 从当前 Run 的 PASSED 图谱、目标、代理情境、权威快照和精确来源绑定生成不可变 0030 `CANDIDATE`；它不生成法院必备文书、不自动激活计划，也不接受浏览器/模型提交计划内容。因 `purpose` 新进入规范哈希，已有旧计划的安装必须先执行显式、可审计的失效与重规划，迁移不会伪造回填。
- `0044` 为不可变动态办案计划事项增加一次性、追加式律师复核。逐项批准不推进案件版本；提出调整或驳回会在数据库层永久阻断旧候选激活并写入重规划 Outbox，不能伪装成原计划已被编辑。整案激活只接受浏览器案件版本与幂等键，服务端在同一事务选择最新候选并重验计划哈希、当前代理档案、PASSED Agent 图谱、来源和逐项复核。三种复核决定都写入脱敏追加审计；`audit_events` 仅对该非变更事件允许输入/输出版本相等，其他事件仍必须严格前进。
- `0045` 为 DeepSeek 事实/交易候选提取增加独立的一次调用交换账本。只有 `0031` 已提交的精确 `STARTED` run/task/attempt/request 哈希可建立交换；固定官方 HTTPS endpoint、模型和响应 schema 后才允许一次网络调用。原始响应先进入加密私有对象库并经 HEAD/GET/SHA-256 复核，随后才解析；超时、提交回执丢失或结果不明只按确定性对象键核对，绝不再次发送。exchange/outcome 均追加式、强制 RLS，能力启用前还必须同时预检 `0042` 的私有律师复核落点。
- `0046` 把 `0042` 低风险整组确认产生的权威 Outbox 事件投影为持久 `case_agent_snapshot_refresh_requests`。Worker 只能消费服务器派生的最新请求，在同一事务重读当前案件快照、追加 `CASE_SNAPSHOT_CHANGED`、更新 Run 投影/检查点并标记请求 `APPLIED`；Supervisor 随后派生 `REPLAN`。仍有未处理复核记录时请求保持阻断，同时数据库禁止对应旧图谱进入 `0043` 晋升或 `0044` 激活。
- `0047` 将 `0042` 的完整异常通道按候选类型、规范原因、来源策略和风险策略固化为不可变组，只允许当前主办律师对整组选择 `REJECT_AS_DUPLICATE`、`REQUEST_REEXTRACTION`、`REQUEST_MORE_EVIDENCE` 或 `DEFER_WITH_REASON`。分组成员、决定、事件和批次终态均追加式并校验完整性；snapshot refresh 以同一 Run 的完整低风险/异常复核证明为门，纯异常 Run 也能产生服务器派生刷新。这里的“已分流”只表示路由决定已记录，不表示后续工作已经完成。
- `0048` 将低风险整组确认和异常整组决定收紧为数据库拥有的 Web 会话授权。隔离的 `NOLOGIN`/`NOINHERIT`/`NOBYPASSRLS` owner 先从服务器持有的短时会话解析 ACTIVE 用户和当前 `LEAD_LAWYER`，再签发短时、追加式确认许可；服务端重读精确来源页后，最终函数重复校验候选集合、来源绑定、案件版本和幂等请求再写正式台账。浏览器不能选择 actor、候选子集、正文、页 ID 或哈希；现有 session schema 仍不能由 PostgreSQL 单独重证上游 MFA 仪式。
- `0049` 将 `0047` 的非去重路由物化为有当前头的 `ACTIVE` 后续事项：重新提取必须把当前图谱任务精确绑定到原异常组完整来源并在独立验证、私有暂存后按同一图谱集合终结；补充证据只能绑定同案受管对象；延期必须由律师恢复、撤回或替代。Web 只读取分页安全投影并提交受限动作，Worker 只调用专用函数；控制 Run、刷新 Outbox、追加审计和恢复状态保持可追溯。任一 `ACTIVE` 后续事项都会在数据库层阻断 `0043` 计划晋升和 `0044` 激活。迁移同时为可达 SECURITY DEFINER/触发器函数固定可信 `search_path`、撤销 `public` schema 创建权限，并把应用角色限制为最小表/函数权限。
- `0050` 关闭异常控制恢复中“替代 Run 已创建但控制尚未转移”的抢跑窗口：先提交不可变、会话授权的恢复意图，未 `TRANSFERRED` 的替代 Run、旧控制 Run 及升级期遗留孤儿 Run 均由 wake/claim 围栏保持 `QUIET`/不可领取；控制转移与恢复意图终态、旧 inbox 停放和新 inbox 激活在同一事务完成，并与领取共享事务 advisory lock。迁移不会把一次性本地迁移测试冒充真实故障恢复、并发压力或生产权限证明。
- `0051` 收窄 Web/Worker 对恢复表的可读列，使会话 UUID 等授权素材不再被后台 Worker 或普通 Web 表级 `SELECT` 暴露；既有数据库通过前向迁移撤销旧宽权限，新建库也在原迁移权限段直接使用同一列级合同。
- `0052` 把每个恢复意图与服务端固定语义的 `goal_id/goal_hash` 不可变绑定：恢复目标 ID 由替代 Run ID 派生，数据库独立重算 canonical hash，并在 prepare/resume、Run wake、transfer 和 Worker claim 两阶段均 fail-closed 复核。普通 create-run 即使猜中已准备的 Run UUID，也不能用浏览器或模型自选目标占用它。
- `0053` 把首次 Run 中律师显式选择的 `CASE_REVIEW_MEMO`/`PAYMENT_LEDGER` 成果意图按规范 JSON 与目标哈希持久化；主办律师激活动态计划后，只有服务器重读当前 `ACTIVE` 计划、精确可执行文书项及来源 Run 才能不可变绑定第二次 Run。每个计划最多一次显式执行，不由激活触发器自动调用模型；模板类型、输出格式和计划项均不可由浏览器伪造。

## 尚未具备的条件

- 数据库管理员角色与应用角色必须分离；迁移使用 `FORCE ROW LEVEL SECURITY`，但超级用户和具备 `BYPASSRLS` 的角色仍须严格隔离；
- 仍需审核生产迁移账号与三类最小权限角色、在部署同构 PostgreSQL 中重跑完整集成/并发测试，并完成备份与恢复演练；
- 迁移工具、部署密钥、真实连接串和真实案件数据均不在本仓库。

因此本文件记录的是可审阅、曾在一次性本地 PostgreSQL 中执行的迁移代码基线，不是已经启用或验收的生产数据库。
