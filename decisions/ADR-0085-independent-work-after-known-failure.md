# ADR-0085：已知局部失败不阻断独立工作

状态：Accepted

日期：2026-09-05

## 需求与计划

律师不应因一项局部处理失败而失去其他可完成的工作。先改状态推导与持久契约，再验证独立分支、依赖阻断、审批与历史回放；不增加模型重试或另建恢复脚本。

## 决策

- 新 Web 创建的运行在创建事件中明确记录 `ISOLATE_KNOWN_TASK_FAILURES_V1`；缺省为旧策略 `STOP_ON_TASK_FAILURE_V1`。旧事件序列化结构、回放行为不变，不改写历史任务。
- 新策略下存在 FAILED 时，如果还有 READY、RETRYABLE 或 RUNNING 的独立工作，运行保持 EXECUTING；只有独立待审批工作时保持 WAITING_APPROVAL。没有可继续工作时进入 WAITING_INPUT。
- 依赖只由 SUCCEEDED 满足，失败节点及其后继不得派发。UNKNOWN 仍优先进入对账并阻止派发；既有重试、预算、权限、暂停、取消和快照失效规则不变。
- 不新增对失败任务的自动修复、重试或重规划。不得把部分成功当作整案完成，完整验证仍要求所有任务成功。
- 界面明确说明局部失败及其影响；终止在技术错误时不再一概要求律师补资料。

## 范围与风险

本阶段实现独立分支继续，不代表已完成错误自动修复或部分文书终审。固定串行计划也不会凭此产生新分支；后续仍需改进正常规划与律师修订闭环。
策略仅由服务端设置，浏览器不能通过请求正文提升权限。事件策略持久化，不用部署日期猜测行为。
