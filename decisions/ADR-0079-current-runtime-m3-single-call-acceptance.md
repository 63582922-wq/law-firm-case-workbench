# ADR-0079：以当前运行时验证完整 Agent 链路的独立 M3 单次合成验收

状态：`Accepted`

日期：`2026-09-05`

## 背景

M2 已在独立的 88 页合成民间借贷案件中完成一笔 `qwen3.7-plus` 外发，并获得可认证的正常结束原始响应。
但它在当时的严格解释器下进入 `WAITING_INPUT`。后续的只读解释、法条投影和文书回放证明当前代码可以把
该封存响应编译为 `NEEDS_LAWYER_REVIEW` 候选，却不能改写 M2 的历史任务、为其持久化成果，或绕过 Web
接口对未完整复核成果的拒绝。当前 API 的真实会话读取也确认了该拒绝门仍在生效。

因此，M2 不能证明“当前解释器 + 当前 API + 当前 Worker + 当前动态计划 + 当前文书交付”的正常状态机能够
向律师提供一个可审阅的成果。把 M2 回放结果硬写回历史运行会破坏不可篡改审计；停留在只读回放又无法验证
当前用户链路。

## 决策

1. 允许且仅允许一个显式命名的 M3 合成验收：
   `m3-current-runtime-full-flow-acceptance`。它只能由
   `--source-qualified-m3-current-runtime` 显式启动，拥有独立的案件、运行、会话、幂等键和规则版本命名空间。
   它不读取、续接、恢复、改写或重发 M1/M2 的 Agent 运行。
2. M3 只使用现有 88 页、11 文件的全合成案卷，绝不包含真实客户资料。启动后、任何模型调用前，必须在
   只读数据库事务中找到同律所已批准的公共法源绑定，并逐项验证来源 ID、发布者、URL、媒体类型、SHA-256、
   条款定位、效力等级、许可状态和批准状态。捕获时间必须在 24 小时窗口内。只有随后对同一精确对象的认证
   读取和向 M3 私有范围的无覆盖复制都成功，才可继续；不得回退访问公网、替换来源或扩大来源范围。
3. M3 的首轮只允许一笔 `qwen3.7-plus` 律师决策包调用。现有硬门保持不变：`max_attempts=1`、
   `max_external_calls=1`、`NEVER_AUTOMATIC`、300 秒传输上限、360 秒任务预算、420 秒租约，以及
   120 分（1.20 元）最高成本。任何外发状态不明、合同拒绝、预算超限、来源/权限失败或超时都保留现场并
   停止；不得创建 M4 或自动重试。
4. 仅在首轮严格通过后，M3 才按当前代码生成动态计划候选、完成合成夹具内的受控计划复核、执行零外部调用
   的文书轮，并读取回可编辑 DOCX 和审阅 PDF。所有自动批准仅是固定合成夹具的服务器端验收动作，不能被
   表述为执业律师批准；成果始终是律师复核候选，不得锁定、签署、发送或提交。
5. M3 不是商用发布或律师验收门。它只补足一个证据缺口：当前受控运行时的正常状态机是否能在一宗合成案中
   从已登记材料与法源走到可下载、来源绑定、待律师复核的答辩状候选。

## 原因

- 当前 API 已实测拒绝 M2 的未完整复核 Agent 成果；这说明历史保护和权限门有效，也说明它不能替代正常
  交付验收。
- M3 的来源来自同律所、同哈希、时效受限的已批准公共法源，不引入新的公网波动或真实客户数据路径。
- 单次预算、独立身份和不可自动重试把“必要的完整验证”与“为得到成功而反复调用模型”严格区分开。

## 后果

- M3 成功时，可证明一条当前运行时的合成 Agent → 律师复核文书候选链；仍不代表真实案件、律师认可、
  跨租户/恢复/备份演练、供应商治理或商用放行。
- M3 阻断或失败时，项目必须以该次持久化证据诊断，不能自动再建运行或调整后重试。
- M1/M2 的历史状态和任何已认证外发记录保持原样。M3 的结果必须作为独立事实记录。
