# ADR-0012：生产登记信任必须门限签名、可轮换并阻断回滚

状态：已接受（代码、合成测试、桌面握手与原生导入链完成；仓库默认仍为 `NOT_CONFIGURED`）

## 背景

只在安装包里固定一个长期签发公钥，会把密钥轮换、人员离任、密钥泄露和离线客户端更新变成不可控风险；允许页面或环境变量填写公钥，则任何本机使用者都可能建立自己的“律所信任”。同时，浏览器把登记凭证直接写入 Keychain 会绕过验签字节、设备绑定和并发覆盖检查。

## 决定

1. 正式安装包只固定 1—8 个离线目录根公钥和门限，不包含任何私钥、测试根或可由页面修改的信任配置。
2. 律所登记目录采用严格、规范化 JSON 和 Ed25519 门限签名，提供当前 HTTPS DNS 服务源、1—3 个 TLS SPKI SHA-256 固定值及最多 32 个签发公钥。
3. 目录有整秒 UTC 签发/到期时间，最长 366 天；版本只能连续增加 1，并精确绑定上一目录规范化字节的 SHA-256。过期、未来签发、跳版、回滚、混链、未知字段、重复字段和签名门限不足全部关闭登记。
4. 签发公钥分为 `ACTIVE`、`RETIRED`、`REVOKED`。退休公钥只能验证退休时点前签发且仍在密钥有效期内的凭证；撤销公钥不再验证任何凭证。目录始终至少有一个当前有效的活动公钥。
5. 本方案借鉴 TUF 的签名元数据、到期、版本单调和前序链原则，但当前不是完整 TUF 客户端，不宣称已实现 TUF 全部角色、镜像或委托规范。
6. 发布仓库携带的 bootstrap 固定为 `NOT_CONFIGURED`、零根、零门限、空目录。生产发布必须由律所运营流程替换为公开根和已签目录；配置错误时 sidecar 仍可显示禁用健康状态，但不开放登记验签路由和案件路由。
7. 桌面父进程为每次 sidecar 启动生成独立 256 位私有令牌。令牌不进入 WebView、状态 JSON、日志或命令参数；登记验签路由只接受携带该令牌的本机父进程请求。
8. WebView 只能发起“选择登记包”，不能提交路径、凭证、公钥、人员、律所或角色。Rust 原生层只读取用户通过系统文件选择器选中的 16 KB 内 `.lawenroll` 普通文件，从 Keychain 计算安装绑定摘要，经 sidecar 当前目录验签后，按已验字节 SHA-256 和当前凭证哈希 compare-and-set 写入并回读复核。
9. 验签/保存成功仍不等于案件可访问。启动会话和每次案件操作还要分别通过登记时效、律所成员状态、专用数据库及逐案角色核验。

## 依据

- [The Update Framework Specification](https://theupdateframework.github.io/specification/v1.0.26/)：签名元数据、过期、版本与回滚/冻结攻击防护原则；
- [TUF Metadata](https://theupdateframework.org/docs/metadata/)：可信元数据职责、版本和到期字段；
- [RFC 8032](https://www.rfc-editor.org/rfc/rfc8032)：Ed25519 标准；
- [Python cryptography Ed25519](https://cryptography.io/en/latest/hazmat/primitives/asymmetric/ed25519/)：当前验签库接口与错误边界。

## 已验证

- 门限签名、未知根、篡改、错误源、错误 TLS pin、目录过期/未来/超长期、版本回滚/跳版/混链全部 fail closed；
- 活动、退休和撤销签发公钥按凭证签发时点执行不同策略，长时间运行进程会重新检查目录到期；
- bootstrap 拒绝乱序/重复/无效根、私钥字段、错误门限和带隐藏信任的禁用配置；
- 父进程 ready 回执拒绝未知字段和非法信任状态，私有令牌不进入 WebView 状态；
- 原生导入只向 sidecar 发送凭证字节和 Keychain 内安装秘密的摘要，不发送秘密；验签失败、返回字段异常或当前凭证变化均不写入。

## 仍未放行

- 律所确定离线根保管人、门限、轮换/应急撤销仪式和生产服务域名；
- 正式 TLS 证书及 SPKI 轮换窗口、签发后台、MFA/管理员双人复核与审计；
- 专用 PostgreSQL 实迁移、sidecar 持久 API/Store/Worker 正式装配和离职/撤销演练；
- Apple Developer ID 签名、公证、自动更新信任链和真实律所安全验收。
