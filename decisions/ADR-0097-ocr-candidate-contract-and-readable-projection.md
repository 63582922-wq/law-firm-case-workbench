# ADR-0097：恢复 OCR v1 合同与不丢尾的纯文字投影

状态：0086已部署，既有真实候选已追加持久恢复，律师服务列表/读取接线并实跑；浏览器验收未完成。

## 需求与事实

律师需要可与原页对照的识别内容，不应看到 HTML 代码或被静默截断的文字。
识别器正常返回、结构校验通过、全文完整和律师确认是四种不同状态。
2026-09-07 的唯一借条 OCR 已产生真实响应，但适配器在固定 v1 成果根节点误加
cost_basis / cost_reserve_minor_units，独立校验器因此拒收。ADR-0094 原本明确不改变文字合同。
新增直接连接实际适配器字节与独立校验器的测试，在修复前对 PDF 扫描页和 JPEG 均复现
ARTIFACT_VISUAL_CONTRACT_INVALID，不再仅靠两端各自手写的样本验证兼容性。

## 决策

1. 新成果恢复已发布 v1 精确字段合同，不扩大校验器允许字段，不伪造 v2，也不调整已部署策略哈希。
   六分保守费用继续记录在 TaskAdapterOutcome/执行回执及既有版本化费用策略中；不是实付账单。
   候选正文不重复承载费用。没有更改已应用迁移。
2. 此修复只影响未来生成字节。禁止重新执行旧成功 OCR、覆盖原候选、清除失败事件，或在读取路径
   偷删旧候选字段以绕过独立校验。既有成果恢复必须追加独立派生记录，绑定原始字节摘要及解释版本，
   保留原失败状态和费用元信息；本 ADR 不自动授权旧成果放行。
3. Web 显示是纯字符串投影，不使用 HTML 执行/远程资源获取。仅完整 HTML 围栏或文档包装、
   无属性且已允许的简单排版标签可转换；未知标签、属性、注释或错配保留为字面原文，避免静默删除。
   React 继续通过普通文本节点显示，即使实体解码后含标签也不执行。
4. 识别文字按每段最多 8000 字符分段，保留原页来源，不再截掉长文尾部。
   ocr-full-page 的系统占位 confidence 不展示成模型置信概率。
   每页明确提示全文完整性待核对，不补写模型漏字，不自动确认事实。

## 验收边界与下一步

聚焦实际生成器→校验器合同、费用保留、恶意/不支持 HTML、表格分隔、实体单次解码、
长页尾部保留、来源绑定、空页提示和原数据不变。测试中的网络/存储为替身，没有新付费调用。
现有 Web 授权、独立验证门和数据库权限不变，没有重新启动消费者。

下一单一目标：为已留存借条候选实现只追加的本地解释恢复，并在真实授权入口和浏览器展示
完整性待核提示；原 run 仍须显示历史失败，恢复件只能是待律师复核，不能冒充正常任务成功。
商用总目标、完整案件决策包与可提交文书的验收要求不因本次修复缩小。

## 真实留存候选的只读解释证据

`visual_candidate_recovery.py` 已实现纯函数解释器。只有原运行 FAILED、原因确为格式错误、
OCR任务 SUCCEEDED、原始字节/来源/运行/任务/尝试/版本/费用一致时，才对副本分离两项费用字段，
交给原独立视觉合同检查器；额外字段、正式事实标志、内容摘要损坏等不会被“顺便修复”。
返回新的 `visual-candidate-cost-contract-recovery-v1` 包装，保留原摘要、原失败状态和费用，
标记完整性未核对；本函数不授予权限、不持久化、不产生普通验证回执。

固定合成诊断入口 `diagnose_visible_loan_planning.py --inspect-visual-recovery` 使用现有 API
数据库身份、只读可重复读事务，核对实际当前案件版本/图/原成果/成功任务回执后读取私有原件。
真实3020字节原候选摘要仍为71ef29c0e3021c148359d17c5a8fc27bc8ac3f2401587f27df6dcbe894516f33；
解释草稿3754字节，摘要01cb917b8ae048ad39d1e540195f15d26edb31a1ba8af8874e3758e058cb5065，
确定性恢复ID bcffde34-6ab6-5b6a-865e-a22615ea8afc。Web纯投影返回“识别文字／全文完整性待核对”。
原运行仍FAILED/10，没有模型、数据库或对象写入；这不是律师Web授权读取证明。

现有封存恢复存储只支持律师决策包，不能冒用其类型或放宽普通成果授权。后续须增加独立的
追加式OCR恢复存储合同及当前案件角色/版本/原摘要复核，再接入明确标注恢复件的律师读取路径。
尚无持久恢复件或浏览器验收，不能把上述只读解释草稿当作交付完成。

## 追加存储实现（尚未部署）

0086新增独立 `case_agent_visual_recovery_candidates` 元数据表；派生包装仍写入现有私有对象存储，
不把正文复制进数据库或增加外部目的地，不写普通 Agent artifact/event/verification 台账。
唯一键为原成果+解释策略，禁止UPDATE/DELETE。插入时由现有Worker身份核对原运行失败原因、
当前版本/图、原成果摘要、成功OCR回执及六分费用；RLS同时绑定律所和当前活动案件角色。
Web仅获得此新表SELECT，不能写恢复件；verifier没有新增权限。

`PostgresVisualRecoveryStore.stage` 先授权读原件、产生确定性草稿、私有写入并字节回读，
再按run→matter锁顺序复核来源/版本并追加记录。同键恢复必须核对元数据和原对象字节，
不覆盖冲突结果。若对象已写而事务因版本变化拒绝，可能留下未登记的私有派生对象；不删除原件，
也不把该对象返回成有效成果。对象孤儿的有界清理仍属后续运维工作。

9项解释/存储局部测试通过，其中5项存储测试覆盖只追加、同键无重复put、版本变化拒绝、
冲突回执拒绝和对象损坏拦截。实际PostgreSQL用现有worker角色在事务内装入0086：
固定合成源的当前版本插入1行成功，另一回滚事务的过期版本按预期拒绝；两次都ROLLBACK，
独立to_regclass确认表不存在。探针对象键为明确虚拟占位，故只证明DDL/SQL守卫，
不证明真实应用写入或对象交付。没有更改已有迁移、案件状态或发送模型请求。

下一单一目标：完成存储入口的真实同构验收与规范0086部署，然后接通当前律师角色/版本授权的
恢复件读取及明确恢复标识；尚不能在普通已验证成果入口放宽限制。
