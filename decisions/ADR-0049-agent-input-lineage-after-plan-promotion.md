# ADR-0049：Agent 输入谱系与计划登记后的版本解释

- 状态：已采纳
- 日期：2026-09-04
- 关联：ADR-0040、ADR-0044、ADR-0046、ADR-0048

## 背景

案件 `version` 是同一案件聚合的乐观并发时钟，不只是事实、证据、诉请、程序或法源的版本。
一份已独立核验的 Agent 图谱登记为动态办案计划候选时，系统必须写入审计和 Outbox，因而案件
版本会前进；主办律师随后激活该候选时，版本还会再次前进。这两次变化都不改写本轮 Agent
实际分析的输入。

浏览器此前仅以 `currentMatterVersion > run.snapshotMatterVersion` 推断“案情已变”。在真实
受控运行中，验证通过后自动登记候选计划即触发这一条件，页面因此把刚完成的分析错误地提示为
旧成果，并提供重新调用模型的入口。该错误既会误导律师，也会为不必要的数据外发和重复费用
创造路径。

## 决策

1. 由 PostgreSQL Agent Store 在读取运行投影时，依据当前案件版本、`case_agent_runs`、已核验
   图谱晋升记录、计划头和计划状态，生成浏览器安全的输入谱系状态：`CURRENT`、
   `PLAN_CANDIDATE_REGISTERED`、`PLAN_ACTIVE` 或 `INPUTS_CHANGED`。
2. 只有同时满足以下条件的下游计划才可被识别为非输入变化：该计划来源于该运行的已核验图谱、
   计划快照与运行快照完全一致、候选或活动计划仍是服务器当前计划，且当前案件版本精确等于
   对应候选登记或计划激活后的版本。任何额外版本推进、运行已失效、关系缺失或不一致均返回
   `INPUTS_CHANGED`，不得由浏览器猜测为安全。
3. 浏览器只在 `INPUTS_CHANGED` 或运行已进入 `STALE` 时提供“基于新案情重新研判”。候选登记和
   计划激活会明确说明版本变化来自下游工作流，而不是新的案情输入，不显示重复分析入口。
4. 不回写、不重标、不删除既有运行、候选计划、审计或模型回执；历史版本保留原样。该决策只
   增加受控显示投影，不能放宽计划激活、文书生成、终审或对外提交的任何前置条件。

## 后果

- 律师能区分“新的案件输入，需要重新研判”与“本轮研判已形成待确认/已激活计划”，避免把系统
  的内部版本编排误解为案情变化。
- 重复模型调用不再由前端版本比较触发；真实的事实、证据、规则、程序或诉请变化仍保持
  fail-closed，并继续要求新快照下的独立研判。
- 该投影不公开计划 ID、图谱、哈希、工具、供应商或提示词，保持浏览器只读最小信息边界。
