# ADR-0017：律所登记远程操作必须用持久操作号消解未知结果

状态：已接受（客户端、sidecar、固定 HTTPS 查询和 Keychain 恢复已完成；生产服务未部署）

## 背景

激活、续期和撤销都会改变律所服务端状态。网络中断可能发生在服务端已经提交、客户端尚未收到回执之间。此时自动重试会重复消费激活码、重复续期，甚至把已撤销的登记误报为仍有效；直接清除本机标记又会丢失恢复线索。

## 决定

1. 原生层在首次远程请求前生成 UUID 操作号，并把版本、操作类型、原凭据 SHA-256、安装绑定 SHA-256 和开始时间写入第三个固定 Keychain 项并回读复核。激活要求原凭据为空；续期和撤销要求原凭据哈希精确匹配。
2. 同一操作号作为激活、续期或撤销请求的 `client_nonce`。原请求失败或回执无法严格解析时，待决标记保留；任何新的远程变更、离线导入或本机清除都被阻断，不自动重试原操作。
3. WebView 只显示脱敏中文状态和“查询待决远程操作”动作，不取得操作号、设备绑定、凭据或服务地址。查询仍经父进程私有 Bearer、数字 loopback 和固定路径 `/v1/desktop-enrollment/status`。
4. sidecar 只向门限签名目录指定的固定 HTTPS Origin 和 SPKI pin 发送严格查询。请求绑定操作号、操作类型、安装摘要和当前凭据哈希；服务端只能返回 `PENDING`、`REJECTED` 或 `SUCCEEDED` 及与状态相符的严格结果材料。
5. `PENDING` 不改变 Keychain；`REJECTED` 只清除完全匹配的待决标记并保留原凭据；`SUCCEEDED` 必须再次验签 envelope 或验证接受的撤销回执、身份连续性、有效期、设备绑定、操作号和原凭据哈希。
6. 成功恢复时，凭据变更与待决标记清除在同一原生锁内执行并逐项回读。任一步失败都尝试恢复原凭据和待决标记；不能把部分提交显示为成功。
7. 撤销只有在本机凭据删除和待决标记清除均成功后才停止当前 sidecar 会话。未知结果期间案件访问不被提升，启动后仍可从 Keychain 恢复待决状态。
8. 仓库默认 `NOT_CONFIGURED` 时不挂载激活、续期、撤销或状态查询端点，也不发外部请求。

## 已验证

- Python 生命周期、固定 HTTPS 适配器和 parent-only sidecar 覆盖成功、处理中、拒绝、错操作号、未知字段和不相符结果材料；
- Rust 覆盖待决标记跨实例恢复、重复提交阻断、精确标记清除、哈希绑定撤销、成功激活提交和损坏标记 fail-closed；
- 前端只新增中文恢复动作，待决期间隐藏或禁用会改变登记状态的其他动作；
- 全仓 315 项后端检查通过，4 项专用 PostgreSQL 破坏性检查按安全门跳过；25 项 Rust 检查、Clippy 严格检查和前端生产构建通过。

## 仍未放行

- 律所生产服务对操作号的唯一约束、状态保留期限、管理员审计和跨节点一致性；
- 真实 TLS SPKI 轮换、超时/断网/进程崩溃注入和多实例互操作演练；
- Developer ID 签名、公证、Keychain 访问组和设备遗失处置；
- 专用 PostgreSQL、逐案授权和真实律所安全负责人验收。
