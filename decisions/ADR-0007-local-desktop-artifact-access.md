# ADR-0007：本机证据读取必须经过 OS 会话、Keychain 与一次性短时许可

状态：已接受（合成 Alpha 桌面边界）

## 背景

律师选定案件文件夹后，系统既需要只读原件，也需要预览和下载受管加密派生件。如果把绝对路径、加密密钥或长期下载地址交给浏览器、Agent 或数据库，任何日志泄漏、跨案件错误或链接重放都会扩大案卷暴露范围。

## 决定

1. 原件读取只接受律师在桌面壳层中确认的目录；授权绑定 OS 本机会话、律所、案件、操作者、会话、目录指纹、设备号和 inode，最长十分钟，进程退出即失效。
2. 受管派生件的 AES-256-GCM 密钥不接受 API、浏览器或项目环境文件输入；macOS 第一实现只从固定 `/usr/bin/security` 读取版本化 Keychain 项。
3. Keychain 适配器当前只读。创建、轮换、撤销和灾难恢复必须由后续桌面安装器和安全流程显式完成，不在后台静默生成密钥。
4. 原件页预览不复制或返回整份原 PDF。服务端从当前短时文件夹授权中按登记哈希解析文件，以 `pdftoppm` 在受限临时目录渲染单页 PNG；一次性许可只向 loopback 返回该 PNG，并在渲染前后复核原件哈希、页数、文件大小和页码。
5. 浏览器只通过桌面原生文件夹选择桥取得待确认目录；没有桥时保持阻断，不提供绝对路径文本框。红框在单页 PNG 的标准化坐标上建立候选，批准和锁定仍走案件版本化命令，原件不变。
4. 派生件预览与下载只允许当前 `VERIFIED` 且仍属于 `LOCKED` Manifest 的记录；数据库对象键仅返回给服务端定位器，不进入证据快照或网页。
5. 每次读取签发随机一次性 Bearer，预览最长 90 秒、下载最长 45 秒，并绑定律所、案件、派生件、操作者和会话；只允许数值型 loopback 地址。令牌不进入 URL，成功使用后立即删除。
6. PDF 响应使用 `no-store`、`nosniff` 和沙箱策略。派生 Worker 在生成时剥离文档级和页级自动动作、表单、附件入口、链接注释和演示动作，检查失败即不登记为可预览派生件。
7. 前端只在内存 Blob 中预览，关闭即释放；下载使用固定、无“最新版”含义的文件名，不写回律师选择的原件文件夹。

## 后果

- 用户不需要提供模型 API Key 或把案卷加密密钥粘贴给系统。
- 浏览器不能凭案件快照构造对象存储路径，也不能长期重放已取得的派生件 URL。
- 重启、注销、会话撤销或目录替换后必须重新授权，这是刻意的安全摩擦。
- 桌面原生选择桥已完成合成 Alpha 实现，但 Keychain 初始化/轮换 UI、真实桌面身份、API/Worker 常驻监护、下载审计持久化和真实恶意 PDF 安全验收尚未完成，因此仍不得接入真实案件。
