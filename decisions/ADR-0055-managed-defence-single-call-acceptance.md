# ADR-0055：受管被告应诉单次真实能力验收

- 状态：已采纳
- 日期：2026-09-04
- 关联：ADR-0041、ADR-0044、ADR-0053、ADR-0054

## 背景

现有全合成民间借贷金标案能够生成原始材料、金标事实和确定性核算，但旧答辩切片并未经过当前 Web 身份、私有对象存储、证据账本、动态办案计划、受管 Worker、独立核验和律师文书阅读链。另一个已实际运行的受管案件是原告庭前案，不具备生成一审被告答辩状的代理情境与来源条件。

因此，既不能把旧切片算作商业 Agent 验收，也不能把当前原告案强行用于答辩测试。需要一条独立的、可恢复而不可机械重试的合成被告案验收链。

## 决策

1. 建立固定 ID 的独立合成案件，仅允许在 loopback 本地受管验收模式中运行。它不得读取、上传、导出或混入客户案件资料。
2. 该验收使用 88 页、11 文件的冻结合成案卷；PDF 与图片均通过当前受管材料接收、扫描、私有对象存储和证据账本流程进入案件，不以数据库直插替代原件接收。
3. 验收夹具可用固定的合成主办律师身份完成“夹具确认”动作，以形成被告一审代理情境、事实、诉请回应、法源、规则与法律依据包；这些审计记录必须明确属于合成验收，绝不表述为执业律师对真实案件的批准。
4. 官方法源只能从国家法律法规数据库等已配置官方域下载、按原始字节哈希留存并以现有官方法源私有存储注册；脚本不得伪造法条文本、哈希、许可审核或对象定位符。
5. 模型分析阶段只允许一笔新的、受预算上限约束的调用。脚本发现已有该验收运行、未知提供商结果、失败或已消耗调用机会时必须停止并保留证据，不得自动重试、换模型或新建第二份相同案件。
6. 第一运行只形成已独立核验的律师决策包和动态计划候选；合成主办律师夹具显式激活该候选后，第二运行仅使用受控计划和确定性文书 Worker 生成 `DEFENCE_STATEMENT` DOCX/PDF/JSON 审阅候选。任何一步不得自动锁定、发送或提交法院。
7. 验收完成至少核对：所有原件的哈希和页数、代理情境、事实/诉请回应/法源/规则的完整来源集合、模型回执、计划来源绑定、文书候选状态、DOCX/PDF 可读性和候选标记。浏览器视觉旅程和执业律师认可仍是独立后续门。

## 后果

- 测试可证明当前受管架构是否真的能把真实运行的 Agent 决策连接到可审阅的被告应诉候选，而非只验证孤立模板。
- 该测试的通过不表示真实客户案已获律师批准，也不表示证据目录、利息核算表、提交包、跨浏览器或商用发布已通过。
- 运行环境、扫描器、对象存储、模型、Worker 或渲染器任一不可用时，验收必须如实停止并给出固定阻断状态；不以离线脚本或伪造输出替代。
