# ADR-0048：来源锚点确定性补全与拒绝结果的实际成本回执

- 状态：已采纳，真实运行验证中
- 日期：2026-09-04
- 关联：ADR-0041、ADR-0042、ADR-0044、ADR-0047

## 背景

一次受控真实运行已经完成供应商调用、返回完整的严格 JSON 结构，并留下可校验的响应归档和
用量字段。内容在进入审阅候选物之前被本地解析器安全拒绝：模型只列出了已授权的案件来源，
但遗漏了若干由服务器登记的跨字段引用关系——争点分析应引用该争点锚点；攻防分析还应引用
该对方路径对应的服务器来源。

JSON Schema 可以限制每一个引用只能取自服务器给出的枚举，但不能可靠表达这些跨字段的
关系约束。若把这种可证明的格式遗漏一律当成模型“未知”，会错误掩盖一次已经发生的调用；
若放宽到不再要求锚点，则律师无法从候选物直接追溯关键分析对象。

同一次拒绝还暴露出计量缺口：适配器只在语义内容通过后读取供应商用量，导致已归档、已核验
的实际消耗在失败回执中被写成零。这既不符合账本可审计性，也会让预算和复盘产生错误事实。

## 决策

1. 原始模型输出仍必须通过严格解析：每个引用只能是当前受控投影中的来源编号，不接受模型
   自造、未知、重复或越权来源；原始响应继续加密归档，绝不在候选物生成时覆盖或改写。
2. 通过原始引用授权校验后，确定性编译器只在审阅候选物中前置补全以下服务器已知锚点：
   - 每条争点分析与律师决定分析加入其 `issue_ref`；
   - 每条攻防分析加入其 `issue_ref`，以及该 `position_id` 在服务器登记的来源。
   编译器不增加任何事实、金额、法源、策略、立场或结论；它仅将已绑定的来源身份置入引用列表。
3. 结构化 Schema 与系统提示词同时明确这些关系；原始模型最多保留十一或十个可选来源槽位，
   为确定性锚点保留容量。补全是容错和可追溯性保护，不是替模型补写实质分析。
4. 供应商响应封套、模型身份和受政策约束的用量字段独立校验。即使分析正文被语义安全规则
   拒绝，只要该用量回执可核验，失败事件也必须记录其实际成本；封套或用量不完整时仍保持
   未知成本，而不是猜测金额。
5. 历史事件保持追加式不可变：已经写入零成本的旧失败记录不被原地修改。后续运行采用新规则，
   并以一次全新的受控运行验证；不得对既有运行自动重发或把归档响应重新包装为新成果。

## 后果

- 候选决策包的每个风险、攻防和律师决定都能指向其服务器定义的案件锚点，律师可追溯性更强。
- 真实模型的可读分析仍无权进入账本、正式文书或对外流程，除非独立解析、确定性编译和律师
  审阅全部通过。
- 实际发生且可核验的模型成本不再被失败状态伪装为零；未知传输和不完整回执仍安全停止。
- 这不是一次“成功结果”的追认。新的受控运行仍必须验证：单次外部边界、成本回执、候选物、
  审阅门槛和浏览器工作流均如约工作。
