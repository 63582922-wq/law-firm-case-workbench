# ADR-0040：首发律师工作成果采用来源绑定的确定性编译

- 状态：已采纳
- 日期：2026-08-26

## 背景

律师 Agent 已能根据案件目标和当前状态形成动态计划，但首个脱敏验收案只有已确认事实和一笔已确认交易，没有律师批准的诉请、法律规则、计算结果或程序事件。若继续把这些不完整来源交给通用文书模型自由起草，模型可能把 OCR 候选、算术差额或常识性法律判断写成正式结论；重复调用也会增加案件外发、费用和不确定结果恢复成本。

项目需要先证明 Agent 能交付真实可用的律师工作底稿，同时继续遵守“模型提议、代码总控、律师决定”和所有关键内容可追溯的产品边界。

## 决策

1. 规划模型仍根据当前案件快照和代理情境决定是否需要 `CASE_REVIEW_MEMO` 和 `PAYMENT_LEDGER`，但不直接控制状态机或文件写入。
2. 首发案件审阅意见只从一份当前代理情境、一份当前计划项和已确认事实编译；缺少诉请、法源、计算、程序事件或证据项时，固定生成风险与待律师决定事项，不推测补全。
3. 首发付款台账只从当前已确认交易逐行编译，不使用未确认 OCR、公式或模型推算。
4. 两类文书任务固定为 `IN_PROCESS`、网络 `DENY`、`max_external_calls=0`，生成候选 JSON、可编辑源件和 PDF 预览后仍需独立校验，并停在 `READY_FOR_REVIEW`。
5. 每个段落和台账行必须携带稳定来源引用；PostgreSQL 暂存前重新核对当前计划、案件版本、来源版本、确认状态和确认哈希，任何漂移均拒绝。
6. 既有 DeepSeek 文书 exchange 不删除。迁移 `0070_local_case_review_memo_policy_hash.sql` 同步当前 Tool 策略标识，同时保留其 `NETWORK_CONNECTOR / EXACT_ALLOWLIST` 数据库门，因此本地确定性任务不能误建外部 exchange。
7. 未来只有在事实、诉请、法源、计算和程序状态均经律师批准后，才可另行决策是否让模型起草法院文书；模型输出仍只能是来源绑定候选，不获得批准或提交权。

## 后果

- 本轮可以真实验证 Agent 的案件观察、规划、受控执行、来源约束、文书生成和独立校验，而不把缺失信息伪装成法律分析能力。
- 案件审阅意见会主动暴露信息缺口，付款台账不会自动产生余额或债权结论。
- 文书阶段不产生外部模型费用，也不存在未知外部提交后的重发风险。
- 当前成果是律师复核底稿，不是已由律师认可的法律意见、诉状、答辩状或法院提交包。
