# ADR-0052：可编辑 Office 候选采用跨运行时的受控验收矩阵

- 状态：已采纳，实现中
- 日期：2026-09-04
- 关联：ADR-0041、ADR-0046、ADR-0050、ADR-0051

## 背景

律师需要同时取得可编辑的 Word/Excel 候选和可固定版式审阅的 PDF。前者要在律师实际使用的
办公软件中可读、可改；后者才是律师批准前核对版式、页码和来源注记的稳定载体。不能把某一台
开发机上的精简 Office 渲染器当成所有客户设备的代理，也不能因为该渲染器缺少中文字体而把
一个在目标操作系统原生预览中可正常阅读的候选错误判为失败。

同样，单一服务器渲染通过也不能证明 Word/WPS 客户端能打开可编辑件。中文字体在 Windows、
macOS 与受管 Linux 上的可用名称不同，跨平台可编辑文档不应声称分页、字宽或行数完全一致。

## 决策

1. 审阅 PDF 是律师批准前的固定版式核对件；DOCX/XLSX 是同一受控内容快照的可编辑候选。律师
   必须先打开审阅 PDF，下载可编辑件不会构成批准或法院提交。
2. 每个 Office 候选的验收至少分三层记录，且必须使用从认证交付端点取得的实际字节：
   - 隔离 Linux 渲染器：转换为审阅 PDF，检查内容哈希、PDF 字体嵌入、页面尺寸和逐页图像；
   - 当前用户操作系统原生预览：在 macOS 使用 Quick Look 核对中文可读性、标题、页眉页脚和
     首页版式；在 Windows 试点使用 Microsoft Word 或 WPS 做等价核对；
   - 结构层：OOXML/工作簿属性、来源绑定、候选状态、公式/宏阻断和可编辑文件哈希。
3. 只要渲染器缺少必需的中文字体、不能发现当前系统字体或其输出与原生预览矛盾，该结果只能
   标为“验收工具环境故障”。它不得单独让候选通过，也不得单独覆盖已通过的受控 PDF 与原生
   可读性证据。修复或替换该测试环境后才可以把它重新纳入门禁。
4. DOCX 保留国内律师文档的中文字体语义、macOS 替代字体声明和受管 Linux 字体映射；不嵌入
   或再分发未获授权的商业字体，也不承诺不同 Office 产品的分页或字形度量完全一致。若客户
   需要固定提交版式，应只以已核验 PDF 与后续批准版本为准。
5. 面向客户的正式发布前，至少完成一次 Windows Microsoft Word/WPS 的真实打开与编辑回存
   演练。该项尚未完成时，系统只能称为“脱敏受控环境已验证”，不能称为跨客户端商用发布完成。

## 后果

- 文书质量从“单一工具截图”升级为可追溯的服务端、原生客户端与结构三层证据，避免误判。
- Mac 本机和受管 Linux 的当前证据可以继续支持受控测试；Windows Office/WPS 演练仍是客户
  发布前必须补齐的独立门，不能由自动化测试替代。
- 可编辑件与 PDF 的职责被明确分开：编辑性不再被误当成固定版式证明，固定 PDF 也不被误当成
  可编辑文档。
