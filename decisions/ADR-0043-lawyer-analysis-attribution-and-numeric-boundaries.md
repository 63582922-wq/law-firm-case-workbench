# ADR-0043：律师分析的主体归属、证据别名与正式数字边界

- 状态：已采纳，实施中
- 日期：2026-08-28
- 关联：ADR-0041、ADR-0042

## 背景

`qwen3-vl-plus` 在 2026-08-28 的一次独立合成案件调用中正常结束，费用为
0.054513 元，并按数量合同返回了八个争点、四组对抗分析、两套策略、六个补证问题和
三个律师决定理由。模型也识别并忽略了材料中的提示注入，未声称批准、终审或提交。

严格校验首先拦截了一条证据别名：模型输出 `SRC-F3-P001`，而受控来源登记为
`SRC-F3a-P001` 与 `SRC-F3b-P001`，其中文档事实工具回执将相关借条事实唯一绑定到
`SRC-F3b-P001`。进一步人工复核还发现，模型把原告起诉状中的“本金分文未还”错写为
被告陈述，并在自由文本中自行写入了年化利率与保护上限等正式数字。

因此，结构完整和来源白名单命中仍不足以证明律师可用性。主体归属、适用规则和正式
数字必须由确定性登记与编译器控制，不能依赖模型在自由文本中保持一致。

## 决策

1. 本次调用继续保持失败状态，不自动重试，也不因修正一个来源编号就改记为通过。
2. 原始模型 JSON、供应商回执和失败原因永久保留；所有纠偏都写入新的派生回执，不
   覆盖原始输出。
3. 仅允许一种自动来源纠偏：模型给出材料级页码别名，且受控 `document_facts` 对同一
   材料代码和页码存在唯一精确来源时，代码可映射到该来源。映射必须记录原值、目标值、
   JSON 路径、规则和输入哈希；零个或多个候选一律失败关闭。
4. 律师分析核心升级为新的版本化合同。模型不再用自由文本重述谁说了什么，而是选择
   受控 `assertion_id` / `finding_id`；编译器从登记中注入主体、原文摘要和来源。对抗分析
   的对方主张必须绑定对方主体的登记陈述。
5. 举证责任基线、每类争点最低法源集合、利率边界、情景金额和程序期限由确定性工具
   回执提供。模型只能分析证据强弱、反驳路径、策略取舍、补证问题和律师决定理由。
6. 模型不得写入正式情景金额、利率换算结果或保护上限结果。模型输出只引用受控的
   `scenario_id`、`authority_id` 与计算政策 ID；DOCX/PDF 中的正式数字由代码插入。
7. 策略目标使用受控 `objective_code`，由代码生成对律师可读的目标文字，避免模型产生
   与所选情景相矛盾的目标描述。
8. 离线单元测试必须覆盖唯一映射、歧义映射失败、主体倒置失败、最低法源缺失失败、
   正式数字泄漏失败和原始输出不可变。全部通过后，才允许一次新的独立真实调用。

## 后果

- 2026-08-28 首次完整返回证明了模型具备实质案件分析能力，但状态仍为
  `FRESH_MODEL_CALL_FAILED_ACCEPTANCE`，不是端到端通过。
- 自动纠偏被限制为可证明的标识解析，不会替模型补造证据、改写法律判断或选择律师立场。
- 输出合同更结构化，模型自由文本更少，但律师文书的主体、数字和来源可审计性更强。
- 下一次真实调用是新合同的独立验收，不是本次调用的重试。
