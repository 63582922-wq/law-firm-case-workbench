# ADR-0075：M2 作为 M1 封存后的独立单次完整链路验收

状态：`Accepted`

日期：`2026-09-04`

## 背景

M1 `m1-source-qualified-final-acceptance` 已经通过来源、规则、法源包和律师审批门，并跨过一次
`qwen3.7-plus` 外发边界。该请求没有可认证的私有原始响应归档，恢复后被标记为结果不确定并
静默封存。它不能重发、换模型、改写结果或被视为失败后可继续的同案运行。

ADR-0074 修复了这一类未知外发的恢复行为：恢复只读取第一次落库的不可变外发边界；结果缺失时
保留 `STARTED` 外发记录和 `UNKNOWN` 任务回执，追加受控审计后停止轮询。该修复本身需要一个
新的真实完整链路来验证，而不是重新使用 M1。

## 决策

1. 新建固定身份的 M2 合成验收：
   `m2-source-qualified-post-reconciliation-acceptance`。它与 M1 使用不同的确定性案件、会话、
   运行、命令幂等键和受控输入身份，不能读取、恢复、续接或修改 M1。
2. M2 继续使用 ADR-0073 已冻结且可见正文可读的天津通信管理局《中华人民共和国民法典》快照：
   URL、媒体类型、字节数、SHA-256 和第六百七十九条/第六百八十条正文标记必须完全一致。
   调用前仍须重新下载并验证；不匹配时在模型调用前停止，不换源。
3. M2 使用独立的同律所规则版本
   `PRIVATE_LENDING_RESPONSE_SOURCE_SCOPE / M2-SOURCE-2026-09-04`，以免与 V4 或 M1 的
   来源绑定版本混同。
4. M2 首轮仅允许一笔律师审批后的 `qwen3.7-plus` 外部模型调用，使用 300 秒传输上限、360 秒
   完整任务预算和 420 秒租约。禁止自动重试、模型切换、并行外发或同案第二次运行。
5. 若模型结果未知，M2 同样按 ADR-0074 封存；若模型响应通过严格合同，才允许继续激活受控计划、
   生成待律师复核的 DOCX/PDF 候选，并做渲染与结构验证。任何结果都不得自动批准、锁定或提交。

### 2026-09-05 修订

M2 首次启动已在模型调用前、完整受控输入后的版本 30 因当前官方网页不可下载而停止，未创建
法律事件、法源包、Agent 运行或外发。该状态不构成新的模型验收，也不消耗 M2 的唯一调用额度。
按 [ADR-0076](ADR-0076-m2-fresh-firm-source-pre-model-recovery.md)，只允许一次显式、严格的预模型
恢复：在 24 小时复用窗口内，读取同律所已验证的同哈希公共法源对象并复制到 M2 的私有范围；不得
重新访问公网、不得新建案件、不得重发 M1。该恢复通过后才继续本 ADR 的原定单次模型调用。

## 原因

- M1 已经消耗其唯一外发额度；把“新的完整验收”伪装成 M1 恢复会破坏证据和成本边界。
- 使用已冻结的可读法源把变量限制在模型与端到端编排修复上，避免再次将公共网页变化误判为
  Agent 能力问题。
- 新规则版本、案件身份和外发台账让每次真实试验可独立审计、可复盘，也避免无止境重跑。

## 后果

- M2 若通过，只证明该 88 页合成案在当前受控架构下能从资料、法源和一次模型分析进入律师复核
  文书候选；它仍不代表真实客户案件、律师最终认可、锁包或法院提交。
- M2 若失败或结果不确定，将封存该新案件并停止；下一步是基于证据诊断，而不是自动创建 M3。
