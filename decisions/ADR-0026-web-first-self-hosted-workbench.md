# ADR-0026：浏览器优先的自托管律师工作台

- 状态：已采纳
- 日期：2026-08-11
- 替代：ADR-0008 中将 Tauri/macOS 桌面壳作为主要交付形态的决定；ADR-0008 保留为未来可选离线伴侣的历史记录

## 背景

本产品面向律所，而非仅使用 macOS 的单个律师。把核心办案流程交付为 macOS `.app` 会排除 Windows 用户，也使安装、Keychain、签名和本机 sidecar 成为每台律师电脑的前置条件。这与“部署一次、多个律师在各自电脑上使用”的商用目标不符。

同时，纯浏览器不能在未获选择的情况下读取律师硬盘上的任意文件夹；将本地绝对路径发送到服务器既不可靠，也不应成为证据处理边界。产品必须明确资料驻留位置和上传授权，而不能把桌面文件夹授权伪装为网页能力。

## 决定

主产品改为**自托管 Web 工作台**：律所或其受托运维方在受控服务器、私有云或律所内网部署；Windows、macOS 和 Linux 律师电脑只需使用受支持的现代浏览器访问 HTTPS 工作台。Tauri、macOS Keychain、loopback API、原生文件夹选择和 `.app` 打包不再是主路径，也不再扩展为本轮功能。

生产拓扑固定为：

```text
浏览器 ── HTTPS / 同源会话 ──> 反向代理 / Web 前端 / FastAPI API
                                      ├─ PostgreSQL：案件、角色、审批、审计
                                      ├─ 私有对象存储：原件、页图、派生件、提交包
                                      ├─ 受控 Worker：检查、渲染、PDF、Office、研究、模型
                                      └─ OIDC 身份服务与服务器端密钥管理
```

### 资料接收

浏览器材料入口按以下优先级实现：

1. 支持目录选择的浏览器可选择资料文件夹；
2. 所有浏览器都支持多文件选择、拖放和 ZIP 上传；
3. 服务器只把客户端给出的文件名、类型和大小视为提示，完成隔离、真实类型检查、哈希和页数核验后才写入受管原件库；
4. 原始资料与生成件绝不写回律师本地资料夹；下载由浏览器明确触发。

客户端不得发送、保存或依赖本机绝对路径、文件系统句柄、模型密钥或任意对象存储地址。

### 身份、权限与密钥

- Web 身份采用 OIDC/OAuth 2.1 兼容的律所身份服务；浏览器使用 `Secure`、`HttpOnly`、`SameSite` 会话 Cookie；所有写操作还须经过 CSRF 与 Origin 校验。
- API 从已验证会话映射内部用户、律所成员关系和案件角色。`firm_id`、角色和律师身份均不能由网页请求体或 URL 决定。
- PostgreSQL 行级安全保留为纵深防线；应用数据库角色不得拥有 `BYPASSRLS`。
- 对象加密密钥、模型 Key 和第三方凭证由服务器端密钥管理提供，不进入浏览器、前端构建物、案件资料或 Git。
- 外部模型、OCR、网络检索和导出仍须保持原有逐案授权、最小投影、次数/成本边界与追加审计；浏览器化不能降低这些门槛。

### PDF 证据闭环

首个真实办案闭环是：上传材料 → 服务端隔离与页级预览 → 律师逐页保留/排除 → 归一化红框 → 锁定清单 → 受控 Worker 生成“相关页 PDF”和“含红框相关页 PDF” → 经权限与审计下载。页面预览返回受服务端检查的单页图片，不在浏览器中直接嵌入原始 PDF。锁定和生成前重新核验来源哈希、页数和案件版本。

Worker 只能读取对象存储已物化到私有工作目录的常规 PDF 文件；拒绝相对路径、符号链接、未登记哈希、页数不符和非私有输出目录。生成完成后再次核验每个来源的哈希与页数。Worker 对外结果和证据谱系只记录稳定文件名、哈希、页数及经过哈希化的存储引用，不记录服务器物理路径、对象存储地址或浏览器本机路径。

## 可复用资产

- React/Next 中文办案界面及新的可复用 PDF 审阅组件；
- FastAPI 请求/响应、PostgreSQL 领域台账、事务、幂等、审计与行级隔离；
- 证据清单、精确去重、红框坐标、PDF 派生、利息计算、法源和文书审查内核；
- 受控 Agent/Tool/外发预授权边界。

## 必须替换或降级的资产

- `DesktopBridgeInstaller`、Tauri Rust 命令、原生 parent token、`tauri://localhost` CORS、桌面 grant 和本机 SQLite 案卷；
- macOS Keychain、NSSecureTextField、macOS 签名/公证与 `.app` 打包；
- 本机资料根、绝对路径和 local folder grant 作为正式材料入口。

它们可在未来作为“离线本地助手”单独评估，但不得影响 Web 主产品的权限模型或成为浏览器的旁路。

## 迁移顺序和验收标准

1. 建立容器化 Web 运行基线、服务器配置和健康检查；
2. 接入 OIDC、律所/案件角色和 Web 会话，完成 PostgreSQL 实际权限验证；
3. 完成跨浏览器上传、对象存储、隔离盘点和可恢复任务；
4. 完成 PDF 逐页审阅、红框、锁定、生成和下载；
5. 逐步接回事实、交易、法源、利息、文书和提交包；
6. 在 Windows 与 macOS 浏览器分别验证同一真实材料流程，并验证跨律所/跨案件不可访问、备份恢复和审计记录。

“容器能启动”“网页能打开”或“macOS 桌面包能运行”均不构成商用放行。正式放行前仍须完成服务器补丁、HTTPS、备份恢复、身份服务、权限隔离、对象存储、Worker 沙箱、日志保留和律师可用性验收。
