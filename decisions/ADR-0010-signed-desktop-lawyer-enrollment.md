# ADR-0010：律师身份必须由律所签发、设备绑定并由 Keychain 保护

状态：已接受（代码与合成测试完成；真实签发和撤销运营尚未启用）

## 背景

macOS 登录用户、设备名、前端表单和案卷文件夹名称都不能证明执业身份、律所归属或案件授权。若允许使用者自行选择“主办律师”或把角色写入请求头，任何本机进程都可以提升权限。桌面产品又需要在不反复上传案卷的前提下建立稳定身份，因此必须把“本机进程”“律所身份”“本案权限”分开验证。

## 决定

1. 律师登记使用律所受信签发方生成的 Ed25519 签名凭证。应用只携带或受控取得公钥；私钥不得进入客户端、项目仓库、环境变量或 API 请求。
2. 签名对象使用严格规范化 JSON，字段集合固定。未知字段、重复字段、未知版本、未知签发 key、非 UUID 用户/律所/登记号、空角色、重复角色和 `SYSTEM_WORKER` 均拒绝。
3. 凭证包含 actor、firm、专业角色、签发/到期时间和安装绑定摘要；最长有效期 30 天，未来时间容差不超过 5 分钟。浏览器不能提交或覆盖这些字段。
4. 每台安装使用 32 字节随机安装秘密；签发凭证只包含其 SHA-256 绑定摘要，不包含秘密。复制凭证到其他设备不能建立会话。
5. macOS 第一实现通过固定 `/usr/bin/security find-generic-password` 分别只读取得签名凭证和安装秘密，限制项目、输出长度、超时和运行环境；错误不回显 Keychain stderr、凭证、秘密或绑定摘要。
6. 验证后的登记身份只能签发一次性 bootstrap 和最长 30 分钟的本机 Bearer。会话到期不得超过登记凭证到期。
7. 登记凭证只证明“谁在使用”；每次案件读写仍由 PostgreSQL 中 `users.status=ACTIVE`、未撤销的 `matter_actor_roles` 和当前角色复核。离职、停用或撤销本案角色必须立即阻断案件操作。
8. 当前 `.app` 不内置合成签发私钥，也不把测试公钥当生产信任根。没有真实律所签发配置、Keychain 登记和专用 PostgreSQL 时，sidecar 继续只开放禁用健康状态。

## 已实现验证

- 有效签名可恢复服务端 Actor，敏感安装绑定不进入对象 repr；
- 篡改角色、未知 key/issuer、跨设备复制、错误签名、过期、未来签发、超长期、非 UTC、重复字段和额外字段全部 fail closed；
- Keychain 适配器只调用固定只读命令，不把秘密放入参数，拒绝缺失、错误编码、超长项目和非 macOS 平台；
- 登记身份已能装配 `DesktopSessionAuthority`，且会话有效期受登记到期时间硬限制；
- PostgreSQL 案件 Store 已在每次读写中独立检查 active user 与未撤销案件角色，登记角色不替代数据库授权。

## 尚未完成的放行门

- 律所管理员或统一身份服务完成律师核验、签发、续期和撤销的真实服务；
- 安装秘密初始化、登记请求、凭证导入、轮换、撤销和恢复的原生界面与人工确认；
- 生产公钥轮换、撤销清单、安装器签名/公证和安全运维流程；
- 专用 PostgreSQL 实库迁移、离职/撤销整链和执业律师验收。

上述门未完成前，“本机服务已就绪”不得改写为“律师已登录”或“真实案件可用”。
