# ADR-0059：受控被告应诉验收的模型前材料续接不得合并重复原件

- 状态：已采纳
- 日期：2026-09-04
- 关联：ADR-0054、ADR-0055、ADR-0056、ADR-0058

## 背景

固定 88 页合成被告应诉案卷包含两份字节完全相同、但以不同文件名和来源身份
提交的借条照片。这是刻意保留的办案事实：字节哈希可以帮助核验内容是否变化，
却不能证明两份当事人交付的原件是同一份原件，也不能授权系统合并、覆盖或删除
其中之一。

首轮受管验收在第六份材料后、创建任何 Agent 运行或外部模型请求前停止。原因是
验收命令错误地仅以图片内容哈希构造上传保留幂等键，因而把另一份同内容原件判为
同一次上传。现有通用上传服务正确拒绝“同一幂等键、不同原件元数据”的请求；
错误在验收编排，而不是上传状态机。

## 决策

1. 固定验收的常见图片上传幂等键同时绑定冻结逻辑来源编号和内容哈希。相同逻辑
   来源的重放仍幂等；不同来源但内容相同的原件必须各自形成不可变接收记录。
2. 正常验收仍严格“一次新案件、一条连续链路”。固定案件已经存在时，普通命令
   一律停止，不会重传材料、创建第二个案件或自动触发任何模型调用。
3. 仅为这次 loopback 合成验收提供显式 `--resume-pre-model-intake` 恢复模式。它先
   从受管 PostgreSQL 读取不含对象定位、文件正文、会话机密或模型凭据的完成回执，
   严格比对：冻结文件名、来源身份、内容哈希、页数、接收路由、连续案件版本和
   已完成前缀顺序。若前缀已刚好覆盖全部材料、但尚未写入代理情境或 Agent 运行，
   它只复核该完整检查点后继续后续受控输入，不重传任何原件。
4. 恢复模式还必须证明所有案件绑定的代理情境、事实、诉请、法律事件/规则包、
   动态计划、Agent 运行均为零。任务尝试、外发和本地规划事件都是 Agent 运行的
   外键子记录，因此运行数为零即为它们不存在的数据库证明；Web 角色不因验收而
   获得读取 Worker 专属表的权限。官方法源快照及规则版本本身是律所级共享对象，
   不以它们的全局存在与否判断本案阶段。任何非完成上传、版本断裂、前缀不匹配或
   案件下游记录均停止；不做“猜测性恢复”。
5. 只有全部条件满足，恢复模式才接收缺失尾部材料；之后才进入原有单次 Qwen
   律师决策包调用与零外部调用的确定性答辩文书阶段。恢复本身不重发、不替换或
   增加模型调用。

> 后续限定：ADR-0060 仅为已完整接收材料、且能证明精确受控输入命令前缀的固定
> 合成验收增加了独立的 `--resume-pre-agent-inputs` 模式。它不放宽本 ADR 的材料
> 完整性条件，也不适用于真实案件或任何 Agent 运行之后的状态。

## 后果

- 验收真实体现证据原件不可变与内容去重的边界，避免为了跑通测试而抹去重复原件。
- 这不是通用生产案件的“自动重试”策略；真实案件仍遵循各上传状态机、律师会话、
  不确定对象状态和人工核对流程。
- 本次保留的前六份合成材料及其审计记录成为可核验的恢复前缀。若续接无法证明
  上述精确状态，验收会停在模型前，不以第二个案件或第二次模型调用掩盖问题。
- 证据账本对 PDF 与图片均保留原件和页级记录；验收按全部 11 份原件、88 页的
  冻结身份清单核验，而不是错误地把“PDF 原件数”当作账本全部原件数。
