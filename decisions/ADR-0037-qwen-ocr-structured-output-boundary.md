# ADR-0037：Qwen OCR 完整响应与结构化候选分离

- 状态：已接受
- 日期：2026-08-24

## 背景

受管 Agent Run 的第二张扫描件得到完整、已哈希并持久化的 Qwen `qwen3.5-ocr` 响应，但模型只返回一个业务字段的 JSON，而没有返回系统要求的来源绑定候选结构。恢复层可以精确找回原响应，严格候选解析器仍会拒绝它；旧 Worker 把该本地解析异常再次映射为未知，导致核验永远无法终结。

阿里云百炼当前模型说明明确标注 `qwen3.5-ocr` 不支持“结构化输出”。OCR API 的 OpenAI 兼容示例也把输出格式作为普通提示词，而不是受约束的 JSON Schema。因此不能把提示词遵循当成来源绑定或严格业务结构保证。

## 决策

Qwen 只接收服务器已授权的单页栅格，只被要求返回页面可见文字。它不再被要求回传案件 ID、页面 ID、哈希、坐标或业务 JSON Schema。服务器从已经完整持久化的 OpenAI 兼容响应中只取有界文本，然后用已授权投影生成来源绑定、待律师复核的 `VisualPageCandidate`。

OpenAI 兼容响应信封只允许在传输适配器中校验和拆解一次。任务适配器直接接收已经拆出的有界 UTF-8 OCR 文本，不得再次把文字当成供应商响应信封解析。

完整响应没有有效有界文本时，返回已知失败 `QWEN_VISUAL_OCR_PROVIDER_TEXT_INVALID`；这不是网络未知，不允许重发。

台账提取运行时必须显式读取直接图像依赖任务的成功成果。运行时重新核对当前图、依赖边、成功回执、不可变产物行、私有对象哈希与完整视觉候选格式；然后才把 OCR 文本作为 `OCR` 来源交给下游。任何引用 OCR 页的台账候选都由服务器强制加上 `OCR_DERIVED` 与 `UNTRUSTED_TEXT`，不进入自动提升通道。

## 后果

- 不再把提示词遵循当成来源完整性。
- OCR 文本可以进入真实的下游冲突提取链，但仍只是律师复核候选。
- 当前旧响应保持原有已知失败回执，不追溯改写，也不重发。
