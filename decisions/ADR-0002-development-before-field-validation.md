# ADR-0002：合成数据开发先行，真实流程验证作为试点放行门

状态：`Accepted`

日期：`2026-08-09`

## 背景

原计划将律师访谈、流程观察、金标准案件和 Phase 1 任务测试设为业务页面与技术基础编码的前置条件。该安排能避免把错误假设固化为产品，但会使项目在没有外部招募资源时完全停工，也不符合产品负责人“先把完整产品开发出来、真实流程验证由其组织”的明确分工。

## 决策

1. 立即使用严格合成、版本化的案例数据实现 Phase 1—7 的内部 Alpha；
2. 三种中文视觉方向完成后，产品负责人可自行选择，或明确委托项目负责人作出记录在案的暂定选择；
3. 真实律师访谈、流程观察、金标准案件和 5 人可用性测试转为并行工作流，以及真实案件接入、封闭试点和生产声明的硬放行门；
4. 不因开发先行而降低原件保护、律师审批、确定性计算、权限、审计、法源和唯一提交版要求；
5. 未通过 Phase 0/1 真实验证的系统只能称为“内部合成 Alpha”，不得接收真实案件材料、调用未经授权的外部处理服务、生成可向法院提交的材料或对外宣传为已获律师接受。

## 原因

- 合成数据足以开发和自动化验证状态机、权限、页级处理、计算、文书编译和依赖失效等确定性能力；
- 实际流程验证需要产品负责人协调律师和合法脱敏材料，开发团队不能虚构这些证据；
- 将真实验证留作试点放行门，既保持风险控制，也避免无谓停工。

## 后果

### 正面

- 产品实现按既定架构、依赖关系和质量策略持续推进；
- 真实验证发现的问题仍能通过合成回归样例转化为可复现修正；
- 不会把“自动测试通过”误写为“律师已接受”或“可用于真实诉讼”。

### 约束和风险

- 缺乏真实工作流反馈时，界面和自动化优先级仍可能存在偏差；
- 开发完成不等于可试点，真实验证失败仍可能要求返工；
- 真实资料接入和生产部署前，原计划中的安全、法源、恢复和律师终审门全部继续有效。

## 被否决方案

### 等待全部真实验证后再开始编码

会造成可由合成数据完成的工程停滞，不采用。

### 取消真实验证与试点门

会把内部演示误当作法律产品可用性证明，风险不可接受，不采用。
