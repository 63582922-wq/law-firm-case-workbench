# ADR-0065：受控规则来源与模型批准声明的精确区分

- 状态：已采纳，等待受管 v2 合成验收
- 日期：2026-09-04
- 关联：ADR-0043、ADR-0044、ADR-0055、ADR-0063、ADR-0064

## 背景

固定 88 页合成被告应诉案的首轮受管模型调用已完整返回，且未重试。其原始供应商响应、
请求哈希和用量回执已经被私有审计链固定。应用层输出校验随后把一段攻防建议中的
“结合已批准规则”识别为模型声称本案已获批准，因而以
`LAWYER_ANALYSIS_OUTPUT_REJECTED` 进入 `WAITING_INPUT`。

只读离线回放证明：该短语是服务器投影中 `APPROVED_LEGAL_RULE` 的来源描述，不包含
模型、律师或法院已经批准本案事实、策略、金额、文书或提交的含义。旧实现按任意
“已批准”字面量拦截，既无法区分该受控来源描述，也与模型提示中暴露的“已批准法律规则对象”
不一致。

旧运行的失败事件、原始响应和一次外发计数均是不可变审计事实。它们不能被修补后的
解析器改写为成功，也不能在原运行上重新提交模型。

## 决策

1. 模型自由文本继续禁止任何事实、立场、计算、文书、锁定、提交或律师决定的批准声明；
   “已终审”“已锁定”“已提交法院”“无需律师复核”等既有硬门保持不变。
2. 仅允许精确的规则来源名词短语 `已批准规则`、`已批准的规则` 及其“法律/受控/适用/
   利息/程序/计算/民间借贷 + 规则（版本）”受限变体。解析器移除该受限来源短语后，
   文本中残留的任意“已批准”仍失败关闭。
3. 系统提示改为要求模型使用“受控规则来源”，不应主动生成“已批准……”表述。解析器的
   窄例外只用于兼容已封存的首轮响应和抵抗模型偶发同义表达，不把批准权交给模型。
4. 增加正反回归：来源短语必须可解析；“本案处理已批准”等批准声明必须继续被拒绝。
5. 首轮运行永久保留为一次已失败的外发证据。经代码、回放和运行时重建核验后，允许创建
   一个独立命名的 `managed-defence-single-call-v2` 合成案件，最多进行一笔新模型调用。
   它不是旧运行重试，也不得因失败自动创建 v3 或后续调用。

## 后果

- 安全门从模糊关键词转为最小语义例外，减少合法服务器来源标签造成的假阳性，同时保留
  对真正越权声明的拒绝。
- 旧运行不会被“补成功”，审计仍可完整说明为什么当时停止。
- v2 若不能同时通过严格结构、语义硬门、确定性编译、文书渲染和受管运行审计，验收保持失败，
  进入架构诊断而非继续调参或循环调用。
