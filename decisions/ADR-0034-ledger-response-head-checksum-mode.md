# ADR-0034：付款台账响应回读显式请求对象校验和

## 状态

已采纳。

## 背景

付款台账提取的外部调用采用一次发送、未知结果只查找不重发的恢复边界。原始响应先以确定性对象键写入私有 S3 兼容对象存储，再以对象长度、媒体类型、服务端加密、绑定元数据和 SHA-256 校验和完成回读认证。

真实受管环境证明：S3 兼容服务可以在对象已正确写入时，默认 `HEAD` 响应仍省略 `ChecksumSHA256`。旧实现未显式请求校验字段，因此把已经持久化的成功响应误判为结果未知；随后恢复查找也因同一缺失字段停止。

## 决策

1. 付款台账响应存储适配器的所有 `HEAD` 请求统一附带 `ChecksumMode=ENABLED`。
2. 仍要求返回值中的 SHA-256 与写入回执完全一致；不允许只依赖自定义元数据、ETag 或对象长度。
3. 该修复只改变确定性对象查找和认证，不重发原始模型请求，也不放宽未知结果保护。
4. 注入的测试客户端与生产 S3 客户端经过同一包装器，防止测试路径与真实路径漂移。
5. 如果只读恢复在提交终态回执前中断，过期的 `RECONCILING` 租约可以被后续 Worker 原位接管；接管仍指向同一个 UNKNOWN attempt 和外部请求 ID，只能进入适配器的 `reconcile` 路径，不能再次 dispatch 或发送。

## 后果

- 已持久化但此前被误判为未知的响应可由原请求 ID 和请求哈希安全回收。
- Worker 重启或恢复步骤中断后不会因一条过期的恢复租约永久卡死。
- 对象存储若确实无法返回 SHA-256，运行仍会失败关闭，不会把未经认证的响应交给 Agent。
- 该结论只证明本次对象回读缺陷及其修复，不等于完整 Agent 端到端已经通过。
