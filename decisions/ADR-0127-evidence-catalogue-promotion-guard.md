# ADR-0127：证据目录可附带已确认原页，但不扩大 Agent 分析输入

状态：`Accepted`

日期：`2026-09-11`

## 问题

首轮办案分析刻意不把原始证据页发送给模型；其图谱只绑定已确认的案情、诉请、法律口径和律师
确认的争点。与此同时，已激活的办案计划需要生成确定性的证据目录。目录每一行必须回到已确认
且已纳入范围的证据页，因此计划编译器会附带这些原页作为目录来源。

原 `0043` 的数据库触发器要求计划来源与 Agent 图谱输入完全相等。这把“目录所需、由服务器补入
的已确认原页”当成来源越界，导致模型已经完成的律师决策包无法进入用户下一步的办案计划。

## 决定

`0105` 保留图谱输入与计划来源的双向完整性校验，只增加一个极窄例外：

- 例外必须是 `EVIDENCE_PAGE`、状态为 `CONFIRMED`、用途为 `EVIDENCE`，且输入标识严格等于
  `evidence-page:<object_id>`；
- 该页必须同时是同一候选计划中 `EVIDENCE_CATALOGUE` 文书事项的精确 `SOURCE` 引用；该引用必须
  指向同一不可变绑定 ID，且绑定的对象版本、绑定哈希和用途完全一致；
- 不允许其他对象类型、未确认页、其他文书类型、浏览器参数或模型自由引用通过该例外。

## 后果

律师可以在同一条办案主线中得到“风险与行动清单”后的证据目录候选，而不会把原件送入首轮模型、
把证据页自动认定为事实，或让候选直接成为法院提交材料。答辩状、目录和收付款表仍是内部审阅
候选；激活、生成、律师复核和下载继续分别留有门槛。
