# ADR-0060：受控被告应诉验收的 Agent 前输入回放恢复

- 状态：已采纳
- 日期：2026-09-04
- 关联：ADR-0054、ADR-0055、ADR-0056、ADR-0058、ADR-0059

## 背景

ADR-0059 已确保固定 88 页合成案卷能从“仅材料接收”检查点恢复，且不重传
已接收原件。后续真实执行发现另一种不同的、仍在模型前的中断：诉请回应已经以
不可变账本命令成功登记，但验收编排把独立的 `CLAIM_RESPONSE` 回执误认为必须复用
`CLAIM` 标识，因此错误停止。

删除或覆盖已确认代理情境、事实、诉请回应来“重来”违反案卷可追溯原则；新建第二
个合成案件也会掩盖恢复能力，并可能把一次零模型故障误报成多次 Agent 尝试。

## 决策

1. 新增显式 `--resume-pre-agent-inputs`，只适用于固定 loopback 合成验收案件。它与
   ADR-0059 的 `--resume-pre-model-intake` 互斥，不能用于真实案件。
2. 该模式首先复核 ADR-0059 的完整 11 原件、88 页、连续材料版本和证据账本；不
   重传、替换、合并或删除任何原件。
3. 它随后仅读取最小命令回执投影（命令名、受限幂等键、案件版本），并要求它精确
   等于冻结的 18 步前 Agent 输入前缀：五项代理情境、五项事实候选及确认、诉请
   候选/范围/回应。案件版本、代理档案/事实/诉请/回应数量必须逐项吻合。
4. 任何法律事件、法律包、动态计划、Agent 目标或 Agent 运行都会阻断恢复。任务
   尝试、外发和产物均由 Agent 运行外键约束，因此运行数为零证明没有模型任务或
   对外模型提交；不向 Web 角色授予读取 Worker 私有表的权限。
5. 只有全部检查通过，编排才以首次固定案件版本及相同幂等键重放这 18 个受管命令。
   已完成命令只能返回原回执；缺失的下一命令只能在其预定版本上写入。之后才登记
   法源输入并创建唯一的律师决策包 Agent 运行。恢复本身不调用模型、不重试外发、
   不锁定文书或提交材料。

## 后果

- 错误的验收回执判断不会迫使系统丢弃或复制已确认输入，恢复链本身成为可审计
  的产品级韧性证据。
- 该模式不是生产案件的自动恢复入口。真实案件仍须由律师会话、权限、材料状态、
  不确定外部提交及案件级恢复策略分别控制。
- 若命令前缀、版本、投影或任何 Agent 前置条件不精确匹配，命令立即停止；不会尝试
  猜测、补写或创建第二笔模型调用。
