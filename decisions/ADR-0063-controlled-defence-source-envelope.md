# ADR-0063：被告应诉单次分析的受控来源信封

- 状态：已采纳
- 日期：2026-09-04
- 关联：ADR-0041、ADR-0055、ADR-0056、ADR-0058

## 背景

ADR-0056 已规定，一审被告应诉的首轮唯一模型调用只能读取当前已确认的代理档案、
事实、诉请回应、已核验法源和已批准规则；原始 PDF、图片、OCR 文本和未复核材料
必须留在私有证据链中，不能因规划而出站。ADR-0058 又明确该专用运行档不安装 Qwen
视觉 OCR。

实际受管运行暴露出一个与该产品边界冲突的实现：通用快照提供者在进入受控规划器前
先要求每一页证据都有当前可执行的适配器。因此，冻结案卷中的 JPEG 页面会在模型调用
前让整个被告应诉运行失败，尽管该页面本就不应属于首轮模型来源。

## 决策

1. 生产 Worker 同时保留完整通用快照和被告应诉专用快照。仅当服务器已确认目标包含
   `DEFENCE_STATEMENT` 时，专用快照才生效；其他目标继续使用完整快照，并对不支持的
   输入保持失败关闭。
2. 专用快照只保留 `POSTURE_PROFILE`、`CASE_FACT`、`CASE_CLAIM`、
   `VERIFIED_LEGAL_SOURCE` 和 `APPROVED_LEGAL_RULE`。它在同一原子事务读取完整投影，
   再生成带独立哈希的受限投影；不删除、覆盖、合并或向模型开放任何原始证据。
3. 活跃的证据重新提取义务，或绑定到受限来源集合之外的律师纠正/否认信号，必须阻断
   该受控路径。系统不得为了维持“一次调用”而悄悄省略律师决定或未完成证据义务。
4. 已激活计划的第二运行继续由服务端目标绑定其文书交付物；它不以工作计划、程序事件
   或原始证据扩大模型来源，也不得产生新的律师分析调用。
5. 回归测试必须同时证明：含未配置视觉 OCR 的 JPEG 证据时，被告应诉快照不把该页交给
   模型；非被告应诉目标仍因该页无可执行适配器而失败关闭。

## 后果

- 单次被告应诉验收恢复与产品说明一致：唯一模型调用测试律师决策能力，而非因被设计为
  不在该调用范围内的 OCR 能力失败。
- 这不表示图片证据已被读取、识别或审查。图片仍须通过已配置的视觉能力或律师人工复核
  才能进入后续事实、交易或法律结论链。
- 通用案件 Agent 的文件能力门不被放宽；任何要把原始图片用于规划或执行的路径仍须安装
  并验证相应适配器、数据路径、预算与审批边界。
