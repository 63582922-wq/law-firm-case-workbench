# ADR-0045：未核验法律缺口触发服务器强制研究规划

- 状态：已采纳，离线实现与回归完成，独立真实运行待验收
- 日期：2026-08-29
- 关联：ADR-0027、ADR-0040、ADR-0041、ADR-0044

## 背景

现有系统已经分别具备案件规划、受控公共检索和官方法源快照能力，但三者没有形成不可
绕过的连续链路。规划模型能够看到 `LEGAL_GAP`，却可以只安排案件阅读和律师分析，导致
一次技术上成功的 Agent 运行在没有任何研究计划、正式法源或适用性复核的情况下结束。
另一方面，直接把公开网页检索自动化为法律依据会泄露案情，并混淆检索线索、官方原文、
时间效力和本案适用结论。

因此，法律缺口不能继续只是模型提示，也不能用一次联网搜索代替完整法源治理。系统需要
一个不出网、低风险、可自动执行的中间产物，把当前受管案件对象转化为律师可审阅的研究
问题和最小公共词，同时把后续外部动作继续锁在独立审批与审计边界内。

## 决策

1. 生产 Worker 安装 `legal_rule_research_planning` 后，只要当前案件快照存在未解决的
   `LEGAL_GAP`，服务器必须在编译图中插入一项研究规划任务。模型看不到、不能请求、删除、
   改写或替换该任务；图预算不足或没有可执行的受管来源时失败关闭。
2. 该任务为 `A1_PROPOSE / ApprovalGate.NONE`，仅因为它在进程内确定性运行、网络始终
   `DENY`、外部调用与费用上限均为零，且只生成 `NEEDS_LAWYER_REVIEW` 候选。此处的免审批
   不延伸到搜索、抓取、法源效力判断、本案适用或对外提交。
3. 研究规划输入只允许当前案件快照中的强类型对象：已确认事实和交易、诉请、争点、代理
   情境、动态计划项、已核验法源及程序事件。投影端重新核验 Worker 身份、当前图、案件版本、
   输入顺序、对象版本和内容哈希。
4. 内部研究问题可以保留案件语境，但任何未来公共查询只能使用服务端固定法律词表的精确
   子集。姓名、金额、账号、案号、自由文本和模型生成词不能跨出案件边界。
5. 研究计划固定记录：研究问题、是否先需律师确认争点、建议公共词、官方来源类别、时间
   效力检查、相反解释、来源引用和后续律师门。产物明确声明无正式事实、无正式交易、无法律
   结论、不可提交法院。
6. 公共搜索继续是独立的律师批准网络任务。搜索结果只算线索；成为正式法源还必须完成官方
   域名与发布机关核验、原始字节捕获、稳定定位、版本和生失效期间核对。法律效果和本案适用
   仍须由律师决定。
7. 独立验证器必须解析研究计划的严格规范 JSON，并要求其顶层来源集合与编译任务输入逐项
   完全一致。增加、遗漏或替换任何来源，提升为法律结论，打开网络或改变控制字段均拒绝。
8. 活动计划执行、重新提取恢复和外部检索保持各自独立工作流；本 ADR 不授权模型计算正式
   金额、批准规则、激活计划或生成法院提交版。

## 后果

- 一次全案 Agent 运行不能再在存在开放法律缺口时静默跳过研究规划。
- 无外部检索凭据时，系统会如实停在“研究计划待律师批准/争点待确认”，而不是编造依据或
  反复要求用户登录。
- 有凭据也不会自动把搜索结果升级为法律依据；正式法源捕获、效力审查和本案适用仍需继续
  接通并分别验收。
- 当前状态是 `IMPLEMENTED_OFFLINE_NOT_LIVE_ACCEPTED`。112 项相关回归已通过，但只有新的
  独立合成案件运行生成并验证该产物后，才能标记为运行时已测试；执业律师认可和商用放行
  仍属于后续门。
