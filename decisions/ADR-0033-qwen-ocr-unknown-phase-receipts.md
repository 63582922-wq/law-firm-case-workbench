# ADR-0033：Qwen OCR 结果未知仅记录安全阶段码

- 状态：已接受
- 日期：2026-08-24

## 背景

0055 已把完整 HTTP/响应拒绝与真正不确定的网络结果分开，但一次真实受管运行仍在约三秒进入 `UNKNOWN_SUBMISSION`。DNS、TLS、请求大小、模型参数和总超时都已有独立证据，单一通用未知码无法判断阻断发生在发送前还是供应商可能已接收后。继续盲跑既不能定位问题，也会违反一次调用边界。

## 决策

固定 HTTPS Broker 只为不确定结果产生五个受控阶段码：DNS、连接、发送、响应头、响应体。阶段码绑定已有外部请求 UUID；不携带或持久化异常文本、地址、凭据、请求体、响应体、材料内容或供应商请求 ID。

所有阶段码仍登记为追加式 `UNKNOWN_SUBMISSION`。恢复路径只查询原交换记录，不重发。未能归类的旧异常继续使用通用 `QWEN_VISUAL_OCR_OUTCOME_UNKNOWN`，避免把未知错误误写成明确失败。

Worker 启动预检要求数据库约束明确接受全部五个阶段码；代码先于迁移部署时必须拒绝启动。

## 后果

- 下一次受控运行可确定唯一网络阻断层，而不扩大敏感日志面。
- 阶段码不是供应商失败结论，也不改变最多一次调用保证。
- 任何修复仍须创建新的受控 Run；已有未知请求不会被自动重发。
- 阶段定位完成后只修复该阻断，不以重复测试代替整案运行。
