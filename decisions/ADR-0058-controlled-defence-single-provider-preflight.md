# ADR-0058：被告应诉单次验收不得用无关模型预检消耗调用

- 状态：已采纳
- 日期：2026-09-04
- 关联：ADR-0041、ADR-0044、ADR-0054、ADR-0055、ADR-0056、ADR-0057

## 背景

ADR-0055 定义的受管被告应诉验收只允许一笔新的外部模型调用：受限的律师
决策包分析。答辩状候选由确定性编译器和隔离 Office 渲染器生成，网络策略为
`DENY`，不应依赖任何文书、台账或视觉 OCR 模型。

原本的本地受管部署复用了通用 `provider-preflight`。该预检会在 Worker 启动前
实际调用 DeepSeek 文书、DeepSeek 台账和 Qwen OCR。即使受控答辩图永远不会
调度这些技能，预检也已经额外消耗了调用并可能因无关能力阻断运行。这与“只验证
一次真实律师分析”的验收合同矛盾。

## 决策

1. 通用部署的 `all` 预检保持不变；它仍可在启用全部能力的标准运行档中探测各
   自的外部模型。
2. 固定 loopback 合成被告应诉环境改用 `controlled-defence` 预检。该预检仅校验
   Qwen 律师分析凭据和工作区配置的结构合法性，网络命名空间为 `none`，明确记录
   `network_calls=0`；它不把“配置合法”表述为模型已可用。
3. 应诉专用 Worker 不安装 Qwen OCR 或 DeepSeek 台账提取凭据。受控本地规划器
   仍拒绝所有非答辩目标，且答辩文书只通过确定性文书任务产生。运行结束后必须从
   持久任务图和预算账本确认首轮正好一笔 Qwen 律师分析、文书轮零外部调用。
4. 若唯一的律师分析调用失败、未知或返回不合约束的结果，验收保留现场并停止；
   不以预检模型调用、换模型或自动重试补偿。

## 后果

- 真实验收的费用、可见能力与用户所要求的工作链一致：一次受控分析，再生成
  可审阅的 Word/PDF 答辩候选。
- 未启用的 OCR、台账与文书模型既不会在启动期扣费，也不能因自身故障妨碍被告
  应诉验收。
- 这只收敛本地合成验收档；面向真实客户案的通用部署仍须按所启用技能逐项完成
  外部供应商、数据路径和律师审批验证。
