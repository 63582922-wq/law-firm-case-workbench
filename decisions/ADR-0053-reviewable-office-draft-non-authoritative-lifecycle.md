# ADR-0053：Office 审阅候选不推进案件输入版本

- 状态：已采纳
- 日期：2026-09-04
- 关联：ADR-0040、ADR-0046、ADR-0049、ADR-0050、ADR-0051

## 背景

可编辑 DOCX/XLSX 与其 PDF 审阅稿都是由已确认快照派生出的内部候选。登记或律师批准这类候选会改变候选本身的审阅状态，却不会改变案件事实、证据、诉请、程序、法律依据、计算参数或已激活的办案计划。

此前这两类动作共用了案件正式账本的版本推进与 Outbox。结果是一次文书排版或下载链路验收会把仍然有效的 Agent 计划视为“案情已变”，错误阻断后续受控执行。这既误导律师，也会诱导不必要的重新分析。

## 决策

1. `REVIEWABLE_OFFICE_DRAFT_PAIR_REGISTERED` 与 `REVIEWABLE_OFFICE_DRAFT_PAIR_APPROVED` 继续写入不可抵赖的审计记录和幂等回执，但审计记录保持 `input_version = output_version`，不更新 `matters.version`，也不发出案件聚合 Outbox。
2. 该例外只适用于上述两种固定、服务器拥有的 Office 审阅候选事件；事实、证据、诉请、程序、法源、计算、提交包和 Agent 图谱的写入仍须推进案件版本并使依赖成果失效。
3. 每次非权威动作仍先取得同一案件和当前版本的行锁，仍受角色、租户、对象哈希、审阅绑定和幂等键约束；它不因此获得修改正式账本或绕过律师审批的权限。
4. 已经写入的历史版本和审计事件不回写、不重标。该修复只影响迁移后创建或批准的 Office 审阅候选。

## 后果

- 律师可以反复生成、审阅、下载或批准内部候选，不会误使有效 Agent 分析、动态计划或提交链失效。
- 事实性上游变化仍 fail-closed；这不是将“文书版本变化”误当作“案情未变”的宽松策略。
- 审计模型现在明确区分“案件输入版本”与“派生工作产品的审阅生命周期”，而不会再用单一聚合时钟代替两种语义。
