# ADR-0064：首轮被告应诉运行的模型前精确续接

- 状态：已采纳
- 日期：2026-09-04
- 关联：ADR-0044、ADR-0055、ADR-0056、ADR-0059、ADR-0060、ADR-0063

## 背景

受管的合成被告应诉案已在服务器端创建首轮 Agent 运行，但在 Worker 取得规划命令
之前，通用快照错误地将四页 JPEG 原件送入未安装视觉 OCR 的首轮来源检查。该错误没有
触发外部模型调用，却留下同一固定 idempotency key 对应的 `CREATED` 运行和本地运行器
事故审计记录。

重新创建运行会破坏“单次模型调用”的验收含义，也会把一次可解释的本地前置失败伪装成
第二次独立尝试。仅凭“看起来没有输出”也不足以安全续接：必须能够从状态机证明从未
领取规划命令或提交任何外部请求。

## 决策

1. 仅允许固定合成案的首轮、固定 idempotency key 派生的运行执行模型前续接；恢复逻辑
   禁止调用创建运行接口，也禁止接受替代运行 ID。
2. 续接前必须同时核验：11 份、88 页冻结合成材料；完整受控输入命令回执；法源检查点
   对应的案件版本；一条代理档案、五项事实、一项诉请、一项回应、一条法源事件和一套
   法律包；无工作计划；一项目标和一条运行记录。
3. 运行只可处于两个精确的模型前边界之一：
   - `CREATED`、事件版本 `1`、当前输入快照、无任务、无成果、无失败和无活动计划执行；
   - `WAITING_APPROVAL`、事件版本 `5`，且仅已完成一项无网络的案件情境任务，唯一待批准
     任务是依赖该情境的律师决策包分析，任务尝试数为零、模型外发数为零、成果仅为案件情境
     候选。

   第一种边界证明尚未领取规划命令；第二种边界允许 Worker 在运行命令附着前完成确定性
   本地准备，但仍从状态机、任务图、审批卡、预算和成果共同证明模型尚未启动。
4. 运行器事故审计记录不得被删除、覆盖或用作已提交模型的替代证据。它们可以与上述
   运行状态并存，并保留为前置实现故障的可追溯记录。
5. 任何一个核验项不匹配即失败关闭，且不得自动重试、创建新运行或补发模型调用。

## 后果

- 修复 ADR-0063 的来源信封后，系统可以让同一条尚未提交模型的运行继续；即使 Worker 已
  完成受限的本地情境准备，也不会把一次真实模型能力验收扩展成多次调用。
- 这只适用于明确证明“零模型提交”的精确状态，不构成通用任务恢复策略。发生规划领取、
  外部请求、输出、失败状态或版本漂移时，必须由律师和运行治理流程另行决定。
- 审计能同时解释两件事：原始本地故障为何发生，以及后续模型调用为何仍是唯一一次。
