# ADR-0023：模型供应商凭证只保存在桌面系统钥匙串

状态：已采纳（凭证配置通道）；供应商调用适配器仍未装配

## 背景

案件工作台需要在未来受控调用文本推理和视觉/OCR 服务。将 API Key 放入 `.env`、浏览器 Local Storage、案卷文件夹、数据库、审计日志或用户聊天都会造成可复制、难撤销和难审计的泄露面。

## 决定

1. 桌面端仅允许固定白名单供应商 `deepseek` 与 `qwen` 的 API Key 配置；不允许用户输入自定义 Base URL、任意模型 ID 或代理地址。
2. API Key 必须经 macOS 原生 `NSSecureTextField` 输入，并由 Rust 直接写入 macOS Keychain；WebView、Tauri 命令参数、React 状态、案卷数据库和外部请求账本永远不接收 Key 明文。
3. 页面只取得供应商标识、显示名称和“已配置/未配置”状态。更换 Key 覆盖同一 Keychain 项，移除操作需要 macOS 原生确认。
4. 配置 Key 与调用授权严格分离。没有本案有效的外部请求预授权，即使 Key 已配置也不得向任何供应商发送材料。
5. 当前交付只完成本机存储与状态界面；没有供应商请求适配器、计量器或真实案件数据外发能力，不得据此宣称 DeepSeek/Qwen 已被实际调用。

## 后果

- 使用者将在“身份与安全 → 模型与外部服务”中直接完成配置，无须改环境变量或把密钥交给聊天窗口。
- 后续适配器必须在 Rust/受控 Worker 内读取 Keychain，先通过外部请求账本 preflight，再以固定 HTTPS 端点和允许的模型清单请求供应商。
- 非 macOS 桌面环境保持 fail closed，不能回退到网页文本输入。
