# ADR-0086：正文修订先保存为独立提案

状态：Accepted

日期：2026-09-05

2026-09-10本地合成资格补充（优先于下方历史未部署描述）：0078已部署。真实Web身份
保存/授权同键恢复通过；授权插入请求、任务与审计后注入异常，整个事务回滚，随后同键
正式提交成功。实跑修复来源绑定只设firm漏设actor导致认领任务RLS不可见的问题，
使用真实Worker身份上下文，不修改RLS或角色权限。第2版后台消费者与第3版Chrome
修改/授权/常驻消费均获独立PASSED，旧版本留存；第3版Word/PDF实际浏览器下载摘要
一致，旧审阅标识不能下载新版。仅本地overlay及本地前端启用，不代表商业发布或律师终审。
UNKNOWN恢复、跨身份并发等未实跑分支不因上述正常链通过被宣布完成。

正文修改不是模板升级。复用现有文书版本与权限读取，增加一张只追加的正文提案表，不复用会自动入队的模板更新请求。
提案保存当前包身份、版本、修改人、幂等键哈希、候选字节和差异清单；同键同内容返回同一提案，不同内容拒绝。
事务内再次核验当前包、来源绑定及候选语义哈希，防止调用者替换原文。数据库强制律所与活动案件角色隔离。
正文和差异保存在现有私有 PostgreSQL，禁止进入普通日志或 Git。每项提案体积有界，不新增外部服务。

保存提案不等于替换当前文书，不自动生成、终审或提交，也不继承旧批准。旧批准只覆盖旧版本；未来接受提案、
生成后继与重新复核必须另有明确状态转换，不能把本表当交付包表读取。当前阶段不开启用户入口或后台消费。

实施顺序：迁移与持久命令 → 接入案件授权服务/API与界面 → 独立复核及后继生成。每阶段区分代码检查与真实数据库验收；
依用户资源限制，不启动 Docker。真实数据库权限及并发测试留待授权的充足资源环境执行。

保存结果核对采用同源只读接口，原幂等键仅在请求头中传入，服务端按原操作者、案件及文书版本链查询已提交记录。
不存在可见记录只返回 UNCONFIRMED，不推断保存失败，不自动重新提交。回执定位不代表内容已核验，
定位后仍通过详情接口检查审核清单完整性。

跨刷新恢复只在 sessionStorage 保留原请求键、原版本和创建时间，不保留正文、理由、来源、身份凭据或令牌。
存储键由会话接口返回的非授权恢复命名空间、案件/运行/文书及段落位置隔离；命名空间为律所/操作者身份的
固定域哈希，仅用于分区，不能替代案件授权。切换身份不复用其他分区，请求结果仍只允许原操作者核对。
首次写请求前须成功保存恢复元数据；存储不可用或记录损坏时不发送修改。刷新恢复只读查询，不重发丢失的正文。
已读取完整保存记录或服务明确拒收后清除对应元数据；未知结果保留，关闭标签页后的恢复依赖服务器记录列表，
不承诺恢复尚未提交的正文。不得把会话存储保留时间视为服务器请求失败证明。

后继生成前的技术复核必须重新读取当前前驱包与提案，核对数据库登记的候选哈希、来源绑定、提案作者及原稿字节。
从原稿重放明确的段落变更，生成的候选必须与提案字节语义一致，差异预览也必须可以重建；不能仅验证一个存储哈希。
该技术核验只证明完整性、来源归属和变更范围，不证明证据充分性、法律立场正确或律师已批准。
当前新增读取函数尚未接入批准命令或渲染队列；正式接入时还需事务内重新核验版本与批准记录，不把只读预检当授权票据。

生成授权使用独立只追加记录，目的固定为 GENERATE_REVIEW_COPY；仅本案活动主办律师或复核人可记录。
它绑定提案、前驱版本、候选哈希、来源绑定、决定人和复核说明。同键重复返回原记录，不同内容拒绝；
同一提案仅有一条生成授权，不覆盖历史。事务内锁定版本链后重读并重放提案，不能只凭前端“已看过”记录授权。
此授权不是事实/法律规则批准，也不是新版终审。生成消费者接入前仍不入队；接入后须重新核对版本和人员权限，
渲染和独立文件核验完成后形成新的待终审包，旧批准不能继承。现阶段不要求额外第二名律师，技术独立核验仍必须保留。

正文编译使用已授权且可重放的完整修订候选，不能调用模板内容生成器重造正文。现有 Office/PDF 转换协议可复用，
但 0073 的 DETERMINISTIC_TEMPLATE_REVISION 模式不可用于正文修订。新的正文登记模式和持久任务认领接通前，
编译函数不挂入生产消费者；转换 UNKNOWN 不得在函数内部自动重试。授权候选的只读查询不是持久任务认领。

登记新正文包还必须绑定持久任务的认领。先建立独立正文生成任务（不是模板更新 inbox）：READY → LEASED →
RENDERING，认领携版本栅栏与租期。仅未进入渲染的过期认领可重新获取，最多三次；RENDERING 过期只转 UNKNOWN，
不自动回 READY。当前阶段不创建任务、不启用消费者；文书包模式、验证回执及状态审计完成后再启用。

后台读取授权稿使用真实 SYSTEM_WORKER 身份，不借用律师身份。提案与生成授权的律师 RLS 策略限定到
Web 应用角色；后台另设只读策略，仅允许读取自身同案、同运行、未过期 LEASED/RENDERING 任务对应的提案与授权。
两类策略明确分离，避免提案与授权互相引用时形成递归策略。后台读取还须核对认领版本、当前文书版本链、
当前 PASSED 根包来源、案件快照、授权人仍有本案角色，以及原稿与候选指纹，重放明确修改。
该读取不创建任务、不代表可以登记后继；渲染前仍需持久阶段转换，登记时仍需重新检查版本和权限。

正文后继沿用 case_agent_document_revision_requests 作为版本请求身份，不另建文书注册表。
请求增加可空的 content_generation_review_id；空值保持既有模板请求合同与摘要，非空值使用独立摘要域，
绑定不可变生成授权、原模板和前驱回执。记录生成授权与正文版本请求在同一事务完成。
正文请求不进入旧模板 inbox，不触发模板消费者；当前登记只是待生成命令，不是后继包或已交付状态。
0078 尚未部署，因此这些同一功能的字段和守卫在该迁移内完善；已应用的 0073 不修改。

正文文书包使用 LAWYER_CONTENT_REVISION 模式，复用既有 revision_request_id、根包、前驱包、
版本号和请求人字段；模式本身与全部版本坐标一并进入 v2 文书包回执摘要。首次生成的 v1 和模板更新
的 v2 摘要保持兼容。正文模式限于 DOCX，不能借此提交任意台账内容。仅定义回执合同不开放登记；
数据库正文插入守卫、认领栅栏与独立回执路径接通前，实际 stage_package 必须在数据库/对象写入前拒绝该模式。

正文包另存 content_generation_claim_version（1—3），只允许正文模式携带，并纳入该模式的回执摘要；
初始/模板模式不增加摘要字段。0078 的正文插入守卫锁定根版本链与任务行，要求仍有效的 RENDERING 租期、
精确认领版本、专用 Worker、仍有案件角色的授权人、已授权候选/来源指纹、原模板和当前计划/快照/根包复核链。
该守卫不能替代文件字节的独立复核。应用写入合同已按模式接线：只有正文 INSERT 增加认领版本列，
旧模式维持原 SQL/参数，兼容尚无 0078 的旧库；重复包按同一版本请求读取后逐字段核对。
正文预写入与事务内复查共用当前计划/来源检查，并额外匹配 RENDERING、认领版本、授权候选/绑定指纹和活动律师角色；
两种修订均检查实际租期。查询仅使用固定 SQL 片段与参数绑定。独立成功回执和消费者尚未接通，保留入口阻断。

独立复核继续使用原 revision_receipts。正文 PASSED 必须由不同于生成者的专用校验身份记录，绑定仍处于
有效 RENDERING 的任务、精确认领编号、授权候选和当前案件/计划；UNKNOWN 不得转为成功或自动重试。
成功回执与任务 SUCCEEDED 在同一事务落地；FAILED/UNKNOWN 也同步任务状态并保留审计。任务终态不能独立于
对应回执写成成功。校验数据库角色只增加任务 SELECT/UPDATE(state)（行锁需要更新权限）与受控授权读取，
不授予认领者、次数或租期字段的更新权限；状态守卫仍必须证明回执及操作者。应用完整消费者完成前入口保持关闭。

模板与正文共用应用回执写入器。先锁同一请求并读取已有回执：身份、用途与结果指纹完全一致才返回；
不同结果拒绝，缺失才插入，再复读确认。不能仅依赖 INSERT ON CONFLICT，因为 BEFORE INSERT 守卫会先执行，
已进入 SUCCEEDED 的正文任务不应因同结果恢复而再次走渲染态守卫。此写入器不替代独立文件读取/校验。

正文消费者现按认领读取版本请求与原稿，重建当前来源、重放授权候选，提交渲染标记后再转换、登记和独立读取，
核对候选/版本/认领编号后使用共用回执。通用异常若发生在渲染开始后，只记录 UNKNOWN，不重新转换；
成功回执失联不补写失败回执，只尝试保留未知状态，数据库不得把已经成功的任务降级。
模板与正文共用登记请求构造器，避免正文在编译途中被模板重写。文书存储的 enable_content_revisions 默认 false，
正文消费者拒绝使用未启用的存储及不匹配的生成/复核身份。当前未接运行装配、未入队、未做真实数据库/转换器验收，
不得仅因消费者单元测试通过而启用该参数；入队和可恢复的用户状态仍需接通。

Web 文书读取沿用根成果的律师权限与 PASSED 来源门，再按当前版本状态读取独立核验包。
后继允许模板修订与正文修订两种已登记模式；正文额外要求 DOCX 与 1—3 的严格整数认领编号，
其他模式不得携带该编号。原成果链接读取当前后继，不绕过当前包、版本请求和回执指纹匹配；
允许读取不等于启用生成，也不将待律师复核状态升级为已批准。

入队接线在未部署的 0078 内完成：正文版本请求通过 BEFORE 守卫后，由 AFTER 触发器在同一事务创建
READY 任务和初始状态审计。主键重复直接使事务失败，不用 ON CONFLICT 掩盖矛盾；应用同键恢复读取原授权，
不重复插入版本请求。网页与后台均无任务 INSERT 授权。触发器以固定 search_path 的 NOLOGIN schema owner
执行，显式撤销应用直接执行权限；降权后仍受 FORCE RLS。owner 专用 INSERT 策略只允许当前操作者已登记的
同律所/案件/运行/授权请求，以及对应的 READY 初始审计，不为人类开放认领或修改任务。
这更新了前述“尚无入队接线”的源码阶段；生产消费者仍未装配，迁移未部署，没有创建实际任务。
启用前必须在真实 PostgreSQL 验证降权后的策略、触发器、授权/请求/任务/审计原子回滚与同键恢复。

后台入口现以 LAWCASE_AGENT_WORKER_DOCUMENT_CONTENT_REVISIONS_ENABLED（默认 false）装配正文消费者，
必须同时启用文书交付。复用同一来源绑定、隔离转换器、私有包存储与独立访问端口；正文/模板轮换优先级，
每轮最多消费一个任务，某一消费者异常不阻止另一个被检查。不开新进程，不发出新的模型请求。
启用前双连接只读检查实际数据库角色、强制 RLS 表、必要任务触发器、认领列及任务读取/禁止直接插入权限。
该结构预检不是迁移内容认证或 SQL/RLS 执行验收；不因预检通过而自动启用部署开关。
源码装配完成，部署配置仍未开启，用户状态读取、未知结果恢复及完整旅程仍未完成。

修改详情现通过只读查询关联授权、任务和回执投影生成状态。没有授权记录与“有授权但任务缺失/结果不一致”
分开，后者为 UNKNOWN，不允许据此重发。SUCCEEDED 必须同时有 PASSED 回执及后继包编号才显示已生成待复核；
仍须正常文书入口独立读取文件，不将状态查询当下载授权。过期预渲染认领显示等待恢复，过期渲染显示待核验。
Web 对任务表仅获状态查询必要列的 SELECT，当前活动案件人类角色 RLS 生效；不暴露认领者、次数或写权限。
页面复用修改详情读取刷新，旧 API 缺状态只显示暂不可判断，不循环轮询、不自动重新生成。
这只是安全状态读取；UNKNOWN 文件对账、生成授权操作与真实用户旅程仍待闭合。

修改详情现提供生成授权操作：填写复核说明，说明仅生成待复核稿、不批准事实或提交。客户端复用已有恢复元数据
格式，按身份/案件/运行/文书/提案/操作分区；写前持久化请求编号，已有未确认编号时只读取详情，不再 POST。
授权 POST 携当前身份恢复命名空间，服务端与真实身份比较，阻止会话切换把旧交互归给新操作者。
写成功后的详情读取错误不能当写拒收清除编号；未查到授权或旧服务不提供状态时保持待核对。
存在生成状态只证明该提案已获授权，不声明由本次请求或当前操作者作出；唯一提案授权约束仍由数据库执行。
UI 及协议源码已接线，真实浏览器和身份切换验收尚未完成；生成结果 UNKNOWN 对账仍未闭合。

终审前重新读取文书不能只看调用是否抛错：GENERATING/FAILED 等可合法返回状态页。协调器现要求真实文书 DTO、
请求成果身份匹配、CURRENT、download_ready、当前模板及正整数 PDF 页数，否则拒绝终审完成。
这只修复就绪判断；运行终审 v1 仍绑定原成果清单，后继版本不推进运行事件，必须继续补充版本/文件指纹审批绑定。

已核验文书投影增加 review_version：SHA-256 固定域 `lawyer-document-review-v1`、文书包 ID 与包回执摘要，
不包含正文/私有对象路径，不是授权票据。回执已经绑定候选、Word/PDF 指纹及版本坐标，后继包得到不同标识；
不可下载状态页没有此标识。客户端按文书种类记录最近标识，读取到变化时清除旧打开/下载记录；旧服务缺标识时
不把操作计入终审。异步下载结束还需匹配当前已观察版本。尚待把标识纳入服务端终审命令/不可变批准并核验并发，
不能把这一前端防陈旧措施当作完整审批失效机制。

不可变运行审批扩展为可选完整文书绑定集合 `(原成果候选编号, review_version)`，按编号规范排序。
非空集合必须恰好覆盖运行内所有文书候选，拒绝重复/外来编号与非 SHA-256 版本值，并使用
`lawyer-agent-final-review-v2` 域将集合纳入审批摘要。历史无集合的 v1 摘要与序列化字段保持原样，
不回写旧审批；编解码恢复元组供状态机重新验证。它只提供版本化数据合同，不自行验证当前数据库包。
Web 终审命令与数据库提交必须继续接入完整绑定和同事务当前包核验后才能启用；不得以仍兼容 v1 为由
允许新的文书终审绕过版本绑定。当前调用端仍未切换，尚不能宣称旧批准失效闭环完成。

Web 终审调用端现传递原审阅版本字典，服务端转为规范元组并逐项重读比较；新文书终审缺清单直接拒绝。
清单必须完整且无重复，版本必须与当前独立核验投影相同；无文书任务仍可用空集合。未知终审保留首次清单，
显式同键重放不从新页面状态重建批准范围。通过后版本集合进入 v2 事件摘要。
这完成请求与审批合同接线，不消除读取到事件写入之间的时间窗口。仍须在持久事件事务内锁定当前版本链、
核对包回执/请求/成功回执及候选成果身份，并与后继登记采用一致锁顺序；本轮未部署或认定并发安全。

应用持久事件写入现于幂等回执检查、运行/案件授权锁和状态机校验之后、任何事件插入之前，核对完整文书绑定。
它解析运行内原候选对应根包，按根包编号排序取得与修订请求/成功回执守卫相同的事务级链锁，全部锁定后才
重读当前 PASSED 后继及回执摘要。有未终结修订（UNKNOWN 包含在内）、缺包或版本不符则整笔终审失败；
