# ADR-0092：律师事实候选纠正保留原始提取链

状态：接受，分阶段实现；本地受管环境已部署保存/恢复接口、0081和律师修改稿页面，真实浏览器验收及后续正式事实审批仍未完成。

## 需求与边界

真实合成复核发现：异常事实候选只能重抽取或暂缓，律师不能纠正付款主体等措辞。
复用CREATE_FACT_CANDIDATE而不记录原候选身份会丢失纠正链；覆盖原抽取成果则破坏审计。

## 决策

- 新建独立纠正提案，绑定案件、批次、原候选、原成果内容摘要及来源集合。原始成果不变。
- 本案主办/复核律师可提交修改稿及理由；来源由服务器从已授权原候选复制，不接受浏览器替换页或摘录。
- 修改稿为律师输入，不冒充模型输出、原页逐字文本或已确认事实，不继承模型置信度及自动入账资格。
- 保存提案不批准事实，不改变付款、法律参数或提交包，不自动满足DEFERRED_REVIEW。
- 第一期支持FACT文字纠正；TRANSACTION金额、币种、方向等须有独立结构化修订合同，不能转换成自由文字绕过。
- 持久写入须在同一事务中检查当前案件角色、原件有效性、案件版本、同键同内容和唯一当前修订，保存审计。
- 后续批准必须单独核验当前提案和来源，复用事实候选/审批、下游失效机制；不因保存提案就自动触发模型。

## 执行顺序与验收

1. 在现有抽取模块增加纯函数提案合同，校验确切原成果与候选并保留来源和风险。
2. 新增只追加持久关联与版本/幂等命令，真实数据库权限验收；不得只有内存对象就开放UI。
3. 接入现有异常复核的原文/改稿/理由对照、保存与恢复，再接独立批准和下游失效。

技术来源绑定不证明改写语义正确；完整验收必须包含原稿保留、跨案拒绝、并发拒绝、刷新恢复、
不自动审批、律师查看修改差异及真实浏览器路径。禁止把纯函数检查称为已可纠正候选。
