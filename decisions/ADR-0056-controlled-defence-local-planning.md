# ADR-0056：被告应诉首轮的本地受控规划与单次模型预算

- 状态：已采纳
- 日期：2026-09-04
- 关联：ADR-0044、ADR-0054、ADR-0055

## 背景

被告应诉验收需要证明真实模型能够形成律师决策包，但不应把模型调用浪费在“是否读取哪一页、是否调用视觉 OCR、任务如何排序”这类代码已经能够确定的控制问题上。旧通用规划器可选择多个网络 Skill；即使每个 Skill 都有审批门，也无法把一次验收准确表述为“一笔新的模型分析调用”。

## 决策

1. 当且仅当服务器已确认目标包含 `DEFENCE_STATEMENT` 时，规划入口改由受控路由处理；浏览器、目标文本、模型输出和材料内容均不能选择该路由。
2. 首轮只从当前、已确认的一审被告代理情境中读取 `POSTURE_PROFILE`、`CASE_FACT`、已作出事实绑定回应的 `CASE_CLAIM`、`VERIFIED_LEGAL_SOURCE` 和 `APPROVED_LEGAL_RULE`。原始 PDF、图片、OCR 文本和未复核材料仍完整保存在证据链中，但不会因规划而出站。
3. 该路由以不可变的本地规划事件记录一份固定任务建议：确定性案件情境核对与一份需要律师复核的律师决策包。它不伪装为供应商请求，也不写入外发账本。若上述来源、Skill 或版本条件缺失，则失败关闭。
4. 有 `DEFENCE_STATEMENT` 的运行预算固定为最多一笔外部调用。首轮唯一允许的出站任务只能是 `lawyer_decision_package`；动态计划执行轮只生成确定性审阅文书，外部调用数为零。
5. 其他目标继续使用既有受控语义规划器。所有候选仍须经过编译器、来源绑定、独立核验、律师激活、审阅和提交门；本决策不自动批准、锁定、发送或提交任何材料。

## 后果

- 单次验收的“一个真实模型调用”有明确、可审计的技术含义，而不是依赖操作人员不去点击其他功能。
- 这条路径有意比通用 Agent 更窄；它首先验证民间借贷一审被告应诉的可交付闭环，不声称覆盖所有案由或代理情境。
- 规划本身由代码完成，并不削弱模型对证据风险、对抗理由、策略条件、补证问题和律师决定理由的真实能力测试。
