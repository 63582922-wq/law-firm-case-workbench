# ADR-0047：规划器采用固定主机、发送前多节点切换的 HTTPS 传输

- 状态：已采纳，真实运行验证中
- 日期：2026-09-04
- 关联：ADR-0031、ADR-0039、ADR-0041

## 背景

受管验收运行中，DeepSeek 规划请求曾在通用 HTTPS 客户端抛出连接异常后被统一记为
`UNKNOWN_SUBMISSION`。该客户端无法区分“尚未写出 HTTP 请求字节的 DNS/TLS 连接失败”和
“请求已经到达供应商、但返回中断”的两种事实；前者因此错误进入不可重发的未知状态。

同一运行环境还观察到：供应商域名可以返回多个已验证公网地址，而单个地址或 TLS 握手可能
临时不可用。将这种发送前单节点故障直接升级为模型结果未知，会让律师端出现不必要的人工
恢复流程，并掩盖实际 Agent 能力。

DeepSeek 官方 Chat Completions 文档只定义创建响应接口，未提供本项目可绑定原始请求的
查询或幂等恢复接口。因此，任何请求字节写出后的异常仍不能假定“未发送”。

## 决策

1. 规划器仅接受固定的 `https://api.deepseek.com/chat/completions` 主机、路径和 HTTPS 端口；
   不接受浏览器、模型或案件输入提供的 URL、代理或重定向。
2. 在任何 HTTP 请求字节写出前，解析该主机的全部全局公网地址，逐个建立 TLS 连接，校验
   SNI 证书和实际对端地址必须等于该次已解析地址；失败地址关闭后才尝试下一个地址。
3. 只有所有已校验地址都在 DNS/TCP/TLS 阶段失败时，记录为确定的
   `TRANSPORT_CONNECT_FAILED`（`FAILED`，无结果未知、无自动重发）。
4. 一旦开始写入 HTTP 请求，仍只允许一次发送。发送、响应头、响应体或结果持久化阶段的
   异常仍记录为 `UNKNOWN_SUBMISSION`，只允许既有的只读恢复流程，绝不自动重发。
5. 传输固定请求头、禁止压缩响应、限制响应尺寸，并保留现有函数调用 Schema、计划编译器、
   账本和预算控制；此决策不改变模型可见案件数据范围。

## 后果

- 常见的发送前网络抖动不会被误记为“供应商可能已经处理案情”。
- 多节点切换发生在零案情外发阶段，不能增加模型调用次数或计费次数。
- 请求写出后的真正未知状态继续安全停止；在供应商未提供可核验查询接口前，不把它伪装成
  可安全重试。
- 真实验收仍须在新的、独立的受控运行中验证；既有未知运行保留为审计记录，不被覆盖。
