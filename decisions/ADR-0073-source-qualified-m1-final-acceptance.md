# ADR-0073：M1 仅使用可读取的冻结法源快照进行一次最终合成验收

状态：`Accepted`

日期：`2026-09-04`

## 背景

V4 `managed-defence-source-bound-numeric-v4` 已在合成案卷上完成一次真实模型调用，历史响应、费用回执和失败状态均已封存。随后，文书回放在读取同一案件的法源对象时发现：最高人民检察院页面的原始 HTML 虽包含条文标记，但安全 HTML 提取只得到页面外壳，不能作为可见、可回链的文书法源正文。

ADR-0072 已将“原始字节包含标记”降级为不足条件。V4 不得被改写、替换来源、重放模型调用或产出文书。

## 决策

1. 新建独立、固定身份的 `m1-source-qualified-final-acceptance` 合成案件；它不是 V4 的续接或重试。
2. M1 只允许使用工业和信息化部天津市通信管理局公开的《中华人民共和国民法典（全文）》冻结快照：
   - URL：`https://tjca.miit.gov.cn/zwgk/zcwj/flfg/art/2020/art_20cf1a2e1b854924b5caa744c8045d1f.html`；
   - 媒体类型：`text/html`；
   - 冻结字节数：`1,164,455`；
   - SHA-256：`2efc5b6c1a6ac1e5b509f93a94d93326c81c7fe1d2e4525120cf13a417255277`；
   - 可安全提取的可见正文须同时包含《中华人民共和国民法典》及第六百七十九条、第六百八十条标记。
3. M1 发起前必须重新下载同 URL、拒绝跳转、核对精确媒体类型、字节数、哈希与可见正文。任一不符即在模型调用前停止；不得换源、降级到网页外壳或放宽匹配。
4. M1 的规则版本必须与其冻结法源快照同源绑定。由于 `legal_rule_versions` 在律所范围内以“规则 ID + 版本”唯一，M1 使用 `PRIVATE_LENDING_RESPONSE_SOURCE_SCOPE` 的专用版本 `M1-SOURCE-2026-09-04`，不得复用 V4 的 `1.0.0` 版本或改变 V4 的历史绑定。
5. `tjca.miit.gov.cn` 只作为该精确 M1 快照的法源台账允许主机加入；不得将其扩展为 `miit.gov.cn` 或 `*.miit.gov.cn` 通配。首次 M1 已在模型前停于旧允许列表，后续已完成来源登记和借款事件登记但尚未生成规则、法源包、计划、Agent 目标、Agent 运行或外发记录时，只允许一次**精确的版本 32 恢复**：逐项验证完整 11 份材料、18 条受控输入回执、来源登记回执、借款事件回执、案件版本 32 和零规则包/计划/Agent/外发，然后只复用同案已认证快照继续规则审批。恢复缺少任一条件即停止；不访问公网、不新建案件、不自动换源或模型。
6. 只有上述法源门、受控输入、运行时、文书 Worker 和代码测试全部通过后，M1 才允许一次律师决策包模型调用；没有自动重试、模型切换或同案第二次运行。
7. M1 的合成主办律师身份仅用于内部自动化验收。它不能替代真实案件中的法源捕获、人工效力核验、律师审批、签署、锁定或法院提交。

## 原因

- 完整 Agent 验收需要一份能进入来源绑定 DOCX/PDF 的真实可读法源；把动态网页外壳视为正文会制造不可审计的法律引用风险。
- 直接修改 V4 会破坏历史失败证据和单次外发边界；独立案件把“修复前失败”和“修复后最终验证”明确隔离。
- 来源、法律事件和规则版本都属于版本化台账写入。恢复到一个已承诺的来源/事件检查点，必须验证全部命令回执并保持同一案件、同一快照和同一来源版本，不能把“前一次模型没有发送”误解为可以放宽账本一致性。
- 按精确字节、哈希、正文和单次外发同时设门，避免测试在来源变化、网络问题或模型失败后演变为无休止重跑。

## 后果

- 通过 M1 只能证明受控的 88 页合成案件能从真实模型分析进入律师复核 Word/PDF 候选；不代表律师认可、真实客户案件、最终提交或商用放行。
- M1 若因来源、运行或模型门失败，将封存该次状态并停止，不创建替代同案运行；唯一例外是本 ADR 明确的模型前版本 32 检查点恢复，它不能越过规则、法源包、计划、Agent 或外发边界。
- 生产案件仍必须通过正式的授权捕获、私有对象存储、律师法源/规则审核和版本失效链；本 ADR 不把转载页面自动提升为无人审核的生产法律结论。
