# ADR-0035：付款台账提取必须在提示中给出完整 JSON 契约与示例

## 状态

已采纳。

## 背景

真实 Agent 运行中，DeepSeek 返回了合法 JSON，但自行采用 `type`、`statement`、`excerpt` 等字段，而不是本地审计链要求的候选结构。严格解析器因此正确拒绝该结果。此前提示只要求候选类型和逐字摘录，没有列出完整字段、枚举或示例。

DeepSeek 官方 JSON Output 文档明确要求：除设置 `response_format={"type":"json_object"}` 外，提示中还要包含 JSON 指令并给出期望格式示例。JSON 模式保证语法合法，不保证业务字段自动符合未说明的 schema：<https://api-docs.deepseek.com/zh-cn/guides/json_mode/>。

## 决策

1. 保留本地严格解析、逐字摘录回查、枚举检查和来源页绑定，不接受供应商自创别名。
2. 系统提示列出 FACT 与 TRANSACTION 的完整键集、枚举、日期/金额格式和逐页摘录规则。
3. 提示提供两种候选的完整 JSON 示例，并明确示例 ID 和文字不得复制，实际结果只能使用输入页 ID 与逐字原文。
4. 供应商输出仍只是私有律师复核候选；模型不得形成正式事实、正式交易或法律结论。
5. 本次修复后只允许再执行一次有界实跑，不以反复调整提示代替端到端验收。

## 后果

### 2026-09-06 页材料与台账比较边界

真实合成读卷run bd10a172…形成17条候选，其中3条使用CONTRADICTS_CASE_LEDGER，
而该适配器请求只包含pages、没有已确认台账。新提示明确禁止此标签，要求区分单方主张、
跨页矛盾、金额不明和要素缺失，保留陈述主体；这是一项提示合同修正，不是语义准确率证明。
旧成果不修改，仍留在异常复核队列；不因此新发模型请求，不将律师复核改成自动批准。
原提示保留为私有历史常量：新发送只用现行提示；reconcile仅在现行指纹不匹配时重建原提示指纹，
必须与已登记external_request_id精确一致后才能lookup，不能send。两版均不匹配就拒绝。
该兼容不修改旧请求、响应、任务或事件，也不将UNKNOWN恢复解释为可重试。
17项适配器/持久交换测试通过；尚未部署，也未声称旧模型标签已被纠正。

- JSON 模式的能力边界与本地业务 schema 不再混淆。
- 不会为了适配一次错误输出而放宽来源、金额、枚举或审核控制。
- 如果下一次有界运行仍不符合协议，应停止并把严格函数调用或供应商替换作为后续架构决策，而不是继续试提示词。
