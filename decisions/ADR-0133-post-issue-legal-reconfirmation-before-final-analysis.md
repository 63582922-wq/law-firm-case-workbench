# ADR-0133：确认争点后，先重新确认当前依据包，再进行最终办案研判

状态：`Accepted`

日期：`2026-09-11`

## 问题

首次 Agent 研判可以从已确认事实中提出来源绑定的问题候选。律师把其中问题确认成正式争点后，案件版本发生变化，旧法律规则包必须失效。此前系统正确地拒绝使用旧包生成当前答辩状，但网页只把它表现为“缺少规则包”，律师看不出这是正常的版本控制，也不知道下一步应当重新确认依据还是重新运行 Agent。

## 决策

- 保持既有失效语义：争点、事实、证据、交易或规则变化后，旧法律规则包不得继续用于当前测算、最终研判、文书或提交材料。
- 法律依据读取接口在没有当前已批准包、但存在最新失效包时，只返回该包的版本、失效时间和原因；不返回或复活旧包的哈希、段、审批或可用状态。
- 律师页面明确展示“案件信息已变化，请重新确认本案依据”，并将同一页的确认表单切换为“重新确认”。这一步仍由主办律师选择已核对的规则、关键日期和适用终点；Agent 不得替代该决定。
- 重新确认成功后，案件版本回写到工作台。随后新建的最终研判只能读取该最新版本；旧 Agent 结果仍留作历史审阅，不能被当作当前文书来源。

## 后果

办案路径变为：材料与事实确认 → 首次问题发现 → 律师确认争点 → 重新确认当前依据包 → 最终风险研判与文书候选。这样保留必要的法律责任边界，同时把原来的技术阻断变成律师看得懂的一步操作。
