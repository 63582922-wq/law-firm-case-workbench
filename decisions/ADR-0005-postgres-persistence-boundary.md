# ADR-0005：生产 PostgreSQL 仓储与合成 Alpha 保持物理隔离

状态：`Accepted`

日期：`2026-08-09`

## 背景

现有 Alpha 工作流使用 `alpha_*` 合成标识和内存仓储，便于在不接触真实资料时验证状态机。初始 PostgreSQL 迁移则采用生产 UUID、RLS、审计和 Outbox 约束。若为了“接上数据库”而把合成标识伪装成生产主键，会破坏租户隔离和未来身份体系。

## 决策

1. 定义 `MatterStore` 端口；内存仓储继续服务内部合成 Alpha，PostgreSQL 仓储服务已经过身份供应方配置的 UUID 生产边界。
2. PostgreSQL 仓储在每条读取和命令事务中以参数化方式执行 `set_config('app.firm_id', ..., true)`；RLS、锁行、乐观版本、幂等、审计和 Outbox 写入在同一事务中完成。
3. PostgreSQL 仓储明确拒绝非 UUID 的案件、律所和操作人标识，防止 Alpha 或未完成认证的调用方写入持久化数据库。
4. 数据库集成测试只在用户显式配置的专用 `_test` 数据库上运行，并要求第二个确认环境变量；默认自动化只运行不连接数据库的契约与单元检查。
5. 真实 HTTP 认证、成员关系读取、密钥管理、迁移部署和生产数据库仍未完成，不得让 API 选择 PostgreSQL 仓储。

## 后果

- 现在可以在隔离测试库中验证迁移与命令原子性，且不会将开发 API 误升级为生产服务。
- 后续身份/MFA 完成后，API 通过受认证的 UUID `Actor` 选择仓储，不需要重写领域状态机。
- 现有 Alpha 用例仍严格保持合成、内存和不可提交状态。
