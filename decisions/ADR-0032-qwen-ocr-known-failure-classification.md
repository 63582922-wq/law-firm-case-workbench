# ADR-0032：区分 Qwen OCR 明确失败与结果未知

- 状态：已接受
- 日期：2026-08-24

## 背景

视觉 OCR 的一次性外部调用先写入提交边界，再发送网络请求。原实现把所有异常都登记为 `UNKNOWN_SUBMISSION`，包括供应商已经完整返回的 HTTP 拒绝或不可用响应。这样既无法安全重试，也无法终止任务，运行会长期停在恢复状态。

## 决策

在通用 Worker 边界引入“明确外部失败”：只携带已绑定的外部请求 UUID 和受控错误码。Qwen 传输仅在收到明确 HTTP 状态，或收到完整但不符合固定响应契约的内容时产生该失败；DNS、TLS、连接、读取中断仍视为结果未知。

Qwen 恢复账本新增 `FAILED` 终态。该行不得保存 provider 请求 ID、响应正文、响应哈希或异常文本，只保存请求哈希和 `QWEN_VISUAL_OCR_*` 错误码。Worker 将它写为 `FAILED/SUBMITTED`，不自动重试。进程在 OCR 账本提交后崩溃时，恢复路径只读取该失败，不再次调用供应商。

## 后果

- 明确拒绝可终止当前任务并暴露安全诊断码，不再伪装成未知结果。
- 真正不确定的网络结果继续停在 `UNKNOWN_SUBMISSION`，保持最多一次调用保证。
- 供应商正文和潜在敏感信息不会进入 Agent 事件或失败账本。
- 任何后续重试都必须先针对明确错误完成修复，并创建新的受控运行。
