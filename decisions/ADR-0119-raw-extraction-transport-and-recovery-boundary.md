# ADR-0119：材料提取将连接失败与结果未知分开，并停止未知结果的轮询循环

状态：`Accepted`

日期：`2026-09-10`

## 问题

原始材料候选提取的第三次受控运行在 5 秒内发生 TLS 握手被对端关闭。该阶段尚未写入 HTTP
请求字节，也没有私有响应对象；旧传输把这类连接失败与已发送后断开的情形一起记为
`UNKNOWN_SUBMISSION`。随后恢复适配器又按当前提示词重建旧请求，提示词安全更新会改变请求哈希，
使本应只查一次的恢复路径重复领取同一个未知任务。

这既不代表模型内容质量失败，也不能通过再次发送同一请求解决。

## 决定

- 材料提取使用 DNS 固定、TLS 固定连接。DNS 或 TLS 连接在任何 HTTP 请求字节前失败时，记为
  `LEDGER_PROVIDER_DNS_FAILED` 或 `LEDGER_PROVIDER_CONNECT_FAILED`：零外部调用、零费用、可由律师在
  服务恢复后用新的明确任务再次发起。
- 一旦开始写入 HTTP 请求，后续发送、响应头或响应体读取失败仍为 `UNKNOWN_SUBMISSION`；系统不得
  重发。
- 未知结果的恢复仅按已持久化的 `external_request_id` 查找不可变交换记录和私有响应对象，不再根据
  当前提示词重建并比较旧请求哈希。当前页投影仍必须与原任务输入绑定，恢复不授予重新发送权限。
- 查无私有响应时，适配器抛出显式 `LEDGER_EXTRACTION_RECOVERY_UNRESOLVED`。Worker 保留原未知回执、
  停止领取和轮询该任务，交由明确的人工恢复/取消流程处理。

## 后果

网络不可用不会被伪装成一次可能收费的模型调用；真正不明的调用仍保守保留。提示词工程的安全修复
也不会使已归档响应无法恢复。历史未知运行不改写、不补发、不作为完整验收通过证据。
