# ADR-0019：证据来源页采用全案就绪摘要、版本分页与服务端锁定复核

状态：已接受并实现

## 背景

证据工作台过去一次读取全部来源页，并在浏览器内统计未审页、待批准处置与重复候选，再由浏览器拼出 Manifest 锁定输入。大案中这会放大响应体、内存和渲染开销；更严重的是，只要浏览器没有完整载入所有页面，就不能可靠判断全案是否可锁定。旧服务端虽会拒绝缺少批准决定的页面，却没有显式拒绝“已有旧批准决定、同时又存在新候选决定”的页面。

## 决定

1. 首屏先读取 `evidence-review-summary`。摘要只包含原件登记、全案页数及三类阻断计数、重复组成员定位、当前锁定 Manifest 摘要、派生件和任务状态；不传输全部页文本、页图、绝对路径、对象键或 Manifest 全部条目。
2. 来源页通过 `evidence-pages` 键集分页，每批默认 50 页、最多 100 页，按 `(原件创建时间, 原件 UUID, 页码, 来源页 UUID)` 排序。游标绑定列表类型、案件 UUID 和案件版本；每批仍重新进行数据库成员授权和律所/案件作用域检查。
3. 页面最小投影只含来源定位、当前已批准处置、当前候选处置及该页未失效红框。原始页图继续走本机文件夹授权、哈希校验和一次性 PNG 许可，不进入分页响应。
4. 全案摘要在服务端对所有页的批准决定、候选决定、已批准红框、重复组结论和成员生成 `manifest_readiness_hash`。锁定请求必须同时携带案件版本、摘要哈希派生的律师批准哈希和该就绪哈希。
5. 服务端在同一写事务内重新读取全部页和重复组，拒绝任一未批准页、任一待批准新处置、任一未裁决重复组或同源重复组的错误纳入关系，并重新计算就绪哈希。状态变化或哈希不一致即停止锁定。
6. 浏览器只根据服务端全案阻断计数决定是否显示锁定动作，不要求先下载全部来源页。网络中断时保留已载入页和当前选择，明确提示可续载，不自动重试写命令，也不回退合成数据。
7. 重复组摘要保留每个成员的原文件名和页码。若组内页面尚未全部载入，界面可以显示成员名称，但必须阻断逐页核验和重复裁决，直到组内页面均已载入并实际预览。

## 安全结果

- 浏览器无法用“只看到前 50 页”伪造全案就绪；
- 旧批准决定之上的新候选决定会同时被摘要计数和服务端锁定事务阻断；
- 锁定前发生的页处置、红框或重复组变化会造成案件版本或就绪哈希冲突；
- Manifest 的实际页序、页决定、红框和重复关系仍由服务端完整物化，客户端不提交自组装页清单。

## 已验证

- 来源页最小投影、第一页/后续页键集查询、全案计数和就绪哈希有定向后端测试；
- 案件版本变化在执行页查询前失败；
- 待批准处置与错误就绪哈希在插入 Manifest 前失败；
- 中文前端静态检查和生产构建通过，分页中断路径保留既有页面并提供续载。
