# ADR-0113：律师端只保留一条办案 Agent 主线

状态：`Accepted`

日期：`2026-09-10`

## 背景

案件材料页曾同时挂载一套历史“材料整理 Agent”，案件概览又挂载统一办案 Agent。它们使用
不同运行入口和状态表达，律师会看到两个“开始分析”的位置，却无法判断哪个会形成风险、补证
和应诉文件。这是产品链路断裂，不是需要用户学习的能力差异。

## 决策

- 律师界面只以统一办案 Agent 作为从材料到分析、文件的主线；材料页只负责接收、查看原件和
  回到案件概览，不能再发起一条平行的材料 Agent 运行。
- 已入卷材料后，页面给出单一动作“回案件概览开始办案”。统一 Agent 根据现有来源决定先读卷
  或进入研判；读卷完成后，律师先核对材料整理结果及其原页来源。只有确认后的当前案情才进入
  风险、补证和文书研判。
- 历史材料整理运行、数据与接口暂不删除，继续作为已存在案件的受限审计/迁移兼容能力，不再
  在律师日常界面作为可选工作流。待迁移与留存期限明确后，再单独移除无用户入口的旧模块。

## 后果

用户不需要理解运行类型、任务图或“哪个 Agent 应该点击”。仍保留代理情境确认、来源绑定、
外发审批和律师终审；这些是法律责任边界，不是研发说明。该决策不把材料候选自动提升为事实，
也不让读卷完成自动生成或提交文书。
