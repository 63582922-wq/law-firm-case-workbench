# ADR-0067：v2 外发不确定结果与唯一最终运行边界

- 状态：已采纳，待运行环境门槛完成
- 日期：2026-09-04
- 关联：ADR-0056、ADR-0063、ADR-0065、ADR-0066

## 背景

ADR-0066 的法源/规则复用修复已使独立 v2 合成案件完成法源包并创建受管分析任务。
任务在跨出模型边界前写入不可变 `STARTED` 外发记录；随后本机 Docker 引擎接口冻结，
运行容器未能把响应归档。恢复后的持久化状态为：该任务的 `external_submission_state`
为 `UNKNOWN`、重试模式为 `NEVER_AUTOMATIC`、运行状态为 `RECONCILIATION_REQUIRED`，且
没有已认证响应归档、没有候选成果、没有第二次外发。

这条记录既不能证明模型没有收到请求，也不能证明模型已经完成。因此它不是模型能力
失败样本，也绝不能被当作可再次发送的失败请求。主机在事故时剩余空间极低，Docker API
在二十分钟以上无响应；恢复引擎后，未删除数据库卷、对象存储或审计记录。

## 决策

1. v2 的外发标记、未知结果、运行事件和所有对象状态永久保留，不重发、不覆写、不把
   “未知”转换为“未调用”或“成功”。
2. 在新的模型调用前，受管运行环境必须同时满足：Docker API 连续可响应、核心服务健康、
   主机可用空间不少于 3 GiB、最新受控代码已进入运行镜像、聚焦回归通过，以及对精确
   允许域完成不含请求体的 DNS/TLS 连通性预检。
3. 仅在上述门槛有证据且 v2 仍保持未知不变时，允许创建一个与 v1/v2 身份完全不同的
   `managed-defence-single-call-v3`。它是一次运行环境恢复后的最终合成验收，不是对 v2
   的重试；最多一笔模型调用，不能自动创建 v4。
4. v3 必须完成律师决策包、动态计划、零模型文书、DOCX/PDF 读取和审计核验才可记为
   合成能力通过。任一模型、硬门、文书或运行时门失败，验收停止并交付失败证据，不继续
   参数调优或循环调用。

## 后果

- 外部调用的“至多一次”约束在进程崩溃和主机重启中仍成立；系统宁可停止，也不猜测或
  重发。
- 运行可用性被提升为真实 Agent 验收的前置条件，而非事后解释。缓存清理由限定为未被
  使用的构建缓存；持久卷、材料、镜像和审计数据不在该操作范围内。
- 若 v3 通过，只证明受控合成被告应诉链在稳定本地受管环境中可用；浏览器律师旅程、
  匿名真实案律师审核、生产部署治理仍保持独立门槛。
