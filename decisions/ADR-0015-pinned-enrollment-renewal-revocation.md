# ADR-0015：登记续期与远程撤销必须经过签名目录固定的 HTTPS 服务和原生 CAS

状态：已接受（固定传输、sidecar 编排、原生 Keychain CAS 与中文操作完成；生产服务未部署）

## 背景

“续期”和“撤销”都会改变律所身份状态，不能由 WebView 自填服务地址、公钥、人员或角色，也不能把“删除本机凭证”等同于律所已撤销。远程调用还可能在回执前断线；自动重试撤销会造成未知外部状态，未经重验直接覆盖 Keychain 又可能覆盖更晚的凭证。

## 决定

1. 服务 Origin、`sha256/<Base64>` 格式的 TLS SPKI 固定值和签发公钥只来自门限签名、时效有效且防回滚的生产信任目录。页面、环境变量和命令参数不能改写。
2. sidecar 使用系统 CA/主机名验证加 SPKI 固定的 HTTPS；只允许 activate、renew、revoke 三个固定 POST 路径，10 秒超时、请求/响应大小上限、严格 JSON、无重定向和无自动重试。错误不回显 URL、凭证、激活秘密或服务响应正文。
3. 续期请求只包含现有登记 UUID、设备绑定摘要、当前凭证 SHA-256 和随机 nonce。服务返回的新 envelope 必须按当前目录重新验签，且登记号、律师、律所不变、到期时间延长。
4. sidecar 通过固定 macOS Keychain 项读取当前 envelope 与安装秘密，在内存 staging vault 中执行生命周期；它不直接写 Keychain。经验证的新 envelope 和旧哈希只经父进程私有 loopback 返回 Rust，永不进入 WebView 或普通状态。
5. Rust 再核对 sidecar 回执、设备绑定、当前凭证哈希和 envelope 哈希后 CAS 写入并回读。续期不延长已经签发的当前会话；用户必须重启，重新验签后建立新会话。
6. 远程撤销需要中文界面二次点击，Rust 命令还必须显示 macOS 原生警告框；即使 WebView 脚本直接调用命令，也不能绕过原生确认。确认后 Rust 才向 sidecar 发送内部固定串。sidecar 仅接受匹配当前登记、`accepted=true` 且时间有效的服务端回执；Rust 收到后立即停止 sidecar/清除当前会话，再按旧凭证哈希删除并回读 Keychain。
7. 如果律所已接受撤销但本机删除失败，产品返回高优先级错误并保持会话停止；不得重新声称当前身份有效。
8. “只停用本机”继续是独立操作：不访问网络，只删除本机 envelope，并明确显示“远程撤销未确认”。
9. 生产信任目录未配置时，续期/撤销端点不挂载，中文按钮禁用；默认安装不发出任何网络请求。

## 已验证

- SPKI 匹配可通过，错误 pin、非 HTTPS Origin 和非白名单路径均阻断；一次操作只建立一次请求；
- 注册传输字段不含 actor、firm 或 role，续期绑定当前 envelope 哈希；
- 续期 envelope 身份变化、到期未延长或签名无效均不会进入 Keychain；
- 远程撤销只有匹配且接受的回执才进入原生删除，错误确认和未知字段被拒绝；
- Rust lifecycle 回执拒绝未知字段，Keychain 删除要求精确旧哈希；
- 默认 `NOT_CONFIGURED` 包的续期、撤销和案件路由均为 404。

## 仍未放行

- 律所真实服务域名、证书/SPKI 轮换窗口、生产根保管与签发后台；
- 激活码原生安全输入和在线交换已实现，仍待真实服务演练；
- 服务端管理员 MFA、双人复核、撤销审计查询和离职自动撤销；
- 断线后通过独立状态查询消解 `UNKNOWN_REMOTE_STATE`；当前不自动重试；
- 休眠唤醒推送、无重启续期、设备遗失和真实律所演练。
