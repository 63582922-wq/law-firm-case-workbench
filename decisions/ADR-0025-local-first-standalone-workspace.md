# ADR-0025：本机基础案卷与律所受管案件运行时分离

状态：`已接受并实现`

## 背景

单人律师安装桌面应用后，需要先能选择自己的案件资料文件夹、建立案件并核对材料范围；不能因为尚未接入律所管理员、律师登记、外部 PostgreSQL 或受管对象库而只能看到合成演示页面。同时，正式事实、法律/利息结论、证据处理和法院提交又不能因为“本机可用”而绕开既有的律所身份、案件角色、审计和逐案外发授权。

现有受管持久化实现含多组 PostgreSQL Store、加密对象库、律所身份和案件角色复核。将它部分搬到 SQLite 会产生表面可用、实则缺少正式审计与授权的伪受管案件，风险高于明确分层。

## 决策

### 1. 使用独立的 `local-standalone` 组合根

打包的 Tauri sidecar 默认选择 `local-standalone`；Python API 的默认值仍是 `synthetic-alpha`。本机模式使用独立的 `LocalStandaloneStore` 与独立的 FastAPI 路由，绝不复用或半装配 `PersistentApiDependencies` 的 PostgreSQL Store。受管模式仍只由 `postgres-internal-preview` 或明确确认的 `commercial-production` 组合根启动。

### 2. SQLite 只保存最小本机元数据

账本位于私有应用目录：目录强制 `0700`，SQLite 文件强制 `0600`。它仅保存：随机的本机 actor/workspace UUID、案件题名/阶段/版本、资料根显示名和 SHA-256 指纹、明确盘点生成的相对文件清单/哈希/类型、审计事件和幂等键。

不保存原始绝对路径、来源文件正文、文件夹授权、律师姓名、律所身份、登记凭证、模型密钥或任何受管案件事实。随机本机 actor 仅用于本机账本的自授权；它不得被展示为律所登记，也永远不能满足 `FIRM_MANAGED` 的身份或角色检查。

### 3. 原生选择与本机会话是两个不同边界

原生文件选择后的绝对路径只进入 Rust 主进程和 sidecar 内存的短时选择记录；选择记录 15 分钟到期，sidecar 重启后必然消失。文件系统根目录、完整用户主目录及符号链接目录不能作为案件根。WebView 永远只收到选择 ID、显示名、指纹和时间。

`LOCAL` 本机会话仅供 WebView 读取脱敏的本机案件和盘点结果；它不是律师登记。创建案件、重新关联资料根和开始盘点都只接受 Rust 父进程持有的私有令牌。盘点为明确触发的只读操作，不修改、移动、上传或删除原文件。

### 4. 明确声明本机模式的可用与不可用范围

本机基础案卷真实可用的能力只有：新建/列出/打开本机案件、选择/重新关联资料目录和显式只读盘点。它不开放正式事实确认、法律依据或利息结论、还款分配、文书、法院提交包、原件页处理、外部检索、OCR、DeepSeek、Qwen 或任何材料外发。即使系统 Keychain 中已有模型密钥，本机模式也在 Rust 调用前阻断模型路径。

正式法律判断、利息计算、证据处理、模型外发和提交材料只能在独立的律所受管工作区获得逐案授权后进行。本机基础案卷不是演示数据，但也不构成正式法律意见、利息计算结果或可提交法院的文件。

## 后果

正面后果是：律师可在没有管理员、数据库或网络的前提下，从“选择自己的资料文件夹”开始真实使用产品；本机数据和文件访问边界仍然可验证，且不会以虚假的律所身份解锁高风险流程。

代价是：本机模式不会立刻提供完整办案生产链。将来若要扩展离线办案能力，必须另行设计加密、备份恢复、冲突同步、正式证据版本、律师审批和迁移路径，不能把本 ADR 的最小账本默认为正式案件数据库。

## 验证要点

- 打包 sidecar 的默认就绪状态为 `LOCAL_CONFIGURED / LOCAL_STANDALONE / LOCAL`，并不读取律所登记或 PostgreSQL；
- SQLite 中不存在选中文件夹的绝对路径；目录/数据库权限分别为 `0700` / `0600`；
- 重启后案件元数据仍可打开，但旧选择 ID 与绝对路径权限不可恢复；
- 只有原生父进程令牌能调用选择、建案、重新关联和盘点路由；浏览器本机会话只能读取；
- 文件系统根目录、用户主目录、过期选择记录和模型调用均被拒绝；
- 律所受管的 PostgreSQL 运行时与模型逐案预授权门不因本机模式而放松。
