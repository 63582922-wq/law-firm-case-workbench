# ADR-0006：证据派生件只从锁定 Manifest 生成并进入本机加密对象库

状态：`Accepted`

日期：`2026-08-09`

## 背景

相关页 PDF 和红框 PDF 是可能提交法院的高风险工作产物。若 Worker 直接读取 Agent 候选、在原案卷目录写文件、用明文绝对路径登记或生成后不做渲染核验，会造成漏页、重复页、红框漂移、原件混淆、敏感路径暴露和错误版本继续流转。

## 决策

1. PDF Worker 只消费当前 `LOCKED` 的证据 Manifest；候选页、未批准坐标、未解决重复组或失效 Manifest 均不能生成派生件。
2. 相关页 PDF 仅复制已批准纳入的原始页；红框 PDF 在相同页面上只叠加已批准坐标，不增加封面、页眉、说明页或案外描述。
3. 红框坐标固定为左上角原点的归一化坐标。当前版本遇到旋转页或 CropBox 与 MediaBox 不同的页面时阻断，直到有经测试的显式坐标变换。
4. Worker 在生成前后校验原件 SHA-256 和页数，在生成后重新打开并通过 Poppler 渲染比对页数、未标注页像素一致性和红框可见性。
5. 明文派生件只存在于权限受限的临时目录，生成、渲染、加密完成后自动清理；不得在律师选择的原案卷目录写入派生件。
6. 持久副本使用本机受管的 AES-256-GCM 内容寻址对象库。密钥由桌面密钥提供方注入，不与对象一起保存；数据库只记录内容对象键、明文哈希、页数、Manifest 和验证哈希，不向普通浏览器返回对象键。
7. 两类派生件使用可恢复幂等步骤依次登记和验证。任何上游正式决定变化在同一案件事务中使旧 Manifest、派生件和提交包失效。

## 后果

- 派生 PDF 可以证明来自哪一个 Manifest、哪些来源页和哪些批准红框，且原件保持不变。
- 生成失败或中断可能留下未引用的加密内容对象，但不会留下可冒充当前提交物的数据库记录；后续由内容寻址垃圾回收清理。
- 旋转页和裁切页在第一版会进入人工处理队列，牺牲部分自动化以换取坐标准确性。
- 正式桌面运行仍需接入 OS Keychain/安全硬件、签名读取接口、备份恢复和密钥轮换；测试密钥不构成生产密钥管理。

## 被否决方案

### 直接在原案件文件夹生成“最终版”PDF

这会混淆原件与派生件、传播多个版本并扩大误删和同步冲突风险，不采用。

### 只检查 PDF 可打开，不做渲染比对

可打开不能证明页序、红框坐标和视觉内容正确，不采用。
