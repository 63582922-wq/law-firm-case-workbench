# ADR-0038：视觉 OCR 运行时策略哈希与数据库交换门必须同步

- 状态：已采纳
- 日期：2026-08-24

## 背景

视觉 OCR 从“要求供应商返回来源结构”调整为“供应商只返回不可信文字，来源谱系由服务器绑定”后，运行时策略哈希发生变化。`case_agent_visual_ocr_exchanges` 的数据库触发器仍固定校验旧哈希，导致当前、已批准任务在 `SUBMISSION_STARTED` 已提交后、真正建立供应商 exchange 前被拒绝。控制器因此只能保守记录为 `UNKNOWN`，且不能重发。

## 决策

1. 通过前向迁移 `0059` 把 exchange 触发器固定到当前运行时策略哈希。
2. 将运行时策略哈希导出为单一代码常量，Manifest 和数据库启动预检共同引用。
3. Worker 启用 Qwen OCR 时必须读取 `validate_case_agent_visual_ocr_exchange` 的函数定义并确认包含同一哈希；不一致即启动失败关闭。
4. 保留当前任务、图谱、律师审批、单一 Worker 角色、一次外部调用及 `SUBMISSION_STARTED` 的全部既有数据库约束。

## 后果

- OCR 策略以后每次发生实质变化，都必须伴随显式前向迁移。
- 部署遗漏会在 Worker 发布就绪心跳前暴露，不再制造不可恢复的未知任务。
- 已产生的未知任务不会被改写或重发；验收必须创建新的受控运行。
