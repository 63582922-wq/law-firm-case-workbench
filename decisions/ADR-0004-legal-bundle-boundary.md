# ADR-0004：时态规则卡只生成候选，案件规则包是计算的唯一法律输入

状态：`Accepted`

日期：`2026-08-09`

## 背景

利息计算可以做到数学上确定，但“适用哪一个版本、以哪个事件日期为锚点、是否存在过渡或事实条件”不是数字引擎可以自行决定的问题。将法条名称、当前利率或模型答案直接填入计算参数，会把法律判断隐藏为不可审计的技术默认值。

## 决策

1. 每张规则卡引用不可变的法源快照、精确版本、有效期间、触发事件、条件、例外和冲突组；不以规则名称代替来源快照。
2. 代码只根据已批准事件和已确认条件产生规则候选。事件日期缺失、来源不可用、条件不足或同一事项有多个候选时，案件规则包必须处于 `BLOCKED`。
3. 冲突规则只能由律师提供具名、带理由和哈希的选择；优先级字段用于呈现和审计，当前版本不静默选择规则。
4. 律师对候选包的批准必须绑定候选输入哈希。得到的 `CaseLegalBundle` 不可修改，只可在上游事实、来源或规则变化后重建新版本。
5. 计算服务只接收服务端规则包注册表中的 `APPROVED` 引用及其获批规则版本；浏览器或 Agent 不能把任意来源字符串伪装成已批准规则。
6. 当前 Alpha 的规则包与来源快照均为严格合成夹具；真实法源取得、许可、快照和律师审核继续受公开研究网关与 Phase 0/1 放行门控制。

## 后果

- “合同成立时 / 起诉时 / 付款时”等可能不同的锚点将作为可见输入进入规则评审，而不会被利息计算器猜测。
- 计算层能够验证其规则版本来自一个可回放的案件规则包。
- 后续 PostgreSQL 持久化需保持候选、审批、注册和失效语义，并将真实法源快照的许可状态纳入硬门禁。

## 被否决方案

### 由计算引擎按当前日期或最高优先级自动选法

这种做法会掩盖过渡规则和事实争议，不能审计，也会越过律师审批，不采用。

### 将法条全文或搜索摘要直接写入模型提示词

其版本、许可、有效期和精确条款无法稳定回放，不采用。
