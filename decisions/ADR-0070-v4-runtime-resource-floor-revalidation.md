# ADR-0070：V4 单次验收的运行空间下限复核

- 状态：已接受
- 日期：2026-09-04
- 关联：ADR-0067、ADR-0068、ADR-0069

## 背景

ADR-0067 的 3 GiB 宿主空间门槛是在 Docker 因宿主磁盘耗尽而冻结后设定的保守恢复条件。
V3 已在该门槛下完成一次真实模型调用；V4 启动前，运行环境剩余约 2.4 GiB，核心服务健康，且不再需要完整镜像构建、依赖下载或大对象导入。

可审计的实际体积也已固定：V3 封存的模型响应为 12,192 bytes，当前解释器生成的律师决策包候选为 32,142 bytes，V4 复用的官方法源为 488,833 bytes。V4 运行中的文书渲染使用已启动的隔离渲染服务，不引入新的镜像或模型下载。为达到原先 3 GiB 而删除正在使用的其他项目构建目录或用户资料，反而会扩大本项目的操作范围和风险。

## 决策

1. 仅对 ADR-0069 定义的这个固定 V4 合成验收，将宿主 Data 分区的硬下限设为 **2 GiB**；该下限不适用于客户案件、生产部署、v2 或 v3 的历史处理。
2. 在 2 GiB 至 3 GiB 区间运行 V4 时，必须同时确认：当前 API、Worker、对象存储、数据库和文书渲染服务健康；Docker 引擎可响应；最新薄层镜像已部署；Qwen DNS/TLS 无请求体预检通过；同律所冻结法源对象已通过零写入读取验证；聚焦回归和 V3 只读回放均通过。
3. 运行期间禁止完整镜像构建、镜像拉取、数据卷迁移、客户端材料导入、额外模型调用和任何自动重试。V4 仍只允许一笔 Qwen 请求；低于 2 GiB 或任一服务门失败即停止。
4. 该调整不把磁盘余量当作能力通过证据，也不降低来源、权限、审批、候选文书或审计门槛。V4 失败时仍不创建 V5。

## 后果

- 运行门槛从事故后的经验性整数值，改为与当前固定工作负载和不扩容运行方式相匹配的受控下限。
- 仍保留超过实际增量数百倍的空间缓冲，同时避免为了满足一个非功能性整数而清理其他项目的活跃构建资产。
- 一旦进入真实客户数据、全量构建、镜像更新或生产部署，必须重新评估空间预算，不能沿用本 ADR 的局部豁免。
