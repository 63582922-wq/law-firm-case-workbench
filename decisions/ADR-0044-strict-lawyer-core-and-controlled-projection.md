# ADR-0044：律师分析核心迁移到严格 JSON Schema 与受控投影

- 状态：已采纳，离线实现完成，独立真实验收待运行
- 日期：2026-08-28
- 关联：ADR-0041、ADR-0042、ADR-0043

## 背景

2026-08-28 的 `fresh-v3-run-01` 是一次新的独立合成案件调用。`qwen3-vl-plus`
正常返回，供应商回执确认输入 12,648 tokens、输出 4,299 tokens、费用 0.055638 元，
无重试。模型完成八个争点、四组对抗分析、两套策略、六个补证问题和三个律师决定分析，
识别并忽略材料内提示注入，未声称批准、锁定或提交。

该次运行仍被硬控制器拦截并永久保持失败。直接阻断原因是模型在自由文本中写入正式
利率百分比；继续按律师视角复核还发现：时效追问的催收主体倒置，一套策略把排除周转款
的情景与“增加该款”收益并列，并写入未经律师确认的时效结论。部分对抗分析没有绑定
任何已登记对方主张。结构完整、正常结束和来源白名单因此都不能单独证明律师可用。

阿里云百炼官方文档显示，`qwen3.7-plus` 支持图片、文本和视频输入，也支持严格
JSON Schema 结构化输出；华北二北京地域在输入不超过 256k 时公开原价为输入每百万
tokens 2 元、输出每百万 tokens 8 元，最大输出长度为 131,072 tokens。官方结构化输出
文档同时要求开启结构化输出时不要设置 `max_tokens`，并建议使用 `strict: true` 与
`additionalProperties: false`。

官方依据：

- https://help.aliyun.com/zh/model-studio/qwen-structured-output
- https://help.aliyun.com/zh/model-studio/qwen3-7-plus

## 决策

1. `fresh-v3-run-01` 保持 `BLOCKED_SINGLE_CALL_NO_RETRY`。原始 JSON、供应商响应、
   用量、失败原因和哈希不可覆盖，也不得投影成“直接通过”。
2. 律师分析核心升级为 `golden-lawyer-analysis-core-v4`。律师包调用从
   `qwen3-vl-plus` 迁移到 `qwen3.7-plus`，使用 `response_format.type=json_schema`、
   `strict=true`，并在每层对象设置 `additionalProperties=false`。旧 v3 合同不再进入
   正式编译器。
3. 模型职责缩为真正需要语义判断的字段：证据有利点、不利点和缺口；受控对方路径下的
   奏效原因、反驳路径和剩余风险；策略成立条件、执行风险和取舍观察；三个登记决定的倾向
   与理由。模型仍必须真实分析材料，不能退化为固定文案。
4. 代码负责争点标题、举证责任、下一动作、对方主张主体和“已提出/仅预判”状态、六个
   角色安全的当事人问题、策略目标、情景与受控收益、程序期限、正式利率、金额、章节和
   决定选项。模型不得新增或改写这些正式字段。
5. 对抗分析只能使用与覆盖标签匹配的 `position_id`。未在材料中出现但律师应预判的路径，
   必须登记为 `FORESEEABLE_NOT_ASSERTED`，编译结果明确写明“材料未显示其已提出”。
6. 模型自由文本禁止阿拉伯数字、全角数字、货币符号、百分号和受控法律结论。证据、法源、
   决定、主张和策略只能通过专用 ID 字段引用。金额、利率、日期和正式规则由代码回执注入。
7. 证据引用数组按真实案件密度放宽到十二项；证据缺口允许为空。代码仍按争点证据政策
   要求必要来源和冲突发现，不因数组放宽降低来源门。
8. 严格结构化调用不设置 `max_tokens`。预检按 `qwen3.7-plus` 北京公开原价和官方最大
   输出长度计算最坏费用，单次总预算固定为 1.20 元；实际费用仍以供应商 usage 回执记录。
   每次验收只允许一次调用，不自动重试或切换模型。
9. 新合同先通过离线 Schema、语义边界、来源/主体、确定性编译和 DOCX/PDF 测试，之后才
   允许一次新的独立真实验收。通过状态必须同时包含完整严格响应、零非法引用、语义硬门、
   确定性计算一致和文书渲染通过。

## 后果

- 严格 Schema 解决字段、类型、数量和额外字段漂移，但不替代应用层语义校验；主体、数字、
  情景一致性和律师权限仍由硬控制器负责。
- 模型输出自由度降低，但律师看到的结论更具体、更可追溯，且不会把模型偶然写出的金额、
  利率、角色或时效结论带入工作成果。
- 六个当事人追问和两套策略中的正式部分由代码登记，不等于固定回复；模型的证据分析、
  对抗分析、策略条件和决定理由仍随案件材料变化。
- 当前状态是 `IMPLEMENTED_OFFLINE_NOT_LIVE_ACCEPTED`，不是新鲜模型端到端通过，也不是
  执业律师认可或商用放行。
