# ADR-0054：被告应诉候选接入受管 Agent 交付链

- 状态：已采纳
- 日期：2026-09-04
- 关联：ADR-0040、ADR-0041、ADR-0044、ADR-0046、ADR-0049、ADR-0053

## 背景

现有受管 Agent 已能在真实模型调用后形成并独立核验“律师案件决策包”，并能将其编译为案件审阅意见；收付款核对表也可由已确认交易确定性生成。项目中另有一套全合成的答辩与证据目录金标脚本，但它是独立工程验收，不是当前受管 Agent、动态办案计划、来源绑定、Worker 与律师阅读链的一部分。

因此，不能把金标脚本产生的 PDF 视为产品已经具备“被告应诉交付”能力，也不能把案件审阅意见误称为答辩状。第一条被告应诉交付链必须以当前案件情境和受控来源为前提，而非依据“被告”标签自动套用模板。

## 决策

1. 新增受管成果类型 `DEFENCE_STATEMENT`，只表示“民事答辩状候选”。它由当前活动办案计划中的一个内部工作成果事项驱动，而不是法院提交件、最终法律意见或自动提交动作。
2. 该事项只有在下列来源同时处于当前、可复读状态时才可执行：
   - 当前代理情境明确为被告、委托有效，且程序阶段允许形成一审应诉候选；
   - 至少一项已确认诉请范围，并且每项拟写入的处理口径已有律师批准的诉请回应记录；
   - 至少一项已确认事实；
   - 至少一项已核验、许可有效的官方法源；
   - 至少一项已批准法律规则；
   - 与同一受管运行、同一案件快照绑定且已独立验证的律师决策包候选。
3. 计划晋升时，服务器从同一权威快照自动补入上述已确认来源；模型既不能选择来源集合，也不能因为文本中出现“答辩状”而新增成果类型。缺少任一类来源时，计划事项必须显示为待补信息，不得进入文书 Worker。
4. 文书由确定性编译器生成。它逐项投影已确认诉请、律师已批准的回应口径、已确认事实、已核验法源与规则的可见标识，以及已验证决策包中的风险提示；不让模型生成承认、否认、金额、法条、期限、案号、法院、落款或签署日期。未知值必须写为“待律师核对”。
5. 生成结果固定为 `NEEDS_LAWYER_REVIEW`、`formal_fact=false`、`formal_legal_conclusion=false`、`court_ready=false`。生成、下载、排版更新和内部候选批准遵循 ADR-0053，不推进案件输入版本；事实、诉请、法源、规则、程序或决策包变化仍会使下游候选失效。
6. 本 ADR 不把证据目录和利息核算表一并放宽。证据目录仍要求逐项已批准纳入的证据页；利息核算表仍要求经独立复算且已批准的计算结果和规则。只有这些各自条件满足后，才可作为同一应诉候选包中的独立成果。
7. 任何候选不得自动批准、锁定、发送给当事人或提交法院。真实调用验收前必须有单次预算上限、不可重复提交和完整供应商回执；合成验收中的“批准”只能标记为测试夹具，绝不能伪装为执业律师批准。

## 后果

- “真实 Agent 决策包 → 被告应诉候选”的链路有了可验证、可追溯的最小商用边界，而不是继续堆叠独立脚本或聊天输出。
- 该链可以先交付一份可审阅的答辩候选；是否形成证据目录、计算表或最终提交包仍由各自的来源与律师终审门控制。
- 需要扩展规划快照、计划晋升、文书来源绑定、确定性编译器、Worker 调度、API 类型、前端成果标签和针对错误代理地位/缺失来源的回归测试。
