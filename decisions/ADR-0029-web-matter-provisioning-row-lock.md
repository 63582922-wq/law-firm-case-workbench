# ADR-0029：Web 新建案件的受管 Agent 身份行锁

状态：已接受

## 背景

浏览器创建案件前，服务端必须重新核验并锁定该律所固定的执行 Worker 与独立 verifier，防止其在身份核验与 `SYSTEM_WORKER` 角色绑定之间被停用或改作人工账号。该锁使用 `SELECT ... FOR UPDATE`，PostgreSQL 要求目标表至少有一个 `UPDATE` 列权限；仅有 `SELECT` 时，服务虽可启动，首次创建案件会失败。

## 决策

`0054` 只向 `lawcase_web_application` 授予 `users.user_id` 的 `UPDATE` 列权限。它仅支撑行锁，不允许应用更新其他用户列；`FORCE ROW LEVEL SECURITY` 保持律所隔离。受管环境的后置加固在撤销广泛用户写权限后恢复这一项精确授权。

Web 运行时启动前对每个已配置律所执行与 `CREATE_MATTER` 相同的身份核验和行锁。权限、身份状态或专用性不满足时，API 不挂载路由，而不是让律师在界面中首次发现错误。

## 后果

- 新建案件仍只能由已验证主办律师发起，且 Agent 身份由服务端配置决定；浏览器不能提交或替换这两个身份。
- 这不是用户资料写权限，也不允许应用更新 `status`、姓名、外部主体或律所归属。
- 该授权只适用于本机 Alpha 和后续同构受管部署；仍不构成生产身份、权限或上线验收。
