# ADR-0066：律所级法源/规则复用与 v2 模型前恢复边界

- 状态：已采纳，待受管 v2 合成验收验证
- 日期：2026-09-04
- 关联：ADR-0044、ADR-0055、ADR-0056、ADR-0063、ADR-0064、ADR-0065

## 背景

`official_legal_source_snapshots` 以 `(firm_id, source_id, content_sha256)` 唯一，
`legal_rule_versions` 以 `(firm_id, rule_id, rule_version)` 唯一。因此二者在模型中是
律所级、版本化的治理对象，而不是可在每个案件重复插入的行。官方法源的私有对象则仍
按律所、案件和内容哈希隔离；账本中仅保存可由受信服务端扩展的内容寻址定位符。

ADR-0065 创建的独立 `managed-defence-single-call-v2` 合成案件已完成 11 个原件、被告
一审情境、5 项确认事实、诉请与回应，案件版本停在法源登记前的固定版本。数据库只读
核验显示：该案件没有 Agent Run、没有案件法源事件、没有案件法源包；模型请求没有发出。
它在尝试插入与 v1 相同的已认证官方来源内容时触发数据库唯一约束。若继续按“每案新建
法源/规则”理解执行，下一步规则版本也会遇到同一律所级唯一性冲突。

## 决策

1. 保持官方法源快照和已批准规则版本的律所级唯一性；不得为绕过唯一约束伪造不同的
   `source_id`、`rule_id` 或版本号。
2. 新案件在复用官方法源前，仍须先在本案私有存储中重新认证精确原文对象、媒体类型、
   哈希和对象元数据。只有已有快照同时为 `VERIFIED`、`ACTIVE`，并且发布者、权威层级、
   官方 URL、条文定位、媒体类型、内容定位和许可依据均完全一致时，才能复用。
3. 复用不是静默跳过：系统为当前案件写入新的命令回执和审计事件，记录本案的对象认证
   哈希及许可复核哈希；既有官方快照及其历史认证信息保持不可变。
4. 规则版本只能在状态为 `APPROVED` 且争点、来源快照、参数来源、适用区间、触发事件、
   公式、确定性费率、事实要求、转换规则、冲突集和优先级完全一致时复用。当前案件另写
   审计回执，记录其规则绑定审批哈希；任何差异都失败关闭，不覆盖、修改或暗中替换旧规则。
5. v2 只允许从已经完整接收 11 个原件、完整验证受控输入命令前缀、且 `case_agent_runs=0`
   的模型前检查点恢复。它不得触碰 v1 已失败运行，不得创建自动 v3，也不得在已有外发后
   恢复。

## 后果

- 同一律所的稳定法律来源与规则可被多个案件一致引用，同时每个案件仍保有自身私有法源
  对象的完整性证明和不可变审计轨迹。
- 唯一约束从运行时的原始数据库异常转为明确的受控复用或受控阻断；不会因测试编号变化
  改写法律来源的身份。
- 本次恢复仅重放模型前、无外发的确定性法源治理步骤。它不是模型重试，v2 仍最多允许
  一笔独立的模型调用。
- 通用多案件产品化前，仍需评估是否增加显式的“案件—法源对象绑定”投影，以便在非受管
  合成路径中更直观地呈现每案对象认证回执；当前命令账本、法源包和私有对象元数据已提供
  受控验收所需的绑定证据。
