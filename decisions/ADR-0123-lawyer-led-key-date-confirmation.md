# ADR-0123：网页以律师选择材料页的方式确认关键日期

状态：`Accepted`

日期：`2026-09-11`

## 问题

“依据与测算”页面此前只能显示已登记的法律事件。律师虽然能看到“需要确认合同、付款、起诉或受理日期”，却没有在同一条办案路径里完成该动作的入口；这会让用户误以为系统已经具备金额核对能力，实际却被隐藏的前置条件阻断。

## 决策

- 网页提供一个受限的“确认关键日期”动作：律师选择事件类型、填写日期，并从本案已入卷的材料页中选择至少一页作为依据。浏览器只提交已经显示的材料页标识，不提交文件路径、哈希、对象地址、规则参数或审批哈希。
- 服务端为该确认生成审批指纹，并复用既有 `approve_legal_event` 持久化命令。该命令仍要求主办律师角色、同案材料页和当前案件版本；任何条件不满足都不写入法律事件。
- 第一段仅处理事实性的日期锚点，不自动选择法律规则、不生成利率、不建立规则包，也不把材料时间戳当作法律日期。规则、期间和金额计算继续走独立的律师核对门。
- 页面以“合同或借据日期、出借日期、付款日期、起诉日期、法院受理日期”等中文选项表达事件，不呈现枚举值、审批哈希或内部编号。

## 后果

- 用户从“材料 → 确认日期 → 核对依据与规则 → 金额”能看见明确连续路径。
- 系统仍不能因一页材料或日期输入自行推定当事人立场、适用法律、利率或计算区间。
- 后续受控规则卡和规则包入口必须以本 ADR 产生的已确认事件为前置条件，不能绕过它。
