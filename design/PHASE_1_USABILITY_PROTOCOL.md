# Phase 1 律师可用性测试协议

状态：`待执行；在三种视觉方向和可点击原型完成前不得改写`

## 1. 目的与边界

验证界面是否会误导律师处理证据、付款性质、法律批准、计算与提交，而不是验证模型、后端权限或法律正确性。测试只使用同一套合成、脱敏案件；运行时权限、事务、计算和导出安全留给后续技术验收。

## 2. 参与者与条件

- 5 名目标律师：至少 3 名承办律师，其余为协办律师或复核人；
- 不得由产品团队成员或已参与原型设计者替代；
- 每人独立完成，主持人不提供任务路径、术语解释或操作提示；
- 使用 1440px 桌面环境和相同浏览器版本；
- 开始前说明：原型数据均为合成，测试记录操作与用时，不评价个人能力。

## 3. 统一任务与时间

每人总时限 45 分钟，任务按 `DESIGN_BRIEF.md` 的 1—9 固定顺序执行。任务 4—9 分别为 HR-1 至 HR-6，必须使用带角色、权限、阻断、失效和审计模拟的原型。

| 任务类别 | 记录字段 |
|---|---|
| 1—3：期限、下一决定、来源回跳 | 是否找到正确对象、耗时、错误路径、是否把候选误认为确认 |
| HR-1：重复页 | 是否区分精确重复与相似页，是否保留原件与理由 |
| HR-2：付款性质 | 是否从证据确认并识别计算、文书、提交包失效 |
| HR-3：法律规则审批 | 律师能否核对来源/日期；助理模拟角色是否被拒绝 |
| HR-4：递减本金 | 是否下钻到期间、公式和付款证据，是否误称内部测算为正式结果 |
| HR-5：文书矛盾 | 是否生成新版本、使旧批准失效并重新批准文本哈希 |
| HR-6：锁定提交版 | 是否识别阻断、再认证、唯一 current、上游变化后的 `STALE` 禁导出 |

## 4. 通过、失败与重测

单人通过要求：6 项高风险任务全部正确、9 项任务至少完成 8 项、无越权、误批、覆盖原件、使用失效结果或误导出。任一高风险一票失败即该参与者不通过。

第一轮至少 4/5 通过才可进入下一阶段。少于 4 人通过时，团队必须记录根因并修订信息架构或交互；重测需至少 3 名未参加首测的目标律师，且全部通过。重测失败时缩小流程或重做交互决策，不以增加引导文案替代根因修复。

## 5. 观察记录与结果

每位参与者使用匿名编号，记录：

```text
participant_id / role / prototype_version / task_id
started_at / ended_at / final_state / pass_fail
click_path / error_type / unauthorized_attempt
participant_quote_summary / moderator_intervention
recording_consent / notes_redaction_status
```

报告按任务公布完成率、耗时中位数、失败类型、误解点和信任问题；不记录可识别客户资料或把录屏上传到未授权服务。原型通过只证明交互可理解，不能证明真实权限、审计或计算已经实现。
