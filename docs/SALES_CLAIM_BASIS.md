# 买卖合同（货款）口径：律师选口径，引擎算数

状态：`v1 · 已装配，合成木业买卖合同纠纷真实案卷已跑通`

## 1. 为什么单独一套

民间借贷的口径是「LPR 四倍上限 + 先息后本冲抵」，不能套到买卖合同的货款上。
买卖合同通常是「货款本金 + 逾期付款损失」，而损失按什么标准算，是**律师的选择**，
不是系统替他决定。因此本机模式做成：

- **律师选口径**（四个选项之一）+ 填利率与日期；
- **引擎算数**：逐段单利、按实际天数，算法写进报告口径说明；
- **模型不参与任何计算**，也看不到"该按哪个口径"的判断。

## 2. 四种口径

| 口径 | 含义 | 需要律师填 |
|---|---|---|
| `按一年期 LPR` | 以逾期起算时一年期 LPR 计算 | 一年期 LPR（年化 %） |
| `按一年期 LPR 的 1.5 倍` | 一年期 LPR × 1.5 | 一年期 LPR（年化 %） |
| `按约定年化违约金率` | 按合同/对账单约定的年化比率 | 约定年化比率（%） |
| `不主张逾期损失` | 只算货款本金 | — |

利率由律师填写（引擎**不联网取数**，也不猜测某日 LPR 是多少）。

## 3. 计算规则（可逐项复核）

1. **本金**：律师确认的应付货款 − 律师确认性质为「还本」的付款；
2. **逐段计息**：还款会减少本金，因此在每个还款日切段，段内按实际天数单利；
3. **日利率 = 年利率 ÷ 365**（单利、不含复利）；
4. **「付息」类付款**冲减已计算的逾期损失，冲减不为负；
5. **「争议」「排除」的付款不进入任何计算**，只在口径说明里计数；
6. 缺参数或参数不合法 → 明确报错或不给数字，绝不静默兜底。

报告第七节同时保留：主张货款、确认货款、已确认还本合计、未付货款本金、
逾期损失毛额/净额、本金与损失合计、起算日、截止日、损失口径。

## 4. 与借贷口径的分流

`compute_engine_numbers` 先看配置里有没有货款口径块，**有就按货款算**，
没有才走借贷口径。货款案由**不需要借贷的 `debts` 参数**（这也是一个真实 bug：
早期版本会先要求借贷参数，导致货款案子根本算不出数字）。

## 5. 界面

「决策包」页面新增**案由口径**：勾选「按买卖合同货款口径计算」后填写
主张货款 / 律师确认应付货款 / 逾期起算日 / 暂计截止日 / 口径 / LPR（或约定比率）。
校验按案由分流：货款案由不再要求填借贷字段；部分填写不会被静默丢弃。

## 6. 实测（合成木业，真实案卷）

- 参数取自**原告材料里主张的数字**：货款 10,000 元、逾期起算 2025-10-25、
  暂计至 2026-06-22、口径选原告自己主张的「按一年期 LPR」、LPR 3%；
- 引擎输出：未付货款本金 **10,000.00**；逾期付款损失 **197.26**
  （10,000 × 3% ÷ 365 × 240 天，单利）、本金与损失合计 **10,197.26**；
- 分析 `COMPLETED` / `MARK_FOR_REVIEW`，1 次调用 ¥0.0500；报告第七节与页面一致；
- 导出：决策包 Markdown 9,020 B、Word 41,308 B。

> ⚠️ 口径与利率是**律师的选择**：上面只是为了验证而选了原告主张的口径。
> 改成「LPR 的 1.5 倍」或律师自己的主张，重算即可，数字与口径说明会同步更新。

## 7. 当前边界

- 只覆盖「货款 + 逾期付款损失」；质量异议导致的减价、违约金与定金的并用、
  分批交货等情形尚未建模；
- 不支持复利、不支持分段不同利率（如需分段，请分成多个案件参数分别计算）；
- 不含诉讼费、保全费的分担计算；不含利息的税务处理。
