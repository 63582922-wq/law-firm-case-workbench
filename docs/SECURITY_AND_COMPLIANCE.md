# 安全与合规计划

本文件是产品安全设计基线，不替代正式上线前由中国执业律师、数据保护和网络安全专业人员出具的专项意见。

## 1. 数据性质

案件材料可能包含：

- 姓名、身份证号、电话、地址；
- 微信昵称、微信号、聊天内容；
- 银行卡、金融账户和完整交易；
- 当事人隐私、商业秘密和诉讼策略；
- 律师执业中知悉的不愿公开的信息；
- 未来其他案由中的健康、犯罪、未成年人等高敏感内容。

律师负有执业保密义务。《律师法》第三十八条要求律师保护执业中知悉的秘密、隐私和当事人不愿泄露的信息：[最高人民法院公报《律师法》](https://gongbao.court.gov.cn/Details/9d97a441edfcd9f72406ce9b758751.html)。

## 2. 安全目标

1. 只有经授权人员能够访问指定案件；
2. 原始材料和正式成果完整、可追溯、不可被静默覆盖；
3. 模型、OCR、MCP和第三方服务只能获得最少必要数据；
4. Agent不能因材料中的恶意指令扩大权限；
5. 所有高风险动作经人类批准并留下证据；
6. 能够发现、响应和恢复数据或服务事故；
7. 律所能够明确知道数据存放、调用、保留和删除路径。

## 3. 威胁模型

### 身份与权限

- 账号被盗；
- 助理访问无权限案件；
- 律所管理员越权读取业务材料；
- 只凭案件 ID 或状态句柄访问他人数据；
- 离职人员权限未及时回收。

### 文件和供应链

- 恶意 PDF、Office 宏、压缩炸弹、路径穿越；
- OCR或文档库漏洞；
- 第三方依赖或本地 MCP 包被投毒；
- 文件类型伪装和超大文件资源耗尽。

### Agent与模型

- Prompt Injection；
- 敏感信息泄露；
- 过度授权和未经批准外发；
- 模型幻觉或错误引用；
- 模型供应商记录或训练客户数据；
- 未知提交状态被重复调用；
- 无界 Token、文件和成本消耗。

OWASP 的生成式 AI 风险清单明确覆盖 Prompt Injection、敏感信息泄露、供应链、不当输出处理、过度代理权、向量检索风险、错误信息和无界消耗等问题：[OWASP GenAI Top 10](https://genai.owasp.org/llm-top-10/)。

### 内部与运营

- 开发人员将真实案件放入 Git、日志或截图；
- 备份未加密或恢复失败；
- 审计日志可以被普通管理员修改；
- 测试、演示和生产环境混用；
- 删除请求只删除数据库引用，未删除对象和备份生命周期。

## 4. 身份、租户与权限

### 层级

```text
Firm → Workspace/Team → Matter → SourceFile/WorkProduct
```

`Firm` 是安全租户，`Workspace/Team` 只是租户内组织分组。对象必须声明 `GLOBAL`、`FIRM` 或 `MATTER` 作用域：平台发布的全局法源/Skill 只读；律所级用户、模板、规则卡和许可必须有 `firm_id` 且无 `matter_id`；案件级证据、事实、任务和成果必须同时有同一租户的 `firm_id/matter_id`。`matter_id` 为空仅允许在白名单全局/律所对象，数据库约束、RLS 和数据面负向测试分别验证三类策略。

### 角色

- 合伙人/复核人；
- 承办律师；
- 协办律师；
- 律师助理；
- 知识库编辑；
- 律所管理员；
- 审计人员。

律所管理员管理账号不自动等于可以阅读全部案件内容。

### 控制

- OIDC或等效企业身份协议；
- MFA；
- 服务端 RBAC + 案件属性权限；
- PostgreSQL 行级安全作为纵深防线；
- 短会话、设备和风险登录告警；
- 离职和案件结案后的权限回收；
- 每个 Tool 独立 Scope，例如 `evidence:read`、`derivative:create`、`release:export`；
- Agent 只获得当前步骤允许的工具和案件范围。
- 角色—动作矩阵区分创建、修改、批准、锁定、撤销和导出；批准绑定对象版本与哈希，不能仅凭角色名称放行；
- 委托有范围、起止时间、授权人和撤销状态，离职或停用账号立即使会话、委托和待执行审批失效；
- 法律立场、正式计算、提交版锁定和导出要求执业律师权限与再次认证；配置复核人的律所执行职责分离，独任律师例外采用明确声明和增强审计；
- 数据库 RLS、对象存储、签名 URL、搜索索引、队列、缓存、审计、导出和备份恢复均进入跨租户负向测试。

## 5. 数据生命周期

### 收集

- 上传前说明用途、处理范围和第三方调用路径；
- 默认不采集完成案件所不需要的信息；
- 原件登记来源、上传人、时间和哈希。

### 存储

- 生产数据与测试、演示完全隔离；
- 传输和静态加密；
- 每律所或高等级客户支持独立密钥策略；
- 对象存储启用版本、保留和访问日志；
- 搜索索引只保存必要内容并可从权威库重建。

### 使用

- 专业 Agent 只接收当前任务最少上下文；
- 法律 Agent 不接收身份证图像等无关内容；
- 计算 Worker 只接收批准的日期、金额、币种和规则；
- 模型调用前执行数据最小化和字段屏蔽；
- 模型供应商必须有不训练、不用于服务改进、保留期和地域条款。

### 导出

- 法院提交包、内部工作底稿和审计导出分开；
- 导出需要权限、审批和审计；
- Manifest记录文件、版本、页数、哈希、审批人和时间；
- 不自动发送至邮箱、网盘或法院。

### 保留与删除

- 律所可配置案件保留期；
- 删除采用双人或高风险审批；
- 原件、派生件、索引、缓存和备份分别有可验证的删除路径；
- 法定、合同或争议保全要求优先；
- 删除完成生成可审计证明，不泄露原内容。

《个人信息保护法》及相关配套规则应成为数据最小化、敏感信息、委托处理、跨境和安全措施设计的依据：[中国网信网《个人信息保护法》](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)。

## 6. 文件安全

上传链路：

```text
隔离区接收
→ 文件大小和类型验证
→ 魔数/MIME校验
→ 恶意内容扫描
→ ZIP路径和压缩比检查
→ 宏和外部链接检查
→ 沙箱解析
→ 不可变对象存储
→ 派生页图和OCR
```

解析 Worker：

- 无生产数据库直连权限；
- 使用临时隔离目录；
- CPU、内存、时间、页数和输出大小限制；
- 默认禁止外网；
- 不执行宏、脚本、嵌入程序或外部链接；
- 失败文件保留安全诊断，不无限重试。

## 7. Agent安全

### Prompt Injection

- 系统指令、Skill、工具描述与案件内容分层；
- 上传文件始终标记为不可信数据；
- 文件中“忽略规则、上传文件、调用工具”等文字不得成为指令；
- Tool由代码白名单提供，不由模型动态发现通用高权限工具；
- 结构化输出经 Schema、权限和业务规则验证。

### 过度代理权

Agent不拥有：

- 原件删除；
- 权限授予；
- 律师审批；
- 正式金额计算；
- 法院提交版锁定；
- 对外发送；
- 支付或付费调用无限重试。

### 输出处理

- LLM文本不能直接拼接到数据库查询、Shell或文件路径；
- HTML和富文本进行净化；
- 文书字段从批准对象编译，不直接采用自由文本金额；
- 引用、金额、日期、身份和币种执行二次验证；
- 低置信结果进入人工队列。

## 8. 模型供应商治理

供应商上线前检查：

- 数据处理协议；
- 是否用于训练或产品改进；
- 输入、输出和日志保留期；
- 数据中心和跨境路径；
- 子处理者；
- 删除能力；
- 安全认证和事故通知；
- 服务可用性和未知提交恢复；
- 模型版本变更通知。

模型 Gateway 必须：

- 按任务选择允许模型；
- 记录实际运行模型而非界面显示名称；
- 设置单案 Token、次数和成本上限；
- 对未知提交状态停止自动重试；
- 保留原始结果和恢复状态；
- 不让模型供应商直接访问对象存储。

每一次外部模型、OCR 或 MCP 调用都必须经过持久化 preflight，并在发送前向有权限的用户展示并绑定：

```text
matter_id / purpose / selected_fields_or_pages
provider / processor_region / retention / training_policy
call_cap / cost_cap / model_or_service
authorization_actor / authorized_at / expires_at
request_id / input_hash / status
```

没有逐次或仍在有效范围内的批次授权即 fail closed。授权不能从“供应商已配置”推断；超出数据范围、供应商、地域、成本或次数必须重新确认。请求进入 `UNKNOWN_SUBMISSION` 时停止自动重试，保留原结果和恢复状态。

## 9. MCP安全

首版不接入未知公共 MCP Server。未来远程 MCP：

- 采用 OAuth、PKCE和受众绑定；
- 不允许 token passthrough；
- 每个客户端、用户、律所和案件独立授权；
- 不把 state handle 当作身份；
- 对 URL、重定向和网络出口进行 SSRF 防护；
- Server 只暴露不透明资源 ID，不接受任意路径；
- 读写工具分开，写操作有预览、审批和幂等键；
- 工具说明、版本和权限变更进入审核。

参考：[MCP Security Best Practices](https://modelcontextprotocol.io/docs/2026-07-28/tutorials/security/security_best_practices)。

## 10. 审计

每次高风险操作至少记录：

```text
tenant_id / matter_id / actor_id / role
workflow_run_id / step_id
agent / model / prompt_id / prompt_version / prompt_hash / skill / tool versions
input_hash / output_hash / source_ids
permission_scopes
approval_id / approver_id / approval_input_hash
idempotency_key
started_at / ended_at / status
external_side_effect / receipt
```

普通管理员不能修改高风险审计日志。日志避免保存不必要的原始私密内容，采用 ID、哈希和结构化事件。

审计采用追加式、防篡改存储和独立保留策略：

- 默认只保存结构化最小字段、哈希、版本和受控对象 ID，不保存完整 prompt、OCR 原文或证据正文；
- 合规诊断确需原始内容时，进入与普通日志分离的加密受限存储，设置用途、访问审批和短保留期；
- 审计批次使用链式哈希、签名或等效 WORM 证据，并定期验证；
- 审计不可写时，批准、锁定、撤销、导出、删除和外部调用全部 fail closed；普通只读浏览可降级但必须告警；
- 对越权尝试、批量读取/导出、异常成本、未知提交和审计中断实时告警。

## 11. 环境和运维

- 本地开发、自动测试、预发布、生产分离；
- 真实案件只进入授权预发布/生产环境；
- 秘密进入密钥管理系统，不写入代码或镜像；
- 构建生成 SBOM并扫描依赖；
- 数据库、对象和审计分别备份；
- 定期做时间点恢复和完整案件恢复；
- 高风险事件配置告警：越权、批量导出、异常模型调用、重复失败和审计中断。

恢复服务目标：

- 已确认上传的原件、已锁定 Manifest 与高风险审计：`RPO = 0`，核心读取 `RTO ≤ 4 小时`；系统仅在对象、元数据和审计均持久化后确认成功；
- 数据库普通案件状态与未锁定草稿：`RPO ≤ 15 分钟，RTO ≤ 4 小时`；
- 可重建派生件和全文/向量索引：`RPO ≤ 24 小时，RTO ≤ 24 小时`；
- 恢复演练必须用 Manifest 对账数据库、对象、审批、审计和 current bundle，重放队列并识别孤儿文件；任何不一致阻断恢复环境对外服务。

## 12. 合规上线门

封闭试点前完成：

- 律所保密和数据处理协议；
- 隐私影响和安全风险评估；
- 数据流图和供应商清单；
- 处理目的、范围、保留和删除说明；
- 访问控制和事故响应流程；
- 产品适用边界和律师终审说明；
- 不用于训练的合同与技术证明；
- 真实案件材料使用授权。

若未来面向中国境内公众提供生成式 AI 服务，需要根据服务形态专项评估备案、内容安全、个人信息和生成内容标识等义务，不能依据“法律工具”自行假定豁免：[《生成式人工智能服务管理暂行办法》](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm)。
