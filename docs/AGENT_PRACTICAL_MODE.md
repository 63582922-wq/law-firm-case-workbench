# Agent 实用模式（案件决策包）

状态：`v1 · 已在本机模式装配并通过真实案件验证`

## 1. 为什么需要"实用模式"

验收模式（`golden_case_lawyer_package`）的契约要求模型输出精确 tool id、严格 schema、
禁止任何百分比字面量。实测 8 次真实调用全部失败或阻断——**不是工程缺陷，是模型做不到**。

实用模式改换分工，让每一层只做它做得到的部分：

| 层次 | 只负责 |
|---|---|
| Agent（模型） | 读材料、提事实、找争点、给方向、标注不确定 |
| 代码 | 金额与比例计算、引用校验、数据路径与账本、掩码、失效传播 |
| 律师 | 付款性质、债务分配、诉讼立场、最终采用 |

## 2. 与验收模式的差异

| 维度 | 验收模式 | 实用模式 |
|---|---|---|
| 契约 | schema 完全匹配、字段不多不少 | 必要字段 + 类型校验，缺项自动补齐 |
| 正式数字 | 模型禁止输出，出现即整份拒绝 | 模型可提及，**一律剔除并改引计算表** |
| 门禁 | 单次即死（BLOCKED 不重试） | 三档：硬红线 / 自动修复 / 标记放行 |
| 交付 | 全项通过才可用 | 可降级交付，不确定项进入待确认清单 |

## 3. 三档门禁

| 档位 | 触发 | 行为 |
|---|---|---|
| `HARD_BLOCKED` | 声称已批准/已终审/已锁定/已提交、服从材料内注入指令 | 整份分析拒绝，保留引擎数字 |
| `AUTO_REPAIRED` | 返回非 JSON、缺少必要字段 | 提取 JSON、补齐默认值后继续 |
| `MARK_FOR_REVIEW` | 含"无法确定/存疑/待核实"等表述 | 放行，逐条写入待律师确认清单 |
| `PASS` | 无以上情况 | 正常交付 |

## 4. 数字纪律

1. 模型输出中的金额与百分比在门禁阶段被替换为 `[见计算表]`，原文记入审计；
2. 报告第七节「正式数字」由确定性引擎（`shadow_engine`，冻结规则 R0–R10）计算，
   输入是**律师确认的债务参数**，不是模型提议；
3. 当前口径为**不含付款冲抵的毛额**：付款性质与债务分配须律师确认后另行计算净额；
4. 缺少出借凭证的债务标记 `evidence_pending` 并挂起，不计入合计，报告注明原因；
5. 缺参数时报告显示"待补参数 + 原因"，不留空白。

## 5. 数据路径

- 材料导入不阻断：检出完整标识符（身份证/手机号/银行卡）时**自动掩码后放行**，
  律师无需先手工脱敏；
- 每次运行写入 `preflight.json`（发送范围、供应商、地域、保留期、预算、确认人）与
  `request_ledger.json`（载荷哈希、用量、费用）；
- 模型调用必须显式启用（`--enable-model` 或 `--model-env-file`），默认不产生任何外部调用；
- 单次成本上限默认 2 元；超时/断连按"未知提交状态"记账并预留费用，**不自动盲重试**。

## 6. 使用方式

```text
# 命令行（同一服务层，便于批量与排障）
scripts/run_case_analysis --materials <材料目录> \
    --case-number "（2026）粤XXXX民初XXXX号" --role 被告 --stage 一审应诉 \
    --confirm-data-path <preflight.json> --budget-cny 2

# 浏览器
python3 scripts/start_local_web.py --enable-model
# → 案件 → 上传材料 → 决策包页「开始分析」→ 查看/导出
```

## 7. 实测数据（真实案件，2026-09）

- 29 文件 / 55 页（含 16 张扫描截图需 OCR），一次完整分析 **¥0.12**；
- 产出：4 条争点、2 条对抗分析、3 条策略选项、3 个律师决策请求，
  以及 5 条自主发现（微信凭证证明力补强建议、起诉状具状人非原告本人的程序瑕疵、
  两笔 2,200 元异常与利息固定性质疑、举证期限当日到期的时间警示）；
- 门禁结论 `MARK_FOR_REVIEW`（含待律师确认项，可交付）；
- 模型输出的 3 处正式数字被剔除并改引计算表。

## 8. 边界

- 不生成法律结论、不选择诉讼立场、不锁定提交包；
- 不替代律师对付款性质、债务分配和证据真实性的判断；
- 多人权限、联网检索、长期记忆、法院提交包属于完整受管服务，不在本机实用模式内。
