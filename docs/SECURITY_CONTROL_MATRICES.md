# 租户、审批与外部调用控制矩阵

状态：`待安全负责人和执业律师确认`

本文件将 `ARCHITECTURE.md` 与 `SECURITY_AND_COMPLIANCE.md` 的原则变为可测试的控制面。任何“界面隐藏”都不构成授权；所有控制由服务端 Command、数据策略和审计共同执行。

## 1. 三层数据作用域

| 作用域 | 允许对象 | 必填键 | 可见性 | 必测负向用例 |
|---|---|---|---|---|
| `GLOBAL` | 已发布官方法源元数据、系统 Skill/模板版本 | 无 `firm_id/matter_id` | 仅已发布且获授权资源 | 用户不能读取未发布规则、其他身份目录或平台运维数据 |
| `FIRM` | 成员关系、律所模板、律所规则卡、许可 | `firm_id`，`matter_id = null` | 有效律所成员，按角色进一步限制 | 不能用相同对象 ID 读取其他律所数据；不能把案件对象写为 `FIRM` |
| `MATTER` | 原件、派生件、事实、交易、计算、文书、审批、导出 | 同一有效 `firm_id` 与 `matter_id` | 有案件成员关系且权限满足 | 不能跨案件读取对象、签名 URL、索引、队列、缓存、审计或备份恢复 |

数据库 RLS、对象键、搜索/向量索引、任务消息、缓存、审计、导出和备份恢复均使用同一 scope 上下文；任一数据面缺少负向测试即不通过。

## 2. 角色—动作—对象矩阵

| 动作 | 助理 | 协办律师 | 承办律师 | 复核人/合伙人 | 律所管理员 | 系统 Worker |
|---|---|---|---|---|---|---|
| 上传原件、建立候选事实 | 可，限获授权案件 | 可 | 可 | 只读/按配置 | 不默认可读 | 不可 |
| 确认身份、付款性质、诉请范围 | 不可 | 可提议/复核 | 可批准 | 可复核或按配置批准 | 不可 | 不可 |
| 批准正式法律规则、计算情景 | 不可 | 可提议 | 可批准，需执业律师权限 | 可复核/按配置批准 | 不可 | 不可 |
| 编辑文书草案 | 可提议 | 可 | 可 | 可复核 | 不可 | 仅模板编译 |
| 批准最终文本、锁定或撤销提交包 | 不可 | 不可，除非有效委托 | 可，再认证 | 可按职责分离复核 | 不可 | 不可 |
| 导出法院提交包 | 不可 | 不可，除非有效委托 | 可，再认证 | 可按职责分离复核 | 不可 | 仅生成候选文件 |
| 账号/模板/保留策略管理 | 不可 | 不可 | 不可 | 按配置 | 可，仍不自动读取案件 | 不可 |

审批必须绑定 `actor_id`、有效角色/委托、案件版本、对象版本、对象哈希、最终文本哈希、再认证和时间。独任律师自审批只可在律所政策明确允许时进行，并要求增强审计；委托必须记录范围、起止时间、授权人和撤销状态，离职/停用立即使会话、委托和待执行审批失效。

## 3. 高风险 Command 门

| Command | 必须前置条件 | 审计与失败策略 |
|---|---|---|
| `APPROVE_FACT/RULE/CALCULATION` | 相应律师权限、版本未变化、来源完整、无阻断冲突 | 审计不可写或版本不符即拒绝 |
| `LOCK_SUBMISSION` | 全部依赖有效、最终文本哈希已批准、唯一 current 原子检查、再认证 | 失败不产生半锁定状态 |
| `EXPORT_SUBMISSION` | current 指针有效、未 `STALE/REVOKED`、导出权限与再认证 | 审计、Manifest 或权限异常即拒绝 |
| `DELETE_ORIGINAL` | 法定/保全检查、双人或高风险批准、保留策略满足 | Agent 永远无权调用 |
| `SEND_EXTERNAL_REQUEST` | 有效 preflight、字段最小化、成本/次数上限、供应商/地域允许 | `UNKNOWN_SUBMISSION` 禁止自动重试 |

## 4. 外部处理 Preflight 契约

每次模型、OCR、MCP 或其他外部处理都先建立不可变记录：

```text
matter_id / purpose / selected_fields_or_pages / input_hash
provider / processor_region / retention / training_policy
service_or_model / call_cap / cost_cap / request_id
authorization_actor / authorized_at / expires_at / status
```

只有 `AUTHORIZED` 且授权范围尚未过期的记录可发送。超出字段、供应商、地域、次数、成本或保留期时必须重新授权。服务端只向工具提供不透明资源 ID 和最小字段；工具说明或上传材料中的文本不得扩大工具权限。

## 5. 验收样例

每次实现控制面都必须至少验证：跨律所、跨案件、离职账号、撤销委托、助理批准、旧版本审批、失效提交包导出、审计不可写、越过 preflight、未知外部提交和错误签名 URL 均被服务端拒绝，并在允许审计的情况下留下最小化事件。

## 6. 桌面本机会话与 sidecar 控制

| 控制点 | 已实现 | 仍需放行门 |
|---|---|---|
| 本机 API 启动 | Tauri Rust 主进程启动随应用分发的自包含 sidecar；前端无 Shell execute/spawn/kill 权限 | 安装器签名、公证、升级与回滚验收 |
| 父子进程绑定 | 64 个十六进制字符的随机挑战只经 stdin 发送；sidecar 回执必须匹配协议、挑战摘要、有效 PID 和动态端口 | 对发布签名和 sidecar 文件哈希增加启动前证明 |
| 网络边界 | 仅绑定数值型 `127.0.0.1` 动态端口；当前无 OpenAPI/Docs/案件路由 | 持久 API 增加严格 Origin/CORS、速率限制和最小安全响应头 |
| 身份会话 | 律所 Ed25519 签名登记、严格字段、30 天有效期上限、设备摘要绑定、Keychain 双项目只读；Tauri 原生 Keychain API 可显式初始化并回读 32 字节安装秘密、只读状态、仅删除本机登记且不冒充远程撤销，秘密不经命令参数/WebView；一次性 bootstrap、令牌摘要、最长 30 分钟 Bearer、撤销/过期、`tauri://localhost` 与数值 loopback均有自动测试；数据库每次复核 active user 与未撤销本案角色 | 真实签发/续期/撤销服务、生产公钥轮换、后端验签凭证保存/恢复、远程撤销清单与专用 PostgreSQL 整链；不得由浏览器请求角色 |
| 生命周期 | 桌面退出时终止 sidecar；sidecar 同时监测父 PID 与 stdin；实测退出后无残留进程 | 崩溃恢复、休眠/唤醒、升级中断和多窗口/单实例策略 |

OS 当前登录会话只证明本机进程上下文，不证明执业身份、律所归属或案件授权。三者必须分层验证；在登记身份和专用数据库缺失时，sidecar 即使健康也只能报告“案件仍禁用”。
