# 律师 Agent 交付主流程阻断清单

日期：2026-09-10。用途：当前交付实施清单，不是验收通过报告。

## 需求与验收终点

固定一个全合成案件，原始材料进入系统时不预置确认事实。律师交代目标后，系统读取材料、
提出来源绑定事实/争点/风险/策略，集中呈现必要决定，生成答辩状、证据目录及补证清单。
律师能核对来源、修改实质段落、取得重新核验的新版 Word/PDF。缺失信息明确标注。
不提交法院、不代表执业律师认可、不使用撤回的真实客户材料。

## 2026-09-10 当前已核实状态

- 原始材料链已完成一次真实、受限的运行：合成案件从本地读卷进入一次受控提取，形成 44 条
  来源绑定候选；全部因为来源可信边界或收付款必要字段不足被分入 3 个异常组。该结果正确地
  阻止了系统编造事实，但不能作为风险分析或答辩状完成。
- 已确认合成输入后的交付链可重新读取：第 3 版答辩状是当前版本，Word 与 3 页 PDF 均可从
  服务端读取，且保持“律师复核候选”标记。它证明修订和下载对象链，不证明原始材料自主理解。
- 律师页面已只保留统一办案入口；材料待核对时直接进入异常组核对，不显示运行计数或空的
  诉请/争点录入表。首页、办案清单和文书区不再把内部任务、恢复、调用或模板机制作为律师
  操作说明。浏览器自动化仍持续超时，因此这项界面改变尚缺实屏交互记录。
- 独立证据目录已接入受控交付目录和页面选择：它只会整理律师已确认纳入范围的证据页，生成
  Excel 与 PDF 审阅稿，不调用模型，也不替律师填写证明目的或判断证据三性。数据库升级和定向
  自动检查已通过；尚未取得浏览器实屏和一次完整案卷中的生成/下载证据，不能写作“律师已验收交付”。
- 原始材料答辩目标的服务器预算已在干净合成案卷预检中实际写入：无确认事实时累计仅
  2 次/240 分、已用 0；不能回退为通用的 50 次/100000 分预算。两次独立候选提取已真实返回并
  形成来源绑定候选；一次低风险候选确认已实际写入事实台账。它们尚未构成同一运行的完整交付链。
- 第三次受控提取在 TLS 握手阶段被对端关闭：5 秒后记录一次 `UNKNOWN_SUBMISSION`，没有私有原始
  响应对象，也没有第二次发送。ADR-0119 已将今后的 DNS/TLS 连接前失败定为零调用、零费用的已知
  失败；对真正未知结果仅保留一次查找并静默暂停。历史运行保持未知，不重发。

下一次验收必须使用一个独立、固定的干净合成案卷：原件进入时不预置任何事实、诉请或争点；
评估答案与模型输入隔离；每个模型阶段各有一次明确上限；律师的合成确认只发生在来源可见的
候选之后。不得把本段两条不同输入边界的证据拼接成“已完成整案”。

## 实施约束与停止条件

- 首先处理P0-1与P0-2，不能把所有答辩请求直接转给通用付费规划器。
- 先定义阶段合同和预算传递，再改路由；该产品边界变更需要新ADR，保留ADR-0056历史。
- 原始文件、来源范围、幂等键、权限、预算和审批由代码控制，材料文字不提供指令权限。
- 模型可以提出待核实假设，但不能把计算差额写成新增付款事实；正式计算仍由确定性工具负责。
- 不因失败自动创建新案件/新调用；结果不明保留原调用记录，只核对，不重发。
- 每阶段只验证本次改动涉及的路径；最终完成必须有一条完整用户旅程，不用测试数量替代。
