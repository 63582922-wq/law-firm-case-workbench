# 证据页处置与派生 Manifest 契约

状态：`合成领域状态机、PostgreSQL 结构、持久化命令/API/只读中文界面已实现；对象存储与正式 PDF Worker 待接入`

## 不可变原件

原始文件以 SHA-256、字节数、媒体类型和页数登记；每页有独立页标识。系统中的“删除无关页/重复页”只表示在派生计划中排除该页，原始文件和原始页永不删除、覆盖或重排。

## 每页处置

每个来源页必须有且只有一个当前有效的律师批准决定：纳入或排除，并保留理由、批准人和批准哈希。任一页未审、重复候选未解决或同源重复组同时纳入多页时，Manifest 锁定必须阻断。

## 重复页

系统或助理只能建立重复候选。主办律师决定“同一来源页”并选择规范页，或决定“不同页面”。同一来源页结论要求派生件只纳入规范页，其余页保留在 Manifest 中并以排除决定说明；不得物理删除原始页。

## 红框坐标

红框是独立页级标注：标准化坐标、标签、状态、批准人和批准哈希。它不修改原始影像，也不自动证明标注内容与案件有关。正式派生 Worker 只能使用锁定 Manifest 中纳入页的已批准标注。

## 锁定与失效

锁定 Manifest 覆盖全部来源页，记录纳入/排除数、派生顺序、页级决定、标注和内容哈希。修改页级决定、红框或重复结论后，旧 Manifest 失效，不得继续生成或冒充当前派生件。

## 派生件状态

相关页 PDF 与红框 PDF 都是 Manifest 的派生件。候选件、已验证件、失效件和撤销件分开保存；已经验证的派生件失效时仍保留原验证哈希、验证人和验证时间，并另记失效时间及理由，不能通过清空历史字段掩盖曾经的批准链。

## 持久化命令边界

原件登记、页级处置、红框、重复组和 Manifest 锁定均使用 UUID、案件版本、幂等键、数据库案件角色、审计事件和 Outbox。正式决定变化在同一事务中使旧 Manifest、派生件及当前提交包失效。候选变化不冒充正式结论；Manifest 锁定前必须覆盖全部来源页并消除未解决重复组。
