# 项目现状审查：2026-09-09

## 结论与范围

当前是有真实执行基础、局部工具与文书生产记录的内部 Alpha，不是已经能够独立办完案件的律师产品。
不能给出可信的完成百分比：代码存在、服务运行、整案成功、律师认可和商用放行不是同一指标。
本轮只读审查源码、运行容器、数据库聚合和聚焦合同测试；未读取下载中的真实律师材料、修改业务代码、
发起新模型请求、审批法律立场或创建提交包。本文是审查产物。

## 主要阻断及依据

1. 正常主线未闭合。专用应诉规划输入仅保留代理、事实、诉请、已核验法源和已批准规则；
   首轮构造情境与律师分析两个任务。不能把已整理事实上的分析，算成主动读原始材料、发现问题。
   依据：backend/case_kernel/controlled_defence_case_agent_planner.py:53、232。
2. 失败恢复过多落到人。WAITING_INPUT 下总控不继续发命令；这是防止失控重试的合理保护，
   但尚不能充分区分机器可修复问题与律师必须决定事项。应保留未知外发不重发，增加有限恢复和独立分支交付。
   依据：backend/case_kernel/case_agent_supervisor.py:1270。
3. 分析限制影响推理。律师分析仍使用定性数值标签，禁止自由文本复述或推导数值。
   应区分读懂来源金额/日期与决定正式计算结果，不能用删除上下文替代受控计算工具。
   依据：backend/case_kernel/case_agent_lawyer_analysis.py:2539、2772。
4. UI 仍要求用户理解系统。目标输入要求完成标准，错误动作含 GET 核验、原请求编号重放，
   还暴露 Worker 和恢复候选。律师缺少一条不用技术解释的任务引导。
   依据：web/src/components/web-agent-panel.tsx:719、723。此为源码事实，不是实屏可用性测试。
5. 修改与交付未实证。段落编辑受前端开关控制；不能因为旧模板修订实现存在，就宣称正文修改链已实跑。
   依据：web/src/components/web-agent-panel.tsx:829；数据库内容修改三类表记录均为 0。
6. 发布版本难以确认。API/Worker 本地覆盖挂载不是不可变发布镜像。当前 Git 有 510 个未跟踪条目、
   59 个已跟踪变更，最新提交日期为 2026-08-11；未跟踪条目可能包含目录，不等同于文件数量。
   不能把当前工作区能力等同于可重装、可部署的商用版本。

## 相比旧审计已经改善

- 动态交付清单已改用 requiredDocumentDeliverables，不再固定要求两类文书。
- 终审读取已检查 CURRENT、下载就绪、PDF 页数及传入文书审阅版本；不再把无异常返回当成可审阅。
- 段落正文编辑和修改历史已有代码，不能继续说只有模板更新；但真实生成交付仍无记录。
- Worker 已常驻，扫描、渲染等容器健康。磁盘当前可用约 52 GiB，旧报告磁盘不足不再是当前事实。
- 本轮 Worker 部署与终审合同共 11 项聚焦测试通过，只支持对应合同，不代表产品全面验收。

## 视觉与安全证据边界

产品体验 audit 技能要求当前实际流程截图；本轮浏览器入口超时，无法取得有效业务截图，
因此视觉、键盘、缩放、可访问性和首次使用全旅程未完成。源码仍存在 8–11px 小字号风险，
但不据此虚构实际对比度、可读性评分。不得以重新绘制截图代替当前产品。
权限/RLS、原件保存、确定性计算、审计与分离验证器是应保留的基础；本轮没有做完整攻击测试、
全部备份还原或执业律师审阅，不能声称商用安全和法律质量已通过。

## 整改优先级及完成标准

先收敛现有主线，不建议推倒重写、加 Agent 数量或再造恢复脚本：

1. 用户旅程：入口→交案→处理进度→集中待办→成果。首次使用无需终端或现场技术指导。
2. 执行链：仅交原始合成材料与业务目标，Agent 自行发现未预填冲突，允许有限恢复和部分成果。
3. 成果链：风险/攻防/补证建议及答辩状候选→可下载→修改→新版→重新复核，来源与版本一致。
4. 发布门：固定代码/镜像/迁移版本，完成独立样本和律师验收、权限及恢复验证，才商用放行。

模型存在历史实质性错误，但无同输入同工具的对照，不足以归因为模型能力不足。
当前更直接的证据指向产品链路、控制边界、部署与交互组织。下一单一目标是统一用户主流程，
以真实原始合成案交付作为验收；不是继续增加局部测试数量。
