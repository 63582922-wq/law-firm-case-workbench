# 律师 Agent 真实能力验收（2026-08-28，更新至 2026-09-05）

## 当前结论

整体当前同时存在 `M2_SEALED_RESPONSE_DOCUMENT_REPLAY_PASSED` 与
`M3_CURRENT_RUNTIME_SINGLE_CALL_BLOCKED` 两项证据；二者都不是“商用放行”或“律师已验收”。

M1 的模型前来源、规则与法源包门已通过，并已实际完成一次律师审批后的 `qwen3.7-plus` 外发；外发台账只有一条 `STARTED` 记录，未生成可认证的本地响应归档。该请求在旧的 180 秒传输上限内未完整回包，结果可能已被供应商受理，因而绝不重发、换模型或伪造失败。ADR-0074 已将旧的后台恢复空转改为“一次只读归档核验后封存并静默”的受控状态：恢复只读取第一次落库的不可变外发边界，M1 的 inbox 已收敛为 `QUIET` 并保留结果未恢复审计。M1 不会被修改或替代。后续真实完整链路验收只能是新的、有单次外发上限的合成案件，而不是 M1 重跑。

M2 的首次启动在模型前因官方网页不能受控下载而停止；该停点随后按
[ADR-0076](../decisions/ADR-0076-m2-fresh-firm-source-pre-model-recovery.md) 在精确版本 30、零外发和
24 小时来源时效门内恢复。同律所、同 URL、同 SHA-256、同媒体类型的公共法源已被复制到 M2 自己的
私有范围，随后只发生一次 `qwen3.7-plus` 外发。供应商正常以 `stop` 返回，原始响应为 11,506 bytes，
有 3,738 输入 token、4,029 输出 token、合计 7,767 token 和费用回执；M2 外发台账始终只有一条
`STARTED` 记录。

M2 的原始状态机结果仍是 `WAITING_INPUT`：旧版本严格解析器发现模型把一个可由来源唯一证明的差额
写进自由文本后正确阻断，历史失败回执、运行版本 8 和状态未被改写。ADR-0077 只增加“差额在金额前”
的同义语序识别，并且只删除、绝不接受为正式数值；当前严格解释器对封存原始响应完成四处可证明差额
的脱敏，形成 32,570-byte 的律师决策包候选。没有再调用模型、没有重发 M2，也没有创建新 Agent run。

M2 的《中华人民共和国民法典》原始可见正文为 111,098 个字符，超过文书单源 40,000 字符门。
[ADR-0078](../decisions/ADR-0078-registered-provision-projection-for-document-binding.md) 不允许截断、概括
或放大上限，而是仅对注册来源 `CN-CIVIL-CODE-680` 和精确登记的第六百七十九条、第六百八十条，重新
验证标题、通过日期、顺序、边界与字面标记后形成 211 字符的可复算条款投影。原始来源哈希、私有对象、
法源包和案件记录保持不变。

在该边界下，M2 只读文书回放已经成功：一份 7 节、11 个受控来源的“待律师复核、不可提交”民事答辩
候选经隔离 LibreOffice 服务生成 3 页 A4 DOCX/PDF。DOCX SHA-256 为
`39d4562c43e1b5829e9460bd0bec56024bec251a6db260db511079944d7a3a79`；PDF SHA-256 为
`73b5cbaca55c00c28d07f7a983c8b9441edc9ad6f7aaf8cad418293fefc0a1b3`。回放回执确认：0 新 Agent run、
0 模型调用、0 案件数据库写入、0 案件对象存储写入、1 次隔离渲染，且封存 `WAITING_INPUT` 运行未改变。
PDF 的 A4 结构、三页候选标识、中文文本、七个章节和无 `NaN`/`undefined` 等异常文本已经实际检查。

状态区分：已配置的是受管 Qwen、对象存储、法源读取和隔离渲染；已测试的是一次真实模型到封存候选

解释规则的持久化 `SUCCEEDED` 正常模式 Agent run。因此不得宣称已经商用放行。

## 2026-09-05 M3 当前运行时单次验收

M3 是独立的 88 页、11 文件全合成案件。它在同律所、同哈希、24 小时时效内的已批准公共法源门通过后，
只发生一笔 `qwen3.7-plus` 外发，且无自动重试。供应商在 71 秒内返回可认证的 10,811-byte 原始响应，
外发台账、私有归档和用量回执均存在；这证明当前 API、Worker、状态机、外发边界和归档能完成一次真实
交换，不是模拟响应。

但 M3 **未通过**律师决策包门：模型在 `adversarial_analysis[1].residual_risk` 写出
`5,000.00 CNY`，并把该数额描述为可能的现金交付或其他形式借款。该值是两项来源金额的算术差，不是
字段内任一来源的原样事实。它也不是 ADR-0077 的可逆展示脱敏对象，因为“现金交付/借款”属于实质性
事实推断，而不是紧邻“差额/差异”标签的展示文字。当前解释器以
`adversarial_analysis[1] contains a numeric literal outside its source bindings` 拒收；任务回执为
`FAILED / SUBMITTED / LAWYER_ANALYSIS_OUTPUT_REJECTED`，运行保留 `WAITING_INPUT`。没有决策包候选、
DOCX、PDF、律师审批或提交物被生成。

这次失败是正确的 fail-closed 行为：没有把模型自行计算的金额带进律师材料，也没有为了获得成功而创建
M4 或重发。M3 的原始响应、外发记录和状态永远保持不变。

根据 [ADR-0080](../decisions/ADR-0080-qualitative-model-projection-and-chinese-quantity-gate.md)，后续模型请求会
将来源中的金额、日期和其他数值替换为稳定的定性标签；模型自由文本仅可作定性分析并通过来源编号引用，
服务器继续独立保存/展示原始来源事实。解释器还新增了中文量化门，避免模型用中文书写金额、比例、期限
或日期绕过数值门。该改动已通过 70 项聚焦测试；M2 的封存回放仍以原哈希结果生成
`NEEDS_LAWYER_REVIEW` 候选，说明历史审计兼容性未被破坏。该修复未进行第二次模型调用，不能被表述为
M3 已通过或当前模型链已经可商用。

## 为什么不能通过

### 硬控制器直接阻断

模型在利率争点的自由文本中写入多个正式百分比，违反“正式利率只能来自确定性工具”的
边界。系统在文书生成前阻断，没有把这些内容带入 DOCX 或 PDF。

### 律师视角复核发现的语义错误

1. 时效追问把催收主体写反，要求被告说明是否向原告催促还款；正确问题应核对原告是否
   催收，以及被告是否确认债务、承诺履行或部分履行。
2. 一套策略绑定了排除周转款的情景，却同时把增加该款写成收益，内部逻辑冲突。
3. 同一策略把未经律师确认的时效结论写成已经锁定。
4. 周转款与时效对抗分析没有绑定登记的对方主张，无法区分“材料中已提出”与“律师应预判”。
5. 原合同把证据缺口强制为非空、单争点来源上限设得过低，与真实案卷密度不符。

这些问题说明：结构完整、正常结束和引用白名单命中仍不足以证明律师可用；系统必须限制
模型能写什么，而不是要求模型下一次“更听话”。

## v4 控制架构

决策见 [ADR-0044](../decisions/ADR-0044-strict-lawyer-core-and-controlled-projection.md)。

- 模型迁移到支持严格 JSON Schema 的 `qwen3.7-plus`。
- `response_format.type=json_schema`、`strict=true`，每层对象禁止额外字段。
- 不设置 `max_tokens`；按官方最大输出长度和北京公开原价做最坏费用预检。
- 单次验收固定费用上限 1.20 元，禁止自动重试或静默切换模型。
- 模型只负责证据强弱/缺口、攻防理由、策略执行条件/风险、登记决定理由。
- 代码负责争点标题、举证责任、角色安全追问、主体归属、已主张/仅预判状态、正式利率、
  金额、情景、策略正式收益、期限、章节与行动。
- 模型自由文本禁止数字、货币符号、百分号和受控法律结论；ID 只能从严格枚举中选择。
- 证据引用上限放宽到十二项，证据缺口允许为空；必要来源政策仍由代码强制。
- v3 原始输出永久保持失败，v4 编译器明确拒收 v3。

## 单一下一目标

在不创建新的模型运行、不重写 M1/M2 历史状态的前提下，完成受管 Worker 的恢复、权限和持久化交付
审计。该审计须确认：

1. 任一中断、未知外发或重启都不会重复调用模型、覆盖原始来源或伪造任务成功；
2. 真实已认证模型响应可在不越权的情况下供律师复核，且不能绕过文书/提交批准门；
3. Worker、法源对象、文书候选和渲染器均按 firm/matter/actor 范围隔离；
4. 审计结束后再用证据决定是否值得进行一条新的、单次预算的正常模式合成运行，而不是机械补测。

即使下一阶段通过，也只代表合成案的受控 Agent 链获得更多运行证据；律师接受、真实案件、跨租户、
备份恢复、供应商治理和商用发布仍需各自独立证据。

管理入口不会自动加载该层，且运行核验会报告仍带覆盖的历史 API。现有运行容器在完成干净重建前继续只是局部验收环境。

清理可重建的前端缓存后，Docker Desktop 后端进程仍在，但 Docker Unix socket 的两次 5 秒只读 ping 与本机管理 `verify` 的
30 秒状态读取均超时。`verify` 已改为报告“无法判断服务是否仍在运行”，而不再把这种控制面不可读误写为服务已停止；因此此前的
容器健康证据不能作为当前状态。没有停止、重启、重建容器或发起模型调用。

下一单一目标调整为：不创建模型运行，先恢复至少 5 GiB 可用空间并建立可读取状态的 Docker 运行面，再将当前前端/API 安全修复重新打包为普通
镜像，再在用户明确选择的浏览器中完成律师候选审阅与恢复旅程，验证 M2 候选的可见性、案件权限、失败恢复
和提交审批门。之后才根据该旅程的真实证据决定是否值得申请一条独立、单次预算、不可自动重试的正常模式
合成运行；不得为了把 M2 或 M3 状态改为成功而创建新运行。
