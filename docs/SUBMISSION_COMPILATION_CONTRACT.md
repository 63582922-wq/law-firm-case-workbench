# 法院提交包编译契约

状态：`合成 Alpha 已实现；未经过真实案件、专用 PostgreSQL 或法院平台验收`

## 目标

将律师已经批准的法院材料编译为唯一、最小、可复核的 `法院提交材料.zip`。编译器不写入原案卷文件夹，不替律师作出诉讼判断，也不连接法院执行提交。

## 强制输入

- 案件必须位于 `READY_TO_EXPORT`，并有唯一当前 `VALID + LOCKED` 提交包；
- 文件必须是同案、`APPROVED`、`COURT_SUBMISSION`、`application/pdf` 且按明文 SHA-256 内容寻址的成品；
- QA 必须引用一份当前 `PASS` 的文书一致性审查：它要覆盖完全相同的工作产物与 `review_input_hash`，绑定当前案件版本，且 `blocking_count=0`；任何文书或材料替换、审查阻断项或版本变化均不能沿用旧审查；
- 币种固定为 `CNY`；
- QA 哈希绑定文件标识、顺序、法院文件名和批准哈希；
- 依赖必须同时包括当前锁定证据 Manifest、已批准法律规则包、使用该规则包的已核验计算、当前最终文本审批；
- 必需文书种类由案件的已批准 QA 规格声明，缺一项即阻断。

## 输出隔离

法院 ZIP 只包含已批准 PDF，不包含系统说明、内部哈希、AI 描述、日志或审计信息。技术谱系保存在独立的 `提交包内部清单.json`，两者分别加密并按内容哈希登记。ZIP 中文件名拒绝路径、控制字符、重复名及“最新、最终、修订、终稿、V2、final”等歧义版本词。

单文件上限 128MB，法院 ZIP 上限 256MB，最多 100 个 PDF。当前使用无压缩 ZIP 以保证字节级可重复编译；PDF 在进入 ZIP 前验证文件头、EOF、长度与哈希。

## 双重核验

1. 编译完成后，Worker 逐项比较 ZIP 与内部清单；
2. 写入加密对象库后，在数据库登记前重新解密并验证 ZIP 结构、清单结构、文件集合、每个 PDF 哈希、案件提交包 ID、QA 输入哈希和文件数量；
3. 仅 SYSTEM_WORKER 能登记导出；只有当前有效导出可以签发下载许可。

## 本机交付边界

主办律师或复核律师在有效的 OS 绑定本机会话中，取得最长 30 秒、仅一次、仅 loopback 可用的下载许可。前端收到文件后再次核对媒体类型、长度和 SHA-256，固定下载名为 `法院提交材料.zip`。助手、律所管理员和系统 Worker 均不能以该入口下载。
