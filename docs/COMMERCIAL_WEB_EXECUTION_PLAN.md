# 律师办案 Agent 商用 Web 执行计划

版本日期：2026-08-15
产品形态：律所部署一次，律师通过 Windows、macOS 或 Linux 浏览器使用的中文 Web 应用
当前定级：代码级内部 Alpha，已有本机受管环境的局部真实运行证据，但混合案卷尚未完成 `PROVEN`，不得称为商用已验收

## 1. 当前唯一产品定义

本产品不是材料上传器、逐页审核表、法律聊天机器人或固定的“原告/被告工作流”。律师交代办案目标并上传材料后，代码总控应当持续观察案件状态、动态规划、调用受限 Skill、恢复失败任务、核验结果并形成成果；律师主要处理代理范围、冲突事实、低置信候选、法律口径和最终交付，不应从第一页开始重复机器可以完成的整理工作。

“代理原告还是被告”只是当前案件情境的一部分。程序阶段、代理对象、诉请变化、法院通知、已付款项、证据缺口和有效法源共同决定任务与交付物。系统不得写成“被告必然生成答辩状”或“原告必然生成起诉状”的固定映射；缺少已确认代理情境时，可以安全接收入卷并显示格式/处理状态，但不得启动统一办案 Agent。只有主办律师形成 `CURRENT` 代理情境后，Agent 才能据此和材料、法源动态规划。

以下边界保持不变：

- 接收文件不等于 Agent 已分析，解析成功也不等于事实已经确认；
- 搜索结果只用于发现线索，只有已抓取、留存并复核的官方原文才能支持正式法律依据；
- 模型只能返回结构化候选，不能决定正式事实、证据取舍、利率、起止日、冲抵顺序或法院提交；
- “支持常见文件”必须逐格式说明是仅接收入卷、可被 Agent 读取，还是已经形成来源绑定成果；
- 页面、单元测试、迁移文件或容器配置不等于真实数据库、对象库、模型、Worker 和浏览器链已经验收；
- 律师 Web 页面不提供宿主机 Shell，也不允许模型取得任意命令、任意网址、任意文件路径或其他案件权限。

完整目标架构仍以 [律师办案 Agent OS 产品架构](LAWYER_AGENT_OS_ARCHITECTURE.md) 为准；本文件是当前执行和验收的唯一状态基线。

## 2. 成熟度口径

| 级别 | 含义 | 对外表述 |
|---|---|---|
| `DESIGNED` | 只有设计、Schema 或安全合同 | 不可称可用 |
| `IMPLEMENTED` | 内核、持久模型或适配器已有代码并经过聚焦检查 | 不可称律师可用 |
| `WIRED` | Web/API/生产组合根/Worker 已按 fail-closed 方式装配 | 只能称代码级内部 Alpha |
| `PROVEN` | 真实 PostgreSQL、对象库、身份、模型/工具及重启恢复已走通 | 才可封闭试用 |
| `RELEASED` | 权限、攻击、备份恢复、浏览器矩阵和律师匿名全案验收齐全 | 才可商用放行 |

### 当前支持范围必须这样向用户表述

- PDF 继续走页级证据链；文本 PDF 可读，扫描页需要视觉/OCR 能力并保持候选状态。
- DOCX、XLSX 已在代码级 Web 链中闭合为 Agent 可枚举的 `material-object`；仍须真实对象库和 Worker 运行证明才能称“Agent 已读取”。
- PPTX、RTF、TXT、CSV、HTML、EML 当前只能按各自已验证能力标示“已接收入卷”或“待解析”，不能统一显示“分析完成”。
- JPEG、PNG 已在代码级 Web 链中闭合为页级视觉来源；页面只能显示“可供 Agent 读取”，真实 Qwen 处理和候选回读完成前不能显示“Agent 已读取/分析完成”。
- DOC、XLS、PPT、MSG、OFD 以及未知、加密、含宏或可执行内容的文件当前明确拒绝或隔离，不用错误兼容换取表面上的“任意文件”。

## 4. 唯一律师用户路径

```text
登录
→ 新建或打开案件
→ 确认本案当前代理对象、程序阶段和授权范围
→ 上传材料并取得服务器接收回执
→ 向办案 Agent 交代整案目标、完成标准和边界
→ Agent 自动盘点、读取、OCR、分类、去重并建立案件情境候选
→ Agent 根据当前事实、诉请、程序事件和缺口生成动态任务图
→ Agent 执行获准的材料读取、公开研究、官方原文核验、计算和起草
→ 律师只处理冲突、低置信、法律口径、数据外发和立场性动作
→ 已确认候选进入正式台账，变更会使依赖结果过期并触发重规划
→ Agent 形成来源绑定的 Word、Excel、PDF 和提交清单候选
→ 律师复核、修改、批准、锁定并导出
```

前台只保留一个“办案 Agent”入口。材料、证据、法律、计算和文书页面是 Agent 成果的专业复核工作区，不是五条彼此割裂的手工流程。系统可以批量呈现高置信低风险候选，但不得代替律师批准正式事实、法律结论或对外行为。

## 5. 剩余 P0：先闭合可用的内部 Alpha

P0 的目标不是再增加能力名称，而是让上述唯一路径在一宗匿名混合案卷上真实走完一次。

### P0-1：验证统一材料入口和 Agent 可达性

- 在生产同构环境用真实 PostgreSQL 和对象库上传 DOCX/XLSX/JPEG/PNG，证明现有 Web 接线会把同一对象哈希的 `material-object`/`evidence-page` 纳入下一次 Agent 权威快照并交给对应 Skill；
- 原生图片只有在 0038 当前任务重新授权并读取到同一对象哈希后才显示“Agent 正在识别”；任何运行失败都只显示“已入卷待处理”；
- 对 PPTX/RTF/TXT/CSV/HTML/EML 逐一显示“已读取、仅入卷、受限或拒绝”，不使用一个模糊的成功状态；
- 补齐结果不明终态对账的恢复 Worker、ZIP 子文件逐项登记和大文件断点能力，并按真实状态呈现；禁止浏览器盲目重传。

### P0-2：证明“Agent 候选→正式台账→新计划”的已接线主干

- 在生产同构环境证明案件首页的单次可恢复确认会形成 `CURRENT` 档案、协办只读、变化后 `STALE`，且本地开发模式完全不请求该服务；
- 证明缺少 `CURRENT` 档案时统一 Agent 启动会 fail-closed，确认后才允许创建运行；
- 已接线主干由 0042/0048 完整低风险组确认、0047 异常整组分流、0049 当前后续事项、0046/0047/0049 snapshot refresh、Worker `CASE_SNAPSHOT_CHANGED`/`REPLAN`、0043 新 `CANDIDATE` 和 0044 整案激活组成；浏览器不能选择候选子集或提交候选正文、哈希、页 ID；
- 重新提取、补充证据和延期不因“已分流”自动算完成；0049 保留 `ACTIVE` 当前头，只有精确来源绑定与对应终态才解除计划晋升/激活门；
- 0050 已把异常控制恢复改为“先持久恢复意图→创建确定性替代 Run→原子转移控制并切换 inbox”，未转移意图、旧控制 Run 和升级期孤儿 Run 都保持不可领取；
- P0 剩余工作不是继续把同一状态机重复写一遍，而是在生产同构环境用真实服务证明：完整低风险组确认和每类异常路由都能进入正确后续，Worker 中断后能恢复，随后只生成并激活基于新案件版本的计划；
- 一次性 PostgreSQL 16 迁移/聚焦集成运行只能说明迁移及部分数据库合同可执行，不能替代真实 OIDC/MFA 会话、S3 对象回读、DeepSeek 交换、浏览器动作和律师判断；
- 律师纠正后使受影响任务和成果过期，并从最新权威快照局部重规划；
- 证据页默认展示异常和冲突，不再要求律师遍历全部页面。

### P0-3：闭合“研究线索—官方原文—规则—计算”

- 普通网络搜索只生成线索；Agent 必须继续抓取白名单官方页面或 PDF、保存原文和版本并核验效力；
- 正式计划项和文书引用只能使用已经复核的官方来源；
- 律师在统一决定箱确认适用期间、起止日、币种、规则和冲抵顺序；
- 已确认输入进入确定性计算和独立复算，上游变化自动使结果过期。

### P0-4：闭合可编辑文书和成果晋升

- 在生产同构环境验收已经注入 Worker 的 LibreOffice/Poppler 隔离渲染侧车：验证内部签名健康预检、转换超时不重传、容器断网与真实 DOCX/XLSX→PDF 结果；
- 完成 Word/Excel 候选的下载、线下修改后再上传或受控在线编辑、批准、驳回、版本比较和重新渲染；
- 将已批准文书与证据清单、法源、计算和未决问题绑定为提交候选；
- 只有所有上游对象仍为当前版本且通过独立校验时，才允许律师锁定和导出；不自动提交法院。

### P0-5：一条真实运行证据

- 在生产同构的本地或测试环境连接真实 PostgreSQL、私有对象库、ClamAV、Poppler、隔离文书服务、DeepSeek，以及按需启用的 Qwen/Brave；
- 从浏览器完成登录、建案、混合上传、Agent 运行、异常决定、官方法源、计算、文书下载和恢复；
- 杀掉并重启 Worker，证明任务从持久状态继续；对外请求结果不明时证明系统不会盲目重发；
- 保存一份可复核的运行记录。未完成此项前，仍只能称代码级内部 Alpha。

截至 2026-08-15，0046—0052 已有代码级接线，并在一次性本地 PostgreSQL 16 空库执行过连续迁移、最小列权限、固定恢复目标和并发路径验证；这不是生产数据库、真实身份/对象库/模型或长期恢复证明。真实 OIDC/MFA、私有 S3 对象库、DeepSeek、隔离工具、Worker 杀进程恢复、Windows/macOS 浏览器端到端和律师匿名全案仍没有 `PROVEN` 证据；单次本地集成通过不能替代这些证明。

## 6. 剩余 P1：封闭试用和商用放行

P1 只有在 P0 的真实整案链通过后开始，不用更多单元测试替代真实环境证据。

- 真实 OIDC/MFA、三类最小权限数据库身份、完整迁移/回滚和 PostgreSQL FORCE RLS；
- 私有 TLS 对象存储、KMS、版本、备份、恢复、保留、删除和法律保全；
- Worker 租约恢复、对象库/数据库一致性修复、未知外部结果人工对账；
- 供应商数据处理、训练/保留政策、处理地域、成本上限和律所授权治理；
- 恶意 PDF/Office、ZIP 炸弹、文档提示注入、SSRF、CSRF、越权、跨租户、命令逃逸、日志泄密和镜像漏洞测试；
- 律师个人/律所知识发布、双人复核、脱敏、撤回和可见范围管理；在真实 RLS 下证明 ACL-first 检索；
- Windows 11 Chrome/Edge、macOS Chrome/Safari 的完整浏览器路径；
- 至少一名律师用一宗匿名真实案件完成整案验收，记录遗漏、人工修改率、错误法源、错误期间、恢复情况和实际节省时间；
- 上述证据齐全后才能把状态从 `PROVEN` 提升到 `RELEASED`。

## 7. 下一里程碑：匿名混合案卷到可编辑成果

唯一下一里程碑命名为：**M1 混合案卷 Agent 闭环**。

验收输入：同一匿名案件至少包含文本 PDF、扫描 PDF 页、DOCX、XLSX、JPEG/PNG，并具有已确认的代理档案、诉请或办案目标。验收结果必须同时满足：

1. 所有文件都有真实接收状态；不支持或仅入卷的格式被逐项说明；
2. Agent 自动覆盖全部可处理对象，律师不需要逐页点击启动；
3. 每项事实、交易、争点、研究线索和风险候选都能回到具体来源页、对象版本或官方原文；
4. 动态计划会随代理地位、材料缺口和律师纠正变化，不按原告/被告套模板；
5. 搜索摘要不会直接进入法律结论，正式引用具有官方原文、版本、抓取时间和效力信息；
6. 金额由确定性引擎计算和复算，模型不输出正式利息结论；
7. 至少形成一份可编辑 DOCX、一份可编辑 XLSX 和对应 PDF 预览，并显示未决问题；
8. Worker 重启后继续，未知外部结果不重复发送；
9. 律师可纠正、批准或驳回，但系统不会自动签章、发函或提交法院。

### 固定实施顺序

1. 在生产同构环境验证现有常见材料、代理情境 Web 链和 Agent 权威快照；
2. 在生产同构环境证明已 `WIRED` 的“低风险事实/交易整组确认→异常分流及后续事项终结→新台账 snapshot refresh→自动重规划→新动态计划整案激活”唯一状态机；
3. 搜索线索到官方原文、规则和确定性计算；
4. 隔离文书渲染、律师修改/批准和提交候选晋升；
5. 生产同构环境中的 M1 实跑、恢复和浏览器记录。

台账到新计划的代码级主干已经是 `WIRED`；但 M1 还同时要求混合材料、真实模型/对象库、研究、计算、可编辑成果和恢复，因此 M1 整体仍只能定级为 `IMPLEMENTED`，不是 `PROVEN` 或 `RELEASED`。完成 M1 只意味着可以申请封闭试用，不意味着商用放行。

## 8. 复核原则

每个里程碑只做与风险相称的一次代码复核、一次真实运行和一次用户路径验收，不把检查本身当进度。任何状态报告必须分开写明：代码事实、合同/测试事实、真实基础设施事实、律师用户验收事实。前两项完成时，不得把后两项写成已完成。
