# 质量、验收与发布计划

## 1. 质量定义

项目必须区分以下状态：

```text
已配置
已运行
已通过自动测试
已由人工复核
已由律师接受
已锁定可提交
已在真实案件证明价值
```

不能用前一层证明后一层。

## 2. 测试分层

### 2.1 单元测试

- 状态机转换和前置条件；
- 权限决策；
- 金额和日期；
- 页级指纹；
- 依赖失效；
- 文件命名和 Manifest；
- 法律有效期间判断；
- 文书一致性规则。

### 2.2 属性和不变量测试

计算引擎重点：

- 相同输入产生相同结果；
- 本金余额按批准事件变化；
- 分配总额不超过付款金额；
- 各期间利息之和等于总利息；
- 分币舍入规则一致；
- 同日事件顺序固定；
- 闰年和跨年正确；
- 未批准付款不能进入正式计算；
- 计算结果能够重新生成。

### 2.3 集成和合同测试

- Web/API Schema；
- API/数据库事务；
- 状态机/任务 Outbox；
- 异步 Run 输入版本指纹、CAS 和旧结果拒绝；
- 外部请求账本、逐次授权和未知提交恢复；
- OCR/对象存储；
- Agent/Tool Gateway；
- 法律检索/官方快照；
- 文书生成/渲染；
- 审批/导出。

所有 Agent 和 Tool 输入输出使用版本化 JSON Schema。

### 2.4 金标准案件

每个脱敏金标准案件包含：

- 原件清单和哈希；
- 正确相关页；
- 重复页面组；
- 人物和别名映射；
- 诉请和关键日期；
- 逐笔交易台账；
- 付款性质的律师答案；
- 适用法律版本；
- 计算参数和逐行结果；
- 预期文书要点；
- 预期提交包结构。

金标准只保存脱敏数据，不进入公共仓库。

### 2.5 端到端测试

P0旅程：

1. 新建案件并上传混合材料；
2. 处理损坏和重复文件；
3. 确认相关页和红框；
4. 确认身份、诉请和送达；
5. 对账并确认付款性质；
6. 批准法律规则；
7. 批准计算参数和正式情景；
8. 生成和修改文书；
9. 修复一致性阻断；
10. 锁定、导出和复核提交包；
11. 修改上游事实并确认旧提交包立即失效。
12. 在提交包已经导出后修改上游事实，确认 current 指针被原子清空、已导出包转为 `STALE` 且不能再次导出。

### 2.6 视觉与文档测试

- UI 参考设计与真实实现视觉回归；
- 1280、1440和更大桌面宽度；
- 长案件名、长法条、100笔交易和200页材料；
- PDF缩放、旋转、坐标和红框；
- DOCX在WPS/Word中的分页、字体、页眉页脚和表格；
- XLSX公式、金额、币种和打印区域；
- PDF页数、书签、文本层和渲染完整性；
- ZIP文件名、目录、可打开性和Manifest。

截图本身不是通过证明。需要按真实任务操作，并比较参考与实现。

### 2.7 安全测试

- 跨律所、跨团队、跨案件访问；
- `GLOBAL/FIRM/MATTER` 三种作用域的所有权、空 `matter_id` 白名单、跨作用域外键和可见性；
- 数据库 RLS、对象键/签名 URL、检索索引、队列、缓存、审计、导出和恢复工具的完整数据面越权；
- 越权审批和导出；
- 过期会话和已离职用户；
- Prompt Injection；
- 恶意PDF、宏、压缩炸弹和路径穿越；
- SSRF和网络出口；
- 重复点击、超时和任务重试；
- 模型未知提交；
- 日志和错误信息泄露；
- 数据删除和备份恢复。

## 3. 核心指标

### 证据

- 金标准相关页召回率目标 ≥99%；
- 精确重复页识别准确率目标 100%；
- 相似但不同页面不得自动排除；
- 正式事实来源覆盖率 100%；
- 红框坐标经真实渲染检查。

自动召回未达到100%的剩余风险由强制人工材料审核门承担，不能用模型置信度替代。

自动召回率只评价候选排序。每个原件必须生成覆盖全部页面的处置 Manifest；生成相关页派生件前，未审页面数量必须为零，排除页面也保留人工决定、理由和审计。关键主体、借据、法院文书和交易流水采用双人复核或预先定义的盲审抽检，试点出现决定性漏页即停止放行并扩大复核范围。

### 法律

- 正式引用官方来源可访问率 100%；
- 条文原文匹配率 100%；
- 有效期间和过渡规则校验率 100%；
- 正式法律命题的触发事件、适用规则和案件 `CaseLegalBundle` 覆盖率 100%；
- 正式法源快照有效许可覆盖率 100%；
- 无虚构引用；
- 三级线索来源不会成为正式依据。

### 计算

- 所有计算不变量 100% 通过；
- 与独立实现复算一致；
- 金额显式币种覆盖率 100%；
- 逐期结果可从批准参数重放；
- v1 正式计算币种仅人民币，非人民币输入阻断率 100%；
- 日期包含性、时区、同日事件、多债务分配和逐期舍入均由版本化规则决定；
- 跨文书金额一致性阻断为零。

### 文书与发布

- 未经批准事实进入正式文书数量为零；
- 姓名、角色、案号、法院、日期、金额、币种和代理权限冲突为零；
- 只有一个当前有效提交版；
- 原始证据覆盖数量为零；
- 未经律师终审导出法院提交版数量为零。
- `STALE`/`REVOKED` 提交包导出数量为零；
- 已导出包发生上游变化后仍保持 current 的数量为零；
- 文书直接编辑后复用旧批准数量为零。

### 用户价值

- 核心任务完成率 ≥80%，封闭试点后目标 ≥90%；
- 5 名测试律师（至少 3 名承办律师）使用同一合成案件和 9 项脚本；至少 4 名在 45 分钟内完成全部 6 项高风险任务和至少 8/9 总任务，无主持人提示、越权、误批或误导出；
- 律师材料整理和初稿时间降低 ≥50%；
- 第10案后单案内部人工逐步降至2小时以内；
- 至少3家律所/团队产生复购或明确复购意向。

安全指标和商业指标分别报告。节时、复购、案件数量或模型成功率不能抵消决定性漏证据、错身份、错法律版本、错金额、越权或恢复失败。

## 4. 发布环境

```text
Local：开发者脱敏样本
Test：自动化合成和金标准副本
Staging：授权脱敏或试点数据，接近生产配置
Production：真实案件，最严格权限和审计
```

环境之间禁止复制真实客户材料到低安全等级。生产数据不能进入开发日志、截图、公共错误追踪或AI编码上下文。

## 5. 持续集成门

每次合并：

- 格式、类型、依赖和秘密扫描；
- 单元和合同测试；
- 数据库迁移前后测试；
- 核心权限测试；
- 受影响金标准回归；
- 构建和SBOM。

涉及状态机、权限、计算、法律有效期、文件派生或导出的修改，需要指定代码评审人和额外回归。

## 6. 阶段复核模板

每个阶段结束必须回答：

1. 原计划交付物有哪些？
2. 哪些已完成并有何证据？
3. 哪些只完成配置或自动测试，尚未人工接受？
4. 发现了哪些真实问题？
5. 是否改变范围、风险或架构？
6. 是否需要更新计划或ADR？
7. 下一阶段唯一目标是什么？
8. 是否有更小、更可靠的实现方式？

复核完成后更新 `PLAN.md` 当前阶段，避免口头状态漂移。

## 7. 发布门

### 内部 Alpha

- 3个脱敏金标准案件端到端通过；
- 证据、法律、计算和文书来源链完整；
- 主要权限和审计可用；
- 关键UI通过内部任务测试；
- 不允许真实客户自助使用。

Phase 1 可用性门在 Phase 0 冻结参与角色、统一合成案件、任务脚本、时间上限、独立完成定义、观察表和失败规则。首测少于 4/5 通过时必须修订，并由至少 3 名未参加首测的目标律师重测；重测未全员通过不得进入生产应用初始化。

### 封闭 Pilot

- 执业律师批准业务规则和文书边界；
- 合同、隐私、安全和供应商流程完成；
- 备份恢复、事故响应和删除演练通过；
- 每案有人工交付负责人；
- 设置案件数量、页数、交易数量和模型成本上限。

### 商用 Beta

- 至少10个按首案由、材料页数和交易量预先分层的真实案件结果支持复用和回归；累计30案作为持续商业验证目标；
- 关键错误为零或均有阻断机制；
- 单案人工和模型成本可持续；
- 安全评估、渗透测试和运维值守完成；
- 产品适用边界、服务级别和责任划分清晰。

真实试点开始前冻结 cohort 纳入/排除条件、样本难度分层、同类历史人工基线或同案盲测方法，以及事实、引用、计算行和提交包各自的错误分母。复购、续用与付费意向作为独立商业看板，不作为绕过安全发布门的条件。

## 8. 故障与恢复

### 技术故障

OCR、渲染、网络、队列等可以有界重试。重试必须幂等，并保留失败产物和诊断。

### 语义故障

身份不明、付款性质不明、法律版本存在争议等，必须进入“待律师决定”，不得通过重复生成掩盖。

### 模型未知提交

若无法确认请求是否已被供应商受理：

- 停止自动重试；
- 保留请求ID、输入哈希和时间；
- 查询原任务状态；
- 只有确认未提交或经授权后才能再次调用。

### 恢复目标

- 已确认上传的原件、已锁定 Manifest 和高风险审计：`RPO = 0`，核心读取 `RTO ≤ 4小时`；成功响应前必须同时持久化对象、元数据和审计；
- 数据库普通案件状态和未锁定草稿：`RPO ≤ 15分钟，RTO ≤ 4小时`；
- 可重建派生件、全文和向量索引：`RPO ≤ 24小时，RTO ≤ 24小时`；
- 可以从输入快照和版本重放计算、文书与后台任务，旧版本结果不能重新成为 current；
- 完整恢复演练必须用 Manifest 核对数据库、对象、审批、审计和唯一 current bundle，检测孤儿文件并重建索引；
- 任何对账不一致均阻断恢复环境对外服务，演练结果和实测 RPO/RTO 进入发布记录。

## 9. 试点复盘

每个真实案件记录：

- 材料页数、交易数和异常类型；
- 原流程耗时和系统流程耗时；
- 自动结果和律师最终结果差异；
- 律师修改最多的模块；
- 漏证据、错身份、错金额、错法条和文书问题；
- 模型调用、失败、重试和成本；
- 哪些输出真实用于庭审或提交；
- 律师是否愿意复购和转介绍。
- cohort 分层、人工基线、每类错误分母和停止/恢复试点决定。

只有被律师真实使用的结果才算产品接受，不以生成成功或文件存在代替。
