# 离线开发模式（非律师正式入口）

这个启动方式用于开发、演示基础材料链和断网诊断，不是律所交付给律师的正式产品入口。它复用与完整服务完全相同的 Web 界面，但后端只有 SQLite 和本机受保护材料目录，因此界面会明确显示“离线开发模式”。

## 启动

在项目根目录运行：

```text
python3 scripts/start_local_web.py
```

启动器会等待后端和页面真正就绪，再打印并打开唯一入口。默认从
`http://127.0.0.1:33000` 开始选择空闲端口；如果该端口已被占用，会自动选择
后续空闲端口，必须以终端打印的地址为准。Windows、macOS、Linux 均使用同一入口；
不需要 Docker，也不需要配置 API Key。

如需固定端口，可设置 `LAWCASE_LOCAL_WEB_PORT` 和 `LAWCASE_LOCAL_API_PORT`。显式端口
已被占用时启动器会停止并说明原因，不会把其他产品的页面误报成律师工作台。

## 本机模式能力（含案件决策包）

- 建立和选择案件；
- 接收 PDF 与图片材料（图片走视觉 OCR 前会自动掩码银行卡号/手机号等标识符）；
- PDF 结构校验、SHA-256、页级记录和单页 PDF 预览；
- 页面纳入/排除、红框坐标记录和证据清单锁定；
- **确定性材料核对**：PDF 文本层的信号词、日期、金额候选，带来源页，秒级完成；
- **Agent 案件决策包**（需配置模型，见下）：案情立场、已确认事实（带来源页）、争点矩阵、
  对抗分析、策略选项、需要律师决定的问题、待律师确认清单；
- **正式数字**：由确定性引擎按律师确认的债务参数与司法保护上限计算，模型不参与计算；
- **案件计算参数**：在「决策包」页面直接填写（司法保护上限月利率、利息暂计截止日、
  每笔借款的本金/放款日/到期日/约定月利率、缺凭证挂起），仅保存参数或直接运行分析均可；
  参数改动后既有决策包自动标记为「已失效」，必须重新运行才能再次阅读或导出；
- 决策包导出 Markdown 与 Word；原始材料不可覆盖，材料目录与 SQLite 使用本机私有权限。

### 扫描件图像与标识符（默认 fail closed，律师可授权）

PDF 文本层里的身份证号/手机号/银行卡号在发送前自动掩码。**扫描件没有文本层**，只能把页面
渲染成图片发送，图片内部的号码无法在本机自动脱敏，因此：

- 默认（不勾选）一旦在 OCR 文本中检出完整标识符，分析立即阻断并提示「人工脱敏后重试，
  或在决策包页面勾选『扫描件图像原样发送』」；
- 勾选后继续运行，检出结果逐项写入报告「待律师确认清单」（含文件名、页码、掩码后的号码），
  门禁记为「含待律师确认项」；下游发送给模型的文本同步做了标识符掩码；
- 授权与检出结果随报告与运行记录保留，可追溯是哪一次分析、对哪一页做的授权。

注意：银行卡号识别使用 Luhn 校验，仍可能把银行流水里的 19 位凭证号识别为卡号（会出现在
待核清单里）。这是有意为之：宁可多报一条待核，也不静默发送未脱敏页面。

### 启用模型深度分析

默认**不调用任何外部模型**（避免未经配置就产生费用）。两种启用方式：

```text
python3 scripts/start_local_web.py --enable-model                    # 使用项目默认模型环境文件
python3 scripts/start_local_web.py --model-env-file /path/to/model.env
python3 scripts/start_local_web.py --model-env-file ... --budget-cny 2
```

未启用时点击「开始分析」走降级路径：完成材料导入与正式数字计算，并在报告中说明原因
（界面显示「未配置模型」）。启用后每次分析的成本上限默认为 2 元，超出即阻断并记账。

### 数据路径与纪律

- 每次分析写入 `preflight.json`（发送范围、供应商、地域、保留期、预算、确认人）与
  `request_ledger.json`（每次调用的载荷哈希、用量、费用），与案件数据同目录、同权限；
- 发送前自动掩码标识符；模型输出中的正式金额与百分比一律剔除并改为「见计算表」；
- 门禁三档：硬红线（声称已批准/已提交等）整份拒绝；格式问题自动修复；不确定内容进入
  「待律师确认清单」并放行——不因格式瑕疵丢弃整份分析；
- 材料一旦变化，既有分析结果标记为「已失效」，不得继续引用；
- 案件计算参数一旦变化，同理失效；两者共用同一套失效检查，报告与导出都会返回「已失效」。

## 明确未装配的能力

本机模式不冒充律所协作服务，也不自动生成法律结论。多人权限与并发、联网法律检索、长期
案件记忆、正式交易台账、利息净额测算（付款冲抵后）、法院提交包、签章与对外发送均未装配。

律师不应被要求“去另一个产品继续”。律所管理员启动完整受管服务后，律师仍访问同一套 Web 工作台；能力恢复状态在原案件首页显示。离线 SQLite 案件不会自动升级为律所受管案件，若确需迁移，必须另行实现带哈希和审计回执的管理员导入流程，不能静默复制。

正式数字当前为**不含付款冲抵的毛额**：付款性质与债务分配必须由律师确认后，才能计算净额。
没有文本层的扫描页在任何情况下都不得被称为「Agent 已完成」。

## 浏览器自检（会真的点页面，而不是只看构建结果）

只跑构建或只调 API 无法发现「页面点不开」「响应解析失败」这类缺陷——本机模式曾因此
长时间呈现「决策包尚未开放」而没人发现。自检脚本用真实 Chrome 走一遍关键路径：

```text
# 只读：打开决策包页面，核对状态、正式数字与导出按钮（不产生模型费用）
python3 scripts/browser_check_decision_package.py --case-id <案件ID>

# 真实运行：填写参数、授权扫描件、点击「开始分析」并等待终态，再核对导出
python3 scripts/browser_check_decision_package.py --case-id <案件ID> \
    --parameters /path/to/parameters.json --run --authorize-image-identifiers
```

脚本以服务端 `run_id` 变化确认「这次点击真的登记了新的一轮运行」，再等终态；未配置模型
的一轮只需几百毫秒，界面可能来不及显示「进行中」，因此不能只靠界面文案判断。未登记新运行时
会打印页面告警并立即失败，不会拿上一次的「分析完成」冒充本次结果。未配置模型的降级路径用
`--expect-status MODEL_NOT_CONFIGURED`。依赖 `playwright`（`python3 -m pip install --user playwright`），
复用本机已安装的 Chrome。

已用该脚本走通的路径（合成材料，无真实当事人信息）：空工作区建案 → 上传 PDF 与借条照片 →
填写计算参数 → 真实模型分析（`COMPLETED`）→ 导出 Markdown/Word → 追加材料后结果标记「已失效」；
以及未配置模型的降级路径（`MODEL_NOT_CONFIGURED`，仍产出正式数字与可导出报告）。


## 为什么生产模式需要更多服务

OIDC/MFA、PostgreSQL、私有对象存储、ClamAV、Poppler、LibreOffice 是服务器端的生产能力，不应由每位律师单独安装。律所管理员部署一次后，律师只需浏览器登录。它们分别负责身份和权限、多人并发台账、原件保存、病毒扫描、PDF 页面渲染和文书转换。
