# 离线开发模式（非律师正式入口）

这个启动方式用于开发、演示基础材料链和断网诊断，不是律所交付给律师的正式产品入口。它复用与完整服务完全相同的 Web 界面，但后端只有 SQLite 和本机受保护材料目录，因此界面会明确显示“离线开发模式”。

## 启动

在项目根目录运行：

```text
python3 scripts/start_local_web.py
```

启动器会等待后端和页面真正就绪，再打印并打开唯一入口。默认从
`http://127.0.0.1:33000` 开始选择空闲端口；如果该端口已被占用，会自动选择
后续空闲端口，必须以终端打印的地址为准。Windows、macOS、Linux 均使用同一入口；
不需要 Docker，也不需要配置 API Key。

如需固定端口，可设置 `LAWCASE_LOCAL_WEB_PORT` 和 `LAWCASE_LOCAL_API_PORT`。显式端口
已被占用时启动器会停止并说明原因，不会把其他产品的页面误报成律师工作台。

## 只用于验证的能力

- 建立和选择案件；
- 明确选择 PDF 并接收本机回执；
- PDF 结构校验、SHA-256、页级记录和单页 PDF 预览；
- 页面纳入/排除、红框坐标记录和证据清单锁定；
- PDF 文本层的确定性材料预处理；它只生成带来源页的核对候选，不是完整 Agent；
- 原始材料不可覆盖，材料目录和 SQLite 文件使用本机私有权限。

## 明确未装配的能力

离线开发模式不冒充律所协作服务，也不自动生成法律结论。完整办案 Agent、视觉/OCR、联网检索、长期案件记忆、正式事实和法律台账、利息测算、Word/Excel/PDF 提交包、多人权限均未装配。

律师不应被要求“去另一个产品继续”。律所管理员启动完整受管服务后，律师仍访问同一套 Web 工作台；能力恢复状态在原案件首页显示。离线 SQLite 案件不会自动升级为律所受管案件，若确需迁移，必须另行实现带哈希和审计回执的管理员导入流程，不能静默复制。

本地材料预处理不会调用 DeepSeek 或视觉/OCR。没有文本层的扫描页只会进入“需要
OCR”的异常队列；界面不得把该处理称为 Agent 已完成。

## 为什么生产模式需要更多服务

OIDC/MFA、PostgreSQL、私有对象存储、ClamAV、Poppler、LibreOffice 是服务器端的生产能力，不应由每位律师单独安装。律所管理员部署一次后，律师只需浏览器登录。它们分别负责身份和权限、多人并发台账、原件保存、病毒扫描、PDF 页面渲染和文书转换。
