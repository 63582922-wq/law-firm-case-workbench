# 交易台账与付款性质契约

状态：`内部合成 Alpha 领域契约；待真实律师流程验证`

本契约处理“流水记录了什么”和“该笔款在本案中应如何处理”之间的边界；它不决定个案付款当然属于本金、利息或其他款项。

## 1. 原始记录与律师决定分离

- 每条 `Transaction` 均保存原始金额、币种、日期精度、方向、渠道、交易参考号及原始证据的文件哈希/页码/区域。原始金额保留十进制精度，不会因为未来计算需要而改写。
- 交易记录先是 `CANDIDATE`，只有承办律师确认后才是 `CONFIRMED`；有误的记录标记 `INVALIDATED`，必须依据原始证据重建，不能原地篡改。
- 对方起诉材料、本方陈述、Agent 候选和助理录入产生不同的 `PaymentClassificationProposal`。这些候选可以并存，只有律师批准的一条可成为该交易当前有效分类。
- `PaymentNature` 仅保存经批准的处理类型：出借、未指定偿还、仅付利息、仅还本金、退款、手续费或与本案无关；不得由金额大小或摘要文字自动推定。

## 2. 多债务与同日顺序

- 与计算有关的分类必须用 `ObligationAllocation[]` 列明对应债务、金额和币种；所有分配额必须精确等于原交易全额，且同一债务在该笔交易中只能出现一次。
- 同日可能影响本金或利息的交易必须由律师指定正整数 `same_day_sequence`。没有序号只可保留为已批准分类，不能进入正式计算快照。
- v1 正式计算只接受精确日期和 `CNY` 分级，且金额/分配额必须精确到分。外币、月/年级日期或更高精度金额保留在台账中，进入“待律师处理”，不得静默换汇、取整或补日期。

## 3. 重复并非删除

- 系统可以提出 `DuplicateGroup` 候选，但不能因为金额、日期或交易号相似而删除任何原始交易记录。
- 律师只能明确选择“同一经济事件”并指定规范交易，或“不同交易”。
- 任一可能进入计算的交易仍处于重复候选状态时，构建计算快照必须阻断；认定为同一经济事件后，只让指定规范交易进入，避免双算。

## 4. 与计算引擎的受控映射

```text
DISBURSEMENT             -> DISBURSEMENT
REPAYMENT_UNSPECIFIED    -> PAYMENT + BY_POLICY
INTEREST_PAYMENT         -> PAYMENT + INTEREST_ONLY
PRINCIPAL_REPAYMENT      -> PAYMENT + PRINCIPAL_ONLY
```

`INTEREST_ONLY` 和 `PRINCIPAL_ONLY` 不会把付款余额自动挪到另一桶；余额保留为未适用金额。`BY_POLICY` 才可交给案件已批准的冲抵顺序处理。

构建 `TransactionCalculationSnapshot` 前，系统必须检查：交易和分类均已由律师确认/批准、原始证据存在、目标债务有分配额、币种和日期可计算、同日顺序唯一、以及所有重复组已得到可用结论。快照只提供给后续情景构建；它本身不是正式利息结论、法院提交材料或律师意见。
