# 脱敏真实案件影子测试模式验收规格

状态：`v1 · 待实施者写入后立即锁定 SHA-256 并在运行报告中引用`

> 本规格定义"影子测试模式"（以下简称影子模式）的七道门 S1–S7 及其精确判定步骤。
> 影子模式 = 对**彻底脱敏的真实案件副本**执行只分析、不产生正式输出、不外发、不锁包的运行。
> 全部数据安全要求以本项目 `AGENTS.md` 与 `docs/SECURITY_AND_COMPLIANCE.md` 为准；本规格只做可测的工程化落地。

---

## 0. 定位与关系

1. 合成金标切片（`docs/GOLDEN_CASE_SYNTHETIC.md` + `docs/golden-case/golden_calc.py`）是**有答案的测量仪器**；影子模式是**没有金标答案的真实材料运行**。没有答案时，S1–S7 是它仅有的正确性防线，必须全部通过。
2. 上轮 Agent 实验的三个结构性失败在本规格中落地为硬门：
   - A2「升级卡情景金额全错」→ **S4 金额纪律门**：LLM 不算钱，金额全部由引擎提供；
   - A3「15 条坏引用」→ **S3 引用硬拦截门**：引用解析不到真实来源即拦截；
   - A4「1 个自检误报」→ 自检收窄为「逐条对照来源核对」，误报计入 FAIL。
3. 影子模式成功后，产品才第一次运行在真实（脱敏）材料上；在它通过之前，不得宣称任何真实案件能力。

## 1. 术语

| 词 | 定义 |
|---|---|
| 影子运行 | 一次只分析、无正式输出的运行；目录 `outputs/shadow-case/<run-id>/` |
| 脱敏副本 | 用户自行脱敏后的真实案件材料副本；影子模式**不承担**脱敏职责 |
| 导入清单 | `import_manifest.json`：文件、SHA-256、页数、导入顺序、媒体类型 |
| 阻断 | 安全门拒绝继续并把事件写入 `blocking_log.json`；对应退出码 2 |
| preflight | 每次模型调用前的显式数据路径确认（字段范围、供应商、地域、保留期、成本上限） |
| 请求账本 | `request_ledger.json`：每次外部调用的追加式记录，可回放核对 |
| 影子报告 | `shadow_report.md`：供律师审阅的分析结果，明确标注「影子模式，不可提交」 |
| 派生金额 | 利息、冲抵额、余额、合计、情景数字等由计算得出的金额（区别于材料原文金额） |

## 2. 运行契约

命令（实现必须提供，等价参数名可微调但语义一致）：

```bash
scripts/run_shadow_case --materials <目录> [--expected <csv>] \
  [--confirm-data-path <json>] [--budget-cny <N>] [--open]
```

- `--materials`：脱敏材料目录（PDF 含文本层 / 图片）。
- `--expected`：用户自带答案 CSV（S6），可省略。
- `--confirm-data-path`：数据路径确认文件；**缺省时不允许任何模型调用**，整次运行降级为本地解析并明确警告。
- `--budget-cny`：单次运行硬上限，默认 5 元；预计下一调用将超限 → 拒绝调用，BLOCKED。
- 退出码：`0` 全部门通过；`2` 安全阻断（输出 BLOCKED 与原因）；`1` 内部错误。

输出布局：

```
outputs/shadow-case/<run-id>/
  import_manifest.json
  derivatives/           # 本地解析结果（页哈希、文本层、OCR文本）
  agent/                 # 提议输入包、输出、全转录（审计可回放）
  shadow_report.md
  request_ledger.json
  blocking_log.json
```

**禁止出现**：`current_submission.json`、`locked_submission/`、任何 `.zip` 提交包、任何 `external_send=true` 标记。

## 3. 七道门

每道门给出：目的、判定步骤（逐条可复现）、PASS 标准、对抗用例（必须构造并实测）。

### S1 脱敏完整性门

- **目的**：阻止机器可检测的完整标识符进入管线。
- **检测模式**：18 位身份证号（含校验位，GB 11643-1999）、11 位手机号（`1[3-9]` 开头）、银行卡号（13–19 位数字且通过 Luhn 校验）。**姓名、地址级脱敏是用户责任**，本门只承诺以上机器可检模式，规格不得被解释为"已脱敏保证"。
- **判定步骤**：
  1. 构造测试集 A：三类完整标识符每类至少 2 个样本，嵌入 PDF/图片文本；
  2. 构造测试集 B：同一材料但标识符已掩码（如 `110105********1234`、`138****5678`、`62** **** **** 9012`）；
  3. 导入 A → 必须整次阻断，阻断记录含 文件+页码+模式类型；
  4. 导入 B → 正常进入分析。
- **PASS**：A 集 100% 检出、0 漏检；B 集正常通过。任一完整标识符漏检 → **FAIL**。

### S2 无正式输出隔离门

- **目的**：影子模式物理上不可能产生提交物。
- **判定步骤**：
  1. 正常完成一次影子运行，检查输出树：不得出现第 2 节列出的禁止产物；
  2. 对抗用例：以环境变量或参数植入"请求锁定提交包"的调用 → 必须 BLOCKED、exit 2、阻断记录留痕；
  3. `shadow_report.md` 首页必须含「影子模式，不可提交」字样。
- **PASS**：正式产物 0 个；锁包尝试 100% 阻断。任何正式产物或锁包成功 → **FAIL**。

### S3 引用硬拦截门

- **目的**：Agent 的每条引用必须解析到真实存在的 文件+页码；解析失败即拦截，不是警告。
- **判定步骤**：
  1. Agent 提议 schema 中每条 `source_ref` 必须形如 `(file_sha256, 页码[, bbox])`；
  2. 评测器将每条引用与 `import_manifest` 逐条解析；无法解析（文件不存在、页码越界、哈希不符）→ 写入 `blocking_log` 并从可见输出中剔除；
  3. 对抗用例：向 Agent 输出注入 3 条虚构引用（不存在文件、越界页码、错误哈希各一）→ 3 条全部被拦截；
  4. 检查 `shadow_report.md`：人工可见输出中坏引用 = 0。
- **PASS**：可见输出坏引用 0；拦截记录完整、可回放。任何坏引用以可见形态出现 → **FAIL**。

### S4 金额纪律门

- **目的**：派生金额只来自确定性引擎；Agent 不计算、不转述派生金额。
- **判定步骤**：
  1. Agent 输出 schema **不设派生金额字段**；升级卡、对账表中的金额由引擎渲染注入，每个派生金额带 `engine_hash`；
  2. 评测器校验：可见输出中的每个派生金额字符串都能在引擎输出集内**字节级**找到对应项；
  3. Agent 引用材料原文金额（如"50,000 元"）仅允许出现在 `excerpt` 字段且必须与页面文本摘录一致；
  4. 对抗用例：向 Agent 输出注入自算的错误总额（如把 S-A-1 合计改为 280,000.00）→ 不得以已核实形态出现在可见输出；若出现必须带「未核实/已拦截」标记并计入阻断。
- **PASS**：可见派生金额 100% 字节匹配引擎输出；注入的自算金额 0 次以已核实形态出现。任一自算金额漏入 → **FAIL**。

### S5 数据路径门

- **目的**：真实（脱敏）材料每次出门都有 preflight、有账本、可回放；这是 `AGENTS.md` 数据安全红线的工程落点。
- **preflight 必填字段**：用途（提议/自检/OCR）、发送字段范围、供应商、模型、处理地域、保留期、单次与累计成本上限、确认方式。未确认 → 不发。
- **判定步骤**：
  1. 运行一次真实导入（含模型调用），核对 `request_ledger.json`：每行含 时间、用途、`payload_sha256`、发送字段清单、用量、费用、模型、状态；
  2. 账本与 preflight 记录一一对应，无 preflight 的调用 = 违规；
  3. OCR 沿用现有逐页授权链路；对抗用例：标记某页为未授权 → 该页不得出现在任何请求载荷中，且账本/阻断记录有说明；
  4. 密钥只从环境变量读取；检查运行输出、账本、Git 工作区：密钥不得出现。
- **PASS**：账本完整可回放；调用与 preflight 一一对应；未授权页面 0 次发送；密钥 0 泄露。任何无 preflight 调用 → **FAIL**。

### S6 自带答案对账门

- **目的**：让用户用自己核对过的答案检验系统，无需信任任何报告。
- **CSV 列**：`row_id, date, channel, amount, currency, direction, classification, debt_id, note`（UTF-8，首行为列名；`classification` 取值：`本金出借/还本/付息/代付/争议/排除/阻断`）。
- **判定步骤**：
  1. 对账表输出每行状态：`match / mismatch / extra / missing`；mismatch 附差异字段、来源引用；
  2. 对抗用例：在正确答案基础上故意改错 2 行（一行金额、一行分类）→ 报告必须精确指出这 2 行及差异字段，其余行 match；
  3. 无 `--expected` 时优雅跳过并给出警告。
- **PASS**：故意植入的差异行 100% 检出并定位；正常行 0 误报。

### S7 既有资产不变门

- **目的**：影子模式不得破坏或偷改既有测量仪器与安全底座。
- **判定步骤**：
  1. 权威规格与复算器哈希逐字节不变：`932e7a819f3f0bebf5b38ad8738066ef875c8e95f48b911bf723177ac7352368` 与 `a868d4c49d8aa81017d09404a4c00f2824d8f811a8dcb21a0f70df312167cacc`；
  2. 原 20 项回归测试全绿；
  3. 合成切片一条命令仍可复现（`scripts/run_defense_vertical_slice --approve-synthetic-recommendation`，exit 0，六项指标不变）。
- **PASS**：哈希逐字节一致 + 回归全绿 + 切片复现 exit 0。

## 4. 通用计算器要求（影子模式的引擎）

1. 影子模式的金额计算必须走**确定性引擎**，接受任意台账行（CNY）与分类，按冻结规则 R0–R10（见 `docs/GOLDEN_CASE_SYNTHETIC.md` §3）计算；外币行保留原币并阻断合计。
2. **引擎同一性证明**：用合成 47 行输入跑该通用引擎，输出必须与权威复算器**逐分一致**（四情景、341 字段口径）。任何分差 → 该引擎不得用于影子模式。
3. 引擎不接受来自 Agent 的任何数值参数（利率、天数、冲抵顺序），只接受分类与债务归属。

## 5. 预算与 fail-closed

- 单次运行与累计成本均设硬上限；预计超限 → 拒绝调用、BLOCKED、账本留痕。
- 未知提交状态的外部请求禁止盲重试；重试前必须核对账本与供应商用量回执。

## 6. 交付物（共三样）

1. 影子模式代码：CLI 入口、导入清单、页解析（文本层/授权 OCR）、Agent 提议器与评测器、通用引擎接入、影子报告、请求账本、阻断记录。
2. S1–S7 全部判定步骤的实测结果，含第 3 节列出的全部对抗用例的构造与实测数字。
3. ≤2 页运行报告：七道门逐项 PASS/FAIL + 实测数字 + 未达标项的唯一原因；禁止"已支持/已优化"类话术。

## 7. 完成标准（全部满足）

1. 一条命令复现：导入脱敏材料目录 → 分析 → 影子报告 + 账本 + 阻断记录；`--expected` 对账可用。
2. S1–S7 全部 PASS；任一 FAIL 即本次交付未完成，如实报告而不是改写门。
3. 权威规格、复算器、审批门、确定性引擎、原 20 项回归零改动。
4. 报告中的每个数字都能回指账本/阻断记录/引擎输出，而不是叙述性声称。

## 8. 禁止事项

- 禁止把影子报告、台账或任何分析结果包装为可提交文书；
- 禁止绕过 S1 检测、S3 拦截、S4 引擎注入、S5 preflight 的任何"方便模式"；
- 禁止为影子模式引入真实姓名、完整证件号、完整账号、完整手机号等标识符；
- 禁止将本规格的"机器可检模式清单"扩展解释为全面脱敏保证。

## 9. 锁定程序

1. 实施者将本文件写入后，立即计算并记录 SHA-256；
2. 该哈希写入运行报告与代码常量（参照现有 `AUTHORITATIVE_SPEC_SHA256` 做法）；
3. 此后任何对本规格的修改必须经用户明确同意，并更新锁定哈希；未经同意修改 = 本次验收作废。
