# 答辩状草稿（律师工作稿）

状态：`v1 · 本机模式已装配，真实调用已走通`

## 1. 这是什么，不是什么

**是**：按律师勾选的主张与态度、用确定性引擎的正式数字拼出的一份答辩状草稿，
带答辩请求、事实与理由分节、依据与数字来源、待律师确认清单，可导出 Markdown 与 Word。

**不是**：法律意见，也不是可直接提交法院的文书。文件头尾都写明「律师工作稿，
未经律师逐句复核不得提交法院」，也没有签章与提交动作。

## 2. 三层分工

| 层 | 负责 |
|---|---|
| 律师 | 勾选主张哪几项抗辩、对每项诉请的态度（不认可/部分认可/认可/不发表意见）、填写当事人与受理法院、登记可引用的法源、补充说明 |
| 代码 | 用律师选择 + 引擎正式数字拼装文书，并守住**数字只来自计算表或材料原文**、**法条只来自律师登记**两条线 |
| 模型 | 只写每节的论证文字：不写数字、不编法条、不声称已提交或已批准 |

## 3. 两道门禁

1. **数字**：模型文字里的金额与百分比，凡不在「引擎正式数字 ∪ 材料原文数字」白名单内的，
   一律替换为 `[见计算表]`，原文记入审计，并在待核清单逐条列出。
2. **法条**：正文里的 `《…》第…条` 必须能匹配到律师登记的法源，否则整段替换为
   `［依据待律师登记］`（连同条文号一起替换，避免留下悬空的「第X条」）。
   待核清单里保留模型原本引用的完整法条，便于律师判断它想引什么。

另沿用实用模式的硬红线：出现「我已批准 / 已提交法院 / 已锁定」等第一人称完成态，
整份草稿拒绝，不降级。

## 4. 数据路径

- 答辩状调用**不发送材料像素**，只发送律师选择、决策包报告与引擎数字；
  数据路径记录写在 `brief_preflight.json`，其中 `sent_fields.page_files` 为空数组，
  `trusted_authorities` 就是律师登记的法源；
- 每次调用写入 `brief_ledger.json`（载荷哈希、用量、费用）；
- 没有决策包报告时不调用模型，只产出确定性骨架，并在「待核清单」写明原因；
- 未配置模型（`start_local_web.py` 未带 `--enable-model`）同样只产出骨架。

## 5. 失效规则

草稿绑定三者：案件材料版本、案件计算参数哈希、生成时所用的分析运行编号。
再加上**律师选择本身**：任何一项变化都会让已生成的草稿标记为「已失效」，
阅读与导出都被拒绝（HTTP 422），必须重新生成。绝不把旧草稿当成新立场的结果。

## 6. 用法

浏览器：案件 → 决策包（填参数、跑一次分析）→ **答辩状** →
填写当事人 / 勾选主张 / 选择诉请态度 / 登记法源 → 「保存并生成草稿」→ 导出 Word。

命令行自检（只读，不产生费用）：

```text
python3 scripts/browser_check_decision_package.py --case-id <案件ID> --brief
```

## 7. 实测（合成材料，真实调用）

| 环节 | 结果 |
|---|---|
| 决策包分析 | `COMPLETED`，2 次调用 ¥0.0153 |
| 答辩状起草 | `COMPLETED`，1 次调用 ¥0.0087，门禁 `MARK_FOR_REVIEW` |
| 正文数字 | 答辩请求使用引擎数字（本金 30000.00、利息挂账 3660.00、截止 2025-01-01）；模型自算的「年化利率」被改为 `[见计算表]` |
| 付款冲抵 | 律师确认付款性质后，答辩请求直接引用净额（已付 X 元、冲抵后本金 Y、利息 Z）；未确认时只写原则性主张 |
| 正文法条 | 只有律师登记的第二十五条被保留 |
| 导出 | Markdown 3975 B、Word 38819 B |
| 改选择 | 立即标记「已失效」，导出按钮消失、导出接口 422 |

## 8. 当前边界

- 付款记录由律师在决策包页面逐笔录入并确认性质（编号/付款日/金额/性质/归属借款/备注）；
  引擎只接受「还本·付息·代付」，其余两类只登记不计算；
- 目前不自动从材料里抽取付款明细：候选金额的提取仍是模型提议，必须经律师逐笔确认；
- 文书不含证据目录编排与签章；「成果文件 / 法院提交包」仍属服务器模式；
- 法源登记是本页面内的律师手填清单，尚未接入律所法源库。
