# 本地案卷与受控研究架构

状态：`已冻结为合成 Alpha 的开发要求；真实案件接入、联网研究与对外部署仍须通过既有放行门`

## 一、对最终使用场景的理解

律师在自己的电脑上建立一个案件，并选择一个包含该案全部材料的文件夹。系统应在不改写该文件夹原件的前提下，识别材料、建立事实与证据索引、提出待确认问题、检索可验证的法规和公开裁判资料，并在律师批准后组织交付材料。

这个方向正确，但“本案文件夹”和“法律知识库”不能合并。前者可能包含身份证号、聊天、银行流水、送达材料、客户策略和非公开文件；后者是会随时间变更的公开法源、利率数据与裁判研究。把两者混合，会造成越权读取、联网泄露、法源版本混乱和引用无法复现。

## 二、三层数据边界

| 层 | 位置与内容 | 默认行为 | 能否联网 | 进入法院交付物的条件 |
|---|---|---|---|---|
| 本地案卷库 | 用户选择的单案件文件夹及其只读清单 | 只读扫描、文件哈希、派生件分离保存；绝不重命名、删除或覆盖原件 | 否；原件和原文不得自动上传 | 由律师逐项确认来源、相关性和版本 |
| 法律与公开研究库 | 本机版本化缓存的法规、LPR、官方案例元数据与来源快照 | 从受控来源下载并记录发布日期、效力/适用时间、URL、抓取时间、哈希和许可状态 | 仅通过受控研究网关 | 每个规则或案例必须有可打开的权威来源和适用时间说明 |
| 工作产物库 | 本机加密的提取结果、台账、规则卡、计算表、文书草稿、审计记录 | 只能从前两层引用；每次生成保留输入版本指纹 | 不直接向外发送案卷内容 | 经角色权限、事实/规则/文本批准、锁定和导出前检查 |

同一份文件不能同时被标记为“原始案卷”和“可提交的衍生件”。原始文件仅保全；红框、OCR、筛选 PDF、目录和答辩草稿都必须是可追溯的衍生对象。

## 三、用户可见的端到端流程

1. 律师创建案件，选择本机文件夹并看到权限说明；系统先建立候选盘点，展示文件清单、类型、哈希、新增/修改/移动/缺失与重复线索，主办律师确认后才替代正式只读范围。
2. 证据 Agent 在本机工作：材料归类、页级候选、重复页候选、金额/日期/主体提取；不因“相似”自动删除、不把 OCR 当事实。
3. 主 Agent 根据案件类型和已确认的争点，写出一个可编辑的“研究计划”，例如“民间借贷：利息约定、已付利息、本金冲抵、过渡规则、LPR 数据、诉请范围”。
4. 律师点击“开始公开研究”后，研究网关只发送脱敏问题和法律关键词，依次查阅允许来源；不得把当事人姓名、手机号、身份证号、账户、聊天原文或整份材料作为检索词/上传内容。
5. 法源 Agent 将每条结果转为规则卡：原文来源、制定机关、公布/施行/失效时间、条款定位、适用条件、反向条件、抓取快照哈希、引用文本范围和待律师确认项。
6. 裁判研究 Agent 只产生“研究参考卡”：法院层级、案号/公开链接、程序阶段、事实标签、争点、裁判要点、与本案相同/不同事实及公开可用性。公开裁判不是法源，不能自动变成规则。
7. 计算与文书 Agent 只能使用已批准的事实、规则卡和情景参数；每个数字可回溯到交易、日期、币种和规则版本。
8. 律师在提交前看到“引用包”：所有证据来源、法律依据、研究参考、未解决问题、版本变化和阻断项。只有锁定的唯一提交版可以生成交付文件。

## 四、受控公开研究网关

### 4.1 允许的第一层来源

- 国家法律法规数据库/全国人大系统：法律、行政法规和现行司法解释文本；
- 最高人民法院官网及《最高人民法院公报》：司法解释、指导性案例、典型案例、发布材料；
- 中国货币网/全国银行间同业拆借中心：LPR 历史数据与发布记录；
- 个案法院官网的依法公开裁判文书：只能作为裁判研究参考，并保存原始公开链接和取得时间。

第二层（学术文章、律所文章、新闻、聚合站）只能用于发现关键词和来源线索，不能直接作为最终法律依据。商业数据库可在取得律所账户、许可、地域与审计确认后作为补充连接器，不能绕过其授权或反爬规则。

### 4.2 网关硬约束

- 每个域名必须在管理员可见的白名单中；重定向后再次校验域名；
- 研究请求必须先经数据最小化和 PII 扫描；命中敏感字段时阻断并提示律师改写检索词；
- 外部请求在本地写入请求账本：调用者、目的、查询摘要、来源域名、时间、响应摘要、成本/次数和结果哈希；
- 抓取失败、来源不可达、来源版本冲突或未知请求状态时停止并标记“待人工处理”，绝不静默换来源、盲目重试或编造引用；
- 公共法源缓存按内容哈希和法源版本保存；任何规则变更都会使依赖它的规则卡、计算、文书和提交包失效；
- 第一版不向任何外部模型或搜索服务传输原始案件文件；若未来需 OCR/模型外包，必须另走逐次授权、字段范围、地域、保留期和成本上限确认。

## 五、民间借贷首案由的初始法源种子

下列条目是产品的“来源注册表种子”，不是对个案的自动结论。每次实际研究前必须重新取得官方文本并由律师确认适用。

| 主题 | 首选权威来源 | 产品必须记录的时间/条件 |
|---|---|---|
| 借款利息的基本规则 | 《中华人民共和国民法典》第 680 条 | 合同是否约定利息、约定是否明确、自然人之间、实际借款期间、适用时间 |
| 民间借贷司法解释（现行文本） | 国家法律法规数据库/最高人民法院公布的 2020 年第二次修正文 | 合同成立日、借贷行为日、原告起诉/法院新受理日、付款/返还日、个案是否请求适用过渡条款 |
| 利率保护上限及过渡 | 上述司法解释第 25—31 条及其修正决定的过渡条款 | 不能只保存“4 倍 LPR”口号；必须保存规则文本、合同成立/行为/起诉日期与分段期间 |
| 1 年期 LPR | 全国银行间同业拆借中心的 LPR 历史数据下载页 | 发布日期、1 年期值、下载时间、原始文件哈希；禁止由模型记忆填值 |
| 已付利息、本金冲抵、预扣利息等 | 司法解释相关条文 + 公开裁判研究卡 | 每笔支付的时间、币种、支付性质、当事人主张、证据强度和律师决定；系统只生成不同情景，不替律师定性 |

特别是利息计算必须由确定性规则引擎执行，不得让模型从文本“猜一个年利率”。对 2020 年前后的民间借贷，系统要将过渡规则编码为可审阅的候选规则与分段结果，而不是把“合同签订时 4 倍 LPR”或“起诉时 4 倍 LPR”其中之一硬编码为所有案件的唯一答案。

## 六、部署到律师电脑的形态

第一版应是“本机优先”的桌面应用或本机服务，而不是把文件夹同步到云端：

- 律师选择案卷根目录；应用只申请该目录的最小权限，并显示可随时撤销的授权；
- 原件留在该目录；本机受管的应用数据目录保存加密索引、哈希、衍生件和审计记录；
- 公共研究库与案件库分开加密、分开备份、分开保留/删除；
- 网络关闭时仍能处理本地材料，公开研究模块明确显示“离线/来源可能过期”，不伪装为完成；
- 律所管理员配置白名单、代理、更新窗口、备份与恢复；普通用户不能关闭审计、改变来源等级或越过导出审批；
- 跨电脑协作不是“共享文件夹”即可完成，必须等后续加上律所级身份、加密同步、租户隔离、冲突处理和可恢复审计。

当前合成 Alpha 已接通上述第一步的正式边界：短时授权内完成只读扫描，绝对路径不落库；数据库保存不可静默删除的版本化相对路径快照。重新扫描只生成候选差异，不自动扩大或缩小正式案卷范围；主办律师批准后，旧范围及其下游证据 Manifest、派生件和提交包失效。已批准范围向原件登记/解析 Worker 的批量导入仍是下一工作包。

## 七、开发顺序与放行门

1. 本地文件夹连接器：只读清单、哈希、类型检测、增量差异、候选范围与主办律师批准；
2. 案件资源模型：原件、页级对象、衍生件、来源关系、版本失效；
3. 公开研究网关：白名单、脱敏、请求账本、缓存、来源卡与离线降级；
4. 法源版本库：法规/司法解释/LPR 的来源注册、时间锚点和内容哈希；
5. 裁判研究卡：公开性、层级、事实差异与“仅供研究”语义；
6. 规则/计算/文书依赖图：上游变化自动使下游变为失效；
7. 桌面封装、加密、备份恢复、权限和真实律师试点。

真实案件文件夹、联网研究和可向法院提交的交付物，必须分别通过律师/安全负责人验收。完成合成开发、来源采集或自动化测试都不等于获得这些权限。
