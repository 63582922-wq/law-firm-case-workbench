# 律师办案 Agent OS 产品架构

版本日期：2026-08-15  
状态：目标架构基线；任何新功能必须说明它位于本架构的哪一层，并证明已接入真实执行闭环

## 1. 什么才叫本产品的 Agent

本产品不是聊天机器人，也不是在固定流程上增加几个“AI 分析”按钮。律师给出办案目标和材料后，系统应当能够持续完成以下闭环：

```text
理解目标与授权范围
→ 观察案件、材料、程序事件和现有成果
→ 建立当前案件状态
→ 识别缺口、风险和需要检索的问题
→ 生成可执行的动态任务图
→ 选择受控 Skill、联网工具或命令沙箱执行
→ 读取回执并更新短期/长期记忆
→ 根据新结果继续、重试、改道或重规划
→ 独立校验来源、数字、文书和交付完整性
→ 只把真正需要法律判断或授权的事项交给律师
→ 形成可编辑、可追溯、可恢复的成果
```

“像 Codex”指的是这种目标驱动、能使用工具、能持续推进并交付成果的工作方式，不是把整台服务器、所有案件和所有网络权限交给模型。法律产品必须比通用开发 Agent 多四条硬约束：证据来源、法律时态、律师权限和最终专业判断。

## 2. 完整能力模型

### 2.1 目标理解与案件情境

- 律师可以用自然语言说明目标、期限、已知争议和限制，不需要先填完所有结构化表单；
- Agent 从材料中提出案件类型、程序阶段、当事人地位、诉请和代理范围候选，但不得自行确认；
- 同一主体在不同程序实例中的原告、被告、上诉人、被上诉人、执行申请人等地位分开保存；
- 代理地位只是研判输入，不直接映射固定材料或固定文书；
- 律师更正事实、目标或代理地位后，Agent 能识别受影响任务并增量重规划。

### 2.2 多模态、常见文件和未知文件处理

“任意文件”不能理解为盲目执行任意二进制。产品应采用**文件能力注册表 + 可扩展解析器**：先识别真实类型、隔离和扫描，再选择解析 Skill；不能安全处理时说明原因并进入异常队列。

首个商用范围必须覆盖：

| 类别 | 文件 | 能力 |
|---|---|---|
| PDF/OFD | 文本 PDF、扫描 PDF、OFD | 结构检查、逐页文本、渲染、OCR、表格、页坐标、签名状态提示 |
| 图片 | JPEG、PNG、HEIC、TIFF、BMP、WebP | OCR、版面/表格、聊天与转账截图区域、时间金额候选、质量/涂改风险提示 |
| Office/WPS | DOCX、XLSX、PPTX 及可安全转换格式 | 文本、段落、批注、修订、公式/表格、工作表、隐藏行列、渲染预览 |
| 文本与数据 | TXT、MD、CSV、TSV、JSON、XML、HTML | 编码识别、结构提取、表格和字段候选 |
| 邮件 | EML，后续受控支持 MSG | 正文、头部、附件、时间与收发件关系 |
| 压缩包 | ZIP，后续按需支持 7z/RAR | 病毒扫描、炸弹/路径穿越限制、受控解包、子文件逐项登记 |
| 音视频 | MP3、WAV、M4A、MP4、MOV 等 | 元数据、语音转写、时间戳、抽帧；不得自动断言说话人或真实性 |

加密文件、宏、可执行文件、磁盘镜像、损坏文件和未知格式默认隔离，Agent 只能请求密码、替代格式或管理员批准的专用解析器，绝不执行其中代码。所有提取结果都回链至原文件、页码/时间戳、坐标框、解析器版本和内容哈希。视觉模型可以提示印章、签名、涂改、模糊或截图拼接风险，但不能认定证据真伪。

### 2.3 环境观察与案件状态模型

- 以服务器正式台账和对象库为事实源，建立可版本化 `CaseStateSnapshot`；
- 快照包含材料、主体/代理/程序、事实、诉请、争点、交易、期限、法源、计算、计划、文书和未解决冲突；
- 上传、律师决定、法院事件、法源更新、Worker 回执和权限变化都成为事件；
- Agent 只观察当前律师有权访问的对象，不通过提示词或模型记忆猜测状态；
- 上游变化自动使下游任务、计算、文书和提交包失效或进入待复核。

### 2.4 动态规划与重规划

- 总控根据目标和案件快照生成有依赖关系的任务 DAG，不是按原告/被告套固定流程；
- 每个任务包含目的、输入引用、前置条件、Skill、风险等级、费用/时间预算、审批门、验收器和失败策略；
- 模型可以提议计划，代码编译器只接受已注册、当前可执行且权限满足的任务；
- 任务结果、材料变化、法源失效、工具失败或律师更正都会触发局部重规划；
- 没有依据时生成“待补材料/待研究/待律师判断”，不能伪装成确定任务或法律结论。

### 2.5 工具选择与 Skill 执行

Agent 必须能够实际调用而不仅是展示以下 Skill：

- 文件识别、解包、PDF/OFD、图片视觉/OCR、Office、邮件、音视频；
- 证据去重、分类、关联、红框、页级派生和证据目录；
- 主体、事实、诉请、争点、交易和时间线候选；
- 官方法源检索、网页抓取、版本/效力核对、案例研究；
- 确定性利息计算、逐笔冲抵和独立复算；
- DOCX/XLSX/PDF 草拟、渲染、比较和一致性审查；
- 提交清单检查和成果打包。

Skill 必须具有类型化输入输出、版本、执行适配器、权限范围、资源上限、审批门、幂等键和稳定回执。注册表中“存在名称”不能算实现；只有运行时装配并通过真实适配器预检的 Skill 才能暴露给规划器。

### 2.6 受控命令执行

需要命令能力，但不能提供宿主机无限 Shell。每个任务在一次性案件沙箱中运行：

- rootless 容器或更强隔离运行时；只挂载该任务获准的案卷副本为只读，并提供独立临时输出目录；
- 只读根文件系统、非 root 用户、无宿主机目录、无 Docker socket、无服务器密钥、无其他案件；
- 默认断网；按任务通过出站代理放行精确域名、方法、次数、字节和期限；
- 命令来自已签名工具镜像和参数化模板。模型可以选择工具和参数，不能提交任意 Shell 字符串；
- 限制 CPU、内存、磁盘、进程数、时长和输出大小；禁用提权、设备、内核能力和持久后台进程；
- 输出重新扫描并只写入受管派生区；每次运行保存镜像摘要、命令模板版本、输入/输出哈希和退出回执。

对确实需要自由代码分析的高级模式，可允许模型生成脚本，但仍在上述无密钥、无宿主、默认断网的一次性沙箱中执行，并在执行前做策略检查。律师 Web 页面永远不能直接取得终端或宿主 Shell。

### 2.7 受控联网、搜索与浏览

- Agent 可搜索公开互联网以发现线索，也可使用专用官方法源连接器；
- 正式法律依据优先来自国家法律法规数据库、最高人民法院、人民法院案例库、受理法院及其他登记的官方来源；普通网页只能作为研究线索；
- 查询先最小化和脱敏，不把当事人姓名、身份证、账户、聊天原文或整卷材料直接发给搜索引擎；
- 浏览器内容、网页脚本和下载文件均视为不可信输入，不得把网页中的指令当系统命令；
- 保存查询、URL、重定向链、抓取时间、原文快照、公布/施行/失效信息、哈希、来源等级和许可状态；
- 登录型数据库或 MCP 连接器只能由管理员登记，按案件和用途授权，不能让浏览器或模型传入任意连接地址。

### 2.8 模型路由与推理

- 代码根据任务选择文本模型、视觉模型、OCR 或本地确定性工具；模型不能自行选择未批准供应商；
- DeepSeek 等文本模型用于结构化抽取、问题分解、候选计划、研究摘要和草稿；视觉/OCR 模型用于页/图理解；
- 每次外部调用绑定案件、输入对象、用途、模型版本、地区、保留政策、预算和律师/律所授权；
- 模型输出必须符合严格 schema，并经过来源、枚举、页码、引用、时态和冲突校验；
- 法律效力、正式金额和最终批准永远由法源台账、确定性代码和律师决定，不由模型记忆决定。

### 2.9 短期记忆、长期记忆与 RAG

需要六类分开的记忆，而不是一个聊天历史：

1. **工作记忆**：当前任务上下文、工具回执和未解决问题；有令牌/时间上限；
2. **运行记忆**：事件、计划版本、尝试、失败、恢复点和律师反馈，用于重启后继续；
3. **案件长期记忆**：本案已确认台账、证据、法源、计算、计划和文书版本；
4. **律师个人记忆**：经律师主动保存的写作偏好、研究笔记、模板和匿名范例；
5. **律所知识库**：知识管理员批准的 SOP、模板、办案要点和匿名化成果；
6. **公共法律知识库**：官方原文、时态规则、案例元数据和官方利率数据。

RAG 必须先做权限和有效期过滤，再检索：

```text
律所/律师/案件/权限/保密/保留状态硬过滤
→ 案件类型/程序阶段/时间效力/来源等级过滤
→ 条号、关键词、全文、结构化字段和向量混合召回
→ 按法律位阶、时效、来源质量和事实匹配重排
→ 返回原对象、页/段、版本、哈希和引用理由
```

“先过滤”是数据库执行顺序，不是在向量分数算完后由应用层再删结果。每次检索都要在同一受 RLS 保护的事务中重新核对律师、案件、权限组、ethical wall 和当前授权版本；工作记忆还必须精确绑定律师、Agent run 和任务。

法律检索使用双时态：`legal_valid_period` 表示法律对争议事实所在期间是否有效，`knowledge_as_of` 表示系统当时已取得和核验的版本。案件类型、程序阶段、法域、法律效力期等由任务明确为硬过滤；争点语义可作软匹配，但不得代替法律适用性判断。

向量索引只是可删除、可重建的加速层，不是事实源。过往案件不会自动跨案进入知识库；必须经过选择、冲突/保密检查、脱敏、律师批准和发布范围设定。跨案检索只引用独立的脱敏派生知识对象；原案页码、对象标识和 lineage 单独加密保留给受权审计，不返回普通检索结果。撤权、删除、法源失效或原对象更新要先写入 deny/tombstone 屏障，再异步撤销索引与缓存，并使依赖结果失效。供应商聊天记录或模型缓存不能充当长期记忆。

查询本身也可能包含客户秘密。嵌入优先使用律所受管的本地或私有服务；任何外部嵌入/重排同样必须经过外发账本、字段最小化、地域/保留政策、成本和授权门。

### 2.10 自主等级与人类审批

| 等级 | Agent 可做 | 典型动作 |
|---|---|---|
| A0 观察 | 自动、只读 | 盘点、格式识别、状态核对 |
| A1 提议 | 自动产生候选 | 分类、抽取、研究问题、任务计划 |
| A2 内部可逆执行 | 在预算和策略内自动 | OCR、渲染、检索官方来源、生成候选文书、质量检查 |
| A3 律师批准后执行 | 必须明确确认 | 正式事实/交易、法律口径、计算参数、立场文书、数据外发 |
| A4 禁止自动化 | Agent 永不执行 | 代表律师提交法院、签章、发函、和解、付款、删除原件或改变权限 |

律师审批应聚焦冲突、低置信度、法律判断和不可逆事项。高置信、低风险、同类候选可以按批次确认；批准必须显示影响范围、依据和可撤销边界。

### 2.11 持久执行、恢复与主动协作

- 总控、任务、依赖、租约、外部请求和工具回执全部持久化；网页关闭或 Worker 重启后能继续；
- 已知未提交的安全任务可按策略重试；外部结果不明时禁止自动重试，转入核验任务；
- Agent 只在缺少授权、法律选择、冲突证据或不可恢复外部状态时暂停；
- 律师可以暂停、取消、修正目标、限定范围和恢复；取消不会删除已产生的审计和原件；
- 前台持续显示“当前在做什么、为什么做、已完成什么、下一步是什么、需要律师决定什么、生成了哪些成果”，而不是只显示聊天气泡或转圈。

### 2.12 自校验、对抗审查和成果交付

- 每个任务都有独立验收器；模型不能自己宣布自己的结果正确；
- 事实候选核对原页，法源核对官方快照和有效期，数字由独立引擎复算，文书做字段/引用/版本/空缺一致性检查；
- 高风险成果可进入第二模型或规则审查，但审查器同样只产生问题清单，不能自动批准；
- 最终交付包括可编辑 DOCX、XLSX、可视 PDF、证据目录、计算说明、来源清单、未决问题和版本回执；
- 任一上游对象变化都会使依赖成果标为过期，不能继续显示为可提交。

### 2.13 安全、合规、运维和评测

- OIDC/MFA、服务端案件角色、PostgreSQL FORCE RLS、私有对象库、密钥管理、加密、审计和保留/删除/法律保全；
- 文档提示注入、恶意 PDF/Office、ZIP 炸弹、SSRF、命令逃逸、跨租户、模型数据外泄和日志泄密专项防护；
- 成本、延迟、失败率、人工修改率、来源命中率、低置信度召回和跨案隔离可观测；
- 用匿名真实案件建立场景评测集，衡量遗漏、误提取、错误法源、错误期间、错误文书和律师节省的操作量；
- 单测、页面可打开、模型返回成功都不是商用证明。必须完成真实身份、数据库、对象库、模型、Worker、恢复、浏览器矩阵和律师全案验收。

## 3. 当前项目与目标的差距

### 3.1 能力成熟度口径

本项目只用下列五级表述能力，避免把“写了合同”、“单测通过”或“页面有入口”写成律师已经可以使用：

| 级别 | 含义 | 能否向律师宣称可用 |
|---|---|---|
| `DESIGNED` | 只有架构、数据模型或安全合同 | 不能 |
| `IMPLEMENTED` | 有可运行内核和聚焦测试 | 不能 |
| `WIRED` | 已被生产组合根和独立 Worker 装配 | 仅可称内部 Alpha |
| `PROVEN` | 真实 PostgreSQL、对象库、模型/工具与重启恢复验收通过 | 可封闭试用 |
| `RELEASED` | 权限、攻击、备份恢复、浏览器矩阵及律师匿名全案验收完整 | 才能商用放行 |

任何 Skill 还必须同时通过“内核实现、运行时适配器、服务端权限与输入绑定、候选暂存、独立验收器、持久 Worker 恢复”六道门。少任何一道，规划器都不得看到该 Skill。

| 能力 | 当前事实 | 结论 |
|---|---|---|
| Web 身份、案件、RLS、对象存储边界 | 已有较强代码底座，真实生产环境尚未接通 | 部分具备 |
| PDF 上传、页预览、证据决定、红框/派生 | 已有多条内核/API/UI，运行时与完整真实验收未闭合 | 部分具备 |
| Agent 材料分析 | PDF 文本页投影、候选暂存、独立回读校验、Web 成果面和生产 Worker 组合已接线；视觉、研究、台账提取等外部能力按服务器配置动态加入目录 | 代码级 `WIRED`；真实对象库、模型与匿名案卷执行尚未 `PROVEN` |
| 代理档案 | 不可变 PostgreSQL 领域模型、Web 查看/主办确认或更新、协办只读及 Agent 启动门已接线；只有 `CURRENT` 档案可进入规划 | `WIRED`；尚无真实律师浏览器与生产数据库记录 |

## 4. 目标技术架构

```text
律师 Web 工作台
  ├─ 目标 / 当前进度 / 决定箱 / 成果 / 历史
  └─ 只提交业务意图、授权和律师决定

Agent Control Plane（代码总控）
  ├─ Goal Service
  ├─ Case Snapshot Builder
  ├─ Planner + Plan Compiler
  ├─ Event Reducer / Replanner
  ├─ Policy / Budget / Approval Engine
  ├─ Task DAG Scheduler + Durable Queue + Reaper
  └─ Result Verifier / Artifact Registrar

Agent Intelligence Plane
  ├─ 文本/视觉模型路由
  ├─ 结构化材料理解
  ├─ 动态案件计划
  ├─ 法律研究与文书候选
  └─ 只返回 schema 约束的候选或下一步建议

Skill Execution Plane
  ├─ 文件与多模态解析 Workers
  ├─ 官方检索 / 受控浏览 Workers
  ├─ 案件隔离命令沙箱
  ├─ 确定性计算与验证器
  └─ Office/PDF 文书与交付 Workers

Memory & Knowledge Plane
  ├─ Run Event Store / Checkpoints
  ├─ Case Ledgers / Object Store
  ├─ Personal/Firm Knowledge Publishing
  ├─ Public Temporal Legal Graph
  └─ ACL-first Hybrid Retrieval + Citations

Governance Plane
  ├─ OIDC/MFA/RLS/Object ACL/Secrets
  ├─ External request & cost ledger
  ├─ Audit/retention/legal hold
  └─ Evaluation/monitoring/recovery evidence
```

总控必须是代码，不是主模型。模型负责解释、提议和生成结构化候选；代码决定当前状态、能调用哪些工具、何时暂停、哪些结果失效、是否允许重试和是否具备交付条件。

## 5. 接下来固定执行顺序

1. **统一 Agent 控制平面**：目标、事件、案件快照、任务 DAG、状态归约、审批门、持久队列、恢复和结果回执；把现有材料 Run、动态计划和各 Worker 接成同一条链。
2. **通用文件与沙箱执行平面**：真实类型注册表、PDF/图片/Office/文本/邮件/压缩包首批适配器、一次性命令沙箱和输出登记。
3. **联网与法源平面**：搜索、受控浏览、官方来源抓取、快照、时态/效力检查和研究引用。
4. **记忆与 RAG**：运行记忆、案件检索、个人/律所知识发布、公共法源索引、ACL-first 混合检索和删除失效链。
5. **案件推理与成果链**：材料候选→事实/交易→动态计划→法源→确定性计算→文书→验证→提交包。
6. **统一律师 Agent 工作台**：律师只看目标、实时进度、异常/决定、依据和成果；支持暂停、纠正、恢复和继续。
7. **真实商用放行**：生产同构环境、模型/数据库/对象库/Worker、攻击与恢复、跨浏览器和匿名真实案件验收。

第一条产品级验收不是“按钮能分析 PDF”，而是：律师上传包含 PDF、图片和 Office 的匿名混合案卷并给出一个办案目标；Agent 自动盘点、解析、提出代理/程序候选、识别材料缺口、生成动态计划、检索并引用官方法源、形成来源绑定的事实/交易候选和成果草稿；律师主要处理异常与法律决定；进程重启后能继续；每项结论和文件都可追溯，未授权网络/命令/跨案访问全部失败。
