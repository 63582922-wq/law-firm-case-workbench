# 交付清单与应诉材料包

状态：`v1 · 本机模式已装配，合成木业买卖合同纠纷真实案卷已跑通`

## 1. 为什么要有这一页

律师要交出去的从来不是"一份分析报告"，而是一整套东西：哪些递法院、哪些必须当事人
本人签字、哪些只是内部工作件。漏签一份送达地址确认书，可能直接导致缺席风险。
所以本页把**交付物清单化**，并让签字文件按案件信息自动成文、事实部分一律留空。

## 2. 交付清单（按去向分三组）

**一、需要当事人签字（未签字不得提交）**：授权委托书、送达地址确认书、
当事人陈述（事实经过）、证据来源说明、调解意见确认、民事答辩状、上诉状。

**二、律师/律所署名**：证据目录、证据材料（副本）、质证意见、申请书
（追加当事人/调查取证/鉴定/延期举证）、代理词。

**三、内部工作件**：案件分析决策包、收付款与余额核对表、期限与开庭提示。

每项都有：去向、署名人、是否需当事人签字、当前状态（未开始／起草中／
待当事人签字／已签字／已提交／不适用）、说明。状态由律师逐项维护。

## 3. 签字文件模板（系统只搭架子，不写事实）

| 文件 | 系统生成什么 | 明确留空什么 |
|---|---|---|
| 授权委托书 | 当事人/受托人信息、一般代理与特别授权选项、期限条款 | **权限勾选**、特别授权逐项写明的范围 |
| 送达地址确认书 | 主体信息表、法律后果告知条款 | 邮箱、微信等电子送达方式 |
| 当事人陈述 | 四个部分（主体身份／交易经过／付款情况／争议事实）的提问式骨架 | **全部事实答案**（并写明"不清楚的写不清楚"，提示虚假陈述责任） |
| 证据来源说明 | 按本案已入卷材料列出表格 + 电子数据专项说明 | 来源、原始载体、提取方式、保管情况 |
| 证据目录 | 序号／证据名称／页数自动填，来源与证明内容留空 | **证明内容**（系统不替律师证明什么） |
| 调解意见确认 | 是否同意调解的选项、授权范围条款 | 金额底线、付款方式、其他条件 |

## 4. 应诉材料包（一键导出 Word／Markdown）

内容顺序：封面信息 → 交付清单（三组，带签字标记）→ 六份签字文件与证据目录 →
**附：民事答辩状草稿**（若已在「答辩状」页生成）→ 提交前检查清单。

导出的是 `.docx`（同一个 python-docx 渲染器，无外部服务依赖）与 `.md`。

## 5. 数据与纪律

- 主体信息（当事人、法院、案号、案由、承办律师）**一次录入，答辩状与签字文件共用**；
  首次进入交付清单页时会用答辩状页面已填的主体信息回填，避免重复劳动；
- 交付清单状态、主体信息存在本机 SQLite（`deliverable_states`），不进 Git、不外发；
- 应诉材料包导出**不调用任何模型**（纯渲染），因此不产生费用、也不存在外发风险；
- 系统不代当事人签名、不代当事人陈述事实；模板里所有事实位都留`【待填】`。

## 7. 当前边界

- 质证意见、代理词、申请书目前是**状态占位**，不生成正文（下一步可做模板）；
- 证据目录的"证明内容"必须律师填；系统不判断某份证据能证明什么；
- 买卖合同等非借贷案由的**正式数字口径尚未接入**（本机引擎目前只有民间借贷
  LPR×4 与冲抵口径），所以这类案子的材料包不含金额计算结论；
- 不含电子签章、不含法院提交包（.zip）与在线提交。
