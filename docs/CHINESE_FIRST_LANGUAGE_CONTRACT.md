# 简体中文优先语言契约

状态：`Phase 0 技术与产品契约；待 Phase 1 中文可用性测试验证`

## 1. 目的和边界

本产品首版服务中国大陆律所处理民间借贷一审应诉。默认操作语言、审批提示、审计说明、模板字段名和交付文书均为简体中文（`zh-CN`）。

这是一项可测试的产品要求，不是把英文界面逐字翻译。它不改变原始证据、法源原文或律师已经批准的文字；更不授权系统擅自推断姓名、案由、币种、日期或付款性质。

## 2. 不可改变的原始内容

下列内容必须以原始文件或原始抽取值保存，并显示其证据位置：

| 内容 | 保存与显示规则 | 禁止行为 |
|---|---|---|
| PDF 原件、图片原件、文件名、SHA-256 | 原字节不可变；派生件记录来源哈希和页码 | 翻译、覆盖、重写原件 |
| 聊天、转账备注、昵称、姓名、账号、案号 | 保存原始字符串；任何规范化值均另存并保留来源 | 简繁转换、拼音化、纠错后替换原值 |
| OCR 文本 | 原始 OCR 输出和结构化提取分开保存 | 把模型修正文本当作原始 OCR |
| 法源及法院文书引文 | 保存官方来源原文、链接、效力日期和引用定位 | 把摘要或二手说法当作法源原文 |

异体、昵称近似、错别字和可能的 OCR 误读只能形成“待确认映射”候选，并由律师审批。它们不能驱动自动去重、金额冲抵、文书表述或提交包。

## 3. 数据码与中文显示层

数据库、API 和规则引擎可使用稳定的机器码；界面、导出目录和面向律师的提示不得直接显示裸机器码。

| 机器码 | 简体中文显示 | 律师可见含义 |
|---|---|---|
| `CANDIDATE` | 待确认 | 系统或助理提出，尚未形成案件事实 |
| `CONFIRMED` | 已确认 | 有权限律师确认，可用于后续审阅 |
| `LOCKED` | 已锁定 | 进入指定提交版本，修改会产生新版本并使下游失效 |
| `INVALIDATED` | 已失效 | 上游材料、事实、规则或计算变化，不能用于正式输出 |
| `BLOCKED` | 已阻断 | 缺少权限、审批、证据、规则或必要字段，必须先处理 |
| `SIMILAR_REVIEW_REQUIRED` | 名称近似，需人工复核 | 不得因近似姓名自动纳入或排除 |
| `IN_SCOPE_CANDIDATE` | 相关页候选 | 仅表示命中筛选条件，仍须确认相关性 |

日志和诊断页面可在“技术详情”中同时显示机器码与中文标签，但默认界面先显示中文含义、证据位置、影响范围和下一步操作。

## 4. 中国大陆法律工作格式

### 4.1 时区与日期

- 所有可计算时间一律以中国标准时间 `Asia/Shanghai` 保存和解释；
- 规则引擎、排序和对账使用 ISO 日期/时间值，不使用模糊的“上周五”“昨天”等相对时间；
- 中文阅读视图默认展示为 `2026年8月9日`；表格、计算说明、交易台账和证据定位使用 `2026-08-09`，以利逐行复算；
- 原始证据中出现的日期格式按原样保留；解析失败或存在多种合理解释时必须阻断并请求律师确认。

### 4.2 金额与币种

- 规则引擎正式金额字段必须同时保存 ISO 4217 代码和原始显示值；v1 只有 `CNY` 可进入正式利息或冲抵计算；
- 面向律师的中文界面和文书默认显示为 `人民币 100.00 元`；金额不得仅显示数字；
- 原始材料中的 `￥`、`¥`、`CNY`、`人民币` 或其他写法保持原始值，并另存律师确认后的币种映射；
- 外币记录可以入库、显示和引用，但必须显示原币种，并阻断正式计算、合计和提交包锁定；
- 除非经模板/律师明确要求，系统不得把阿拉伯数字自动改写为中文大写金额。任何大写金额都必须由同一已批准金额源生成并可复算。

### 4.3 主体、角色和文书称谓

- 角色、姓名、别名和称谓分开存储；“原告”“被告”“委托代理人”“承办律师”不得被昵称替代；
- 文书中的称谓和主体顺序来自律师批准的事实快照，不能由模型根据聊天内容自行确定；
- 未被确认的身份映射在任何面向法院的文书中只可显示为中性证据描述，且应保留原始昵称与页码/记录位置。

## 5. 文书、导出和版本命名

- 对律师显示的文件名使用中文业务名，例如 `证据目录.pdf`、`利息核算说明.pdf`、`答辩状.docx`；
- 最终交付目录只允许一个可提交标记：`已锁定提交版`。不得同时出现“最终版”“最新版”“修订版”等会造成歧义的并列名称；
- 系统内部必须仍保留不可变版本 ID、创建时间、输入哈希、批准人和模板版本，以支持回放；这些信息放入元数据和审计，不污染法院文书正文；
- 导出前一致性检查必须检查姓名、角色、日期、金额、币种和案号在各文书间的冲突，不能仅检查中文文本是否存在。

## 6. 模型与外部服务约束

- 模型提示、OCR 请求和向量检索中的案件原文按最小必要原则传递；语言为中文不构成传递更多数据的理由；
- 模型输出必须返回结构化机器码、中文解释、证据定位和不确定性，不能只返回流畅的中文段落；
- 任何翻译、转写、简繁转换或英文辅助输出都必须是独立、可追溯的派生结果，并在调用前取得所需授权；
- 外部服务不得成为原始中文证据、官方法源或最终律师文书的唯一保存位置。

## 7. Phase 1 验收补充

同一套 5 人、9 项任务、45 分钟的可用性协议增加以下检查，不增加参与者或额外轮次：

1. 参与者在不查看技术详情时，能理解每个案件状态的中文含义及下一步；
2. 参与者能区分原始昵称、待确认映射和已确认主体；
3. 参与者能在 10 秒内识别每笔金额的币种、日期和证据位置；
4. 所有面向律师的核心流程不出现未经解释的英文机器码、英文按钮或模糊版本名；
5. 导出预览能明确显示“已锁定提交版”及其适用范围。

任一项导致高风险任务误批、误导出或误读，即按既有 Phase 1 失败/重测规则处理；不得以“律师能猜到”视为通过。
