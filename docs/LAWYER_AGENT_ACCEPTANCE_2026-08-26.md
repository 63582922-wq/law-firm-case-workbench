# 律师 Agent 真实能力验收（2026-08-26）

## 结论

整体结论：`FAIL`。

律师内容合同已经通过，确定性计算和权限边界已经通过；但本轮新鲜模型调用没有产出一份完整、可验收的结构化决策包，因此不能宣称律师 Agent 已经端到端通过。当前成果是“恢复候选”，不是新鲜运行成功，也不是执业律师批准件或法院提交件。

## 验收目标与材料

- 目标产物：律师案件决策包，而非案情复述或技术状态展示。
- 合成材料：88 页、11 个文件、47 条原始交易记录。
- 必须覆盖：金额冲突、还款举证、利率上限、现金证据、U2 款项性质、诉讼时效、港币阻断、重复交易控制。
- 必须交付：风险排序、争点/举证责任/证据缺口、对方最强主张与反驳、策略取舍、当事人问题、补证和程序行动、待律师决定事项、文书蓝图。
- 安全边界：全部为合成材料；模型不得生成正式金额、批准事实或立场、选择正式情景、锁包、发送或提交法院。

## 紧凑合同与根因判断

紧凑合同没有要求模型再生成整份律师包。模型只负责：8 个争点及举证责任、4 个对方最强主张、2 套策略、6 个补证问题和 3 个必须由律师决定的理由；代码负责风险榜投影、期限动作、登记选项、文书章节和全部正式金额。输入控制估算为 19,952 个字符，低于隔离调用的 28,000 字符门，且提示中没有四情景金额。

本次仍在 4,000 token 处终止，说明输入和登录不是当前阻断。阿里云百炼官方结构化输出文档明确提示：结构化输出不应设置 `max_tokens`，否则 JSON 可能在结束前被截断。项目原调用仍设置了该参数，这与三次截断现象一致，是当前最有证据的根因，而不是模型法律分析能力已经被证明不合格。

代码已按 [ADR-0042](../decisions/ADR-0042-lawyer-package-structured-output-budget.md) 离线修正：律师包调用不再发送 `max_tokens`；按 `qwen3-vl-plus` 官方 32,768 token 最大输出能力和当前价格层做 0.40 元最坏费用预检；返回后仍要求核心 JSON 不超过 12,000 字符，并执行来源、法源、金额和权限边界校验。该修正没有再次调用模型，状态是 `IMPLEMENTED_NOT_RUN`。

## 单一下一目标

用已经修正的“无截断参数 + 最坏费用预检”合同，只执行一次新的独立调用。通过条件必须同时满足：

1. 获得完整结构化响应；
2. 证据、法源、情景和决定非法引用均为 0；
3. 正式金额全部来自确定性工具且独立复算一致；
4. 生成的 PDF 与 DOCX 均通过渲染检查；
5. 保持律师批准、锁包和提交权限边界。

若该次仍失败，停止重复验证，并评估改用支持严格 JSON Schema 的文本模型；不再通过登录、重开页面或反复付费调用绕过问题。通过后再将决策包接入受管案件 Worker 和律师工作台。
