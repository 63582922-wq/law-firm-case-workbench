# 证据派生 PDF Worker 契约

状态：`合成 Worker、主动内容剥离、渲染核验、加密本机对象库、Keychain 只读取钥和短时读取已实现；真实案卷验收未完成`

## 输入门

Worker 的唯一页选择输入是当前锁定的证据 Manifest。Manifest 必须含连续派生顺序、来源文件 UUID、来源页码和已批准红框。来源文件通过律师已确认的案卷根指纹、相对路径、登记 SHA-256 和页数重新核对；绝对路径不进入谱系 JSON 或数据库。

## 输出内容

- `related-pages.pdf`：只复制锁定 Manifest 中 `INCLUDE` 的来源页；
- `related-pages-red-box.pdf`：页序和内容相同，仅叠加 Manifest 中已批准红框；
- `evidence-derivative-lineage.json`：记录 Manifest、来源文件哈希、来源页、派生顺序、坐标和两份 PDF 哈希。

不得添加封面、说明页、案号、推断性标题、AI 描述或其他无关内容。文件名稳定，不使用“最新版、最终修订版”等后缀；版本由 Manifest、内容哈希和 Git/数据库历史表达。

## 坐标与 PDF 安全

坐标采用左上角原点的归一化矩形：`0 <= x0 < x1 <= 1`、`0 <= y0 < y1 <= 1`。转换到 PDF 左下角坐标时使用 `x=x0*width`、`y=(1-y1)*height`。当前 Worker 对加密、旋转、裁切、页数不符、哈希变化、符号链接和越界路径全部 fail closed。来源页的链接注释、自动动作、表单/附件目录与演示动作不会进入派生 PDF；生成后的目录和页字典再次执行主动内容检查。

## 验证与存储

两份 PDF 生成后重新打开，并以 144 DPI 通过 Poppler 渲染。页数必须与 Manifest 一致；无红框页的两个版本必须像素一致；有红框页必须存在可检测的视觉变化和红色描边。验证通过后，明文 PDF 进入 AES-256-GCM 本机受管对象库，键为内容 SHA-256，临时明文自动清理。

数据库先登记 `CANDIDATE` 派生件，再以绑定 Manifest 哈希、PDF 哈希、对象键和渲染结果的验证哈希转为 `VERIFIED`。普通证据快照只显示类型、哈希、页数和状态，不返回加密对象键。

律师基于当前案件版本和 Manifest 哈希建立 `QUEUED` 任务。系统 Worker 以 30—300 秒租约领取任务，并在长任务期间以同一租约心跳续期；心跳不改变案件业务版本。进程中断后只有租约过期的 `RUNNING` 任务可恢复，最多三次。Worker 的派生登记与核验命令使用 run ID 派生的稳定幂等键；只有相关页版和红框版都处于当前 Manifest 的 `VERIFIED` 状态，任务才能变为 `SUCCEEDED`。上游证据变化会在同一事务中把排队、运行、成功或失败的旧任务标记为 `STALE`。

macOS 第一实现以只读方式从 Keychain 取得 AES 密钥，不接受浏览器、API 或项目环境文件中的密钥。派生件读取采用与 OS 本机会话、案件和派生件绑定的一次性短时 Bearer，仅限 loopback；对象键不返回浏览器，详见 `ADR-0007`。
