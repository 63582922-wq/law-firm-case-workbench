# 主体、别名、账号与代理关系契约

状态：`内部合成 Alpha 领域契约；待真实律师流程验证`

## 1. 候选不是身份结论

- 起诉状、聊天、流水、OCR、助理录入和模型抽取的姓名、微信昵称、账号、银行卡、电话，均先建立为候选 `Party` 或 `PartyIdentifier`，并回链到原始文件哈希、页码和区域。
- `Party`、`PartyIdentifier` 与 `Representation` 分别需要承办律师确认。系统不得因为显示名称相似、手机号相近或聊天中互称某名称，就自动合并主体或确认代理关系。
- 有误对象必须标记 `INVALIDATED` 并从原始证据重建；上游主体失效会使其已确认的别名、账号和代理关系全部失效。

## 2. 账号与别名的冲突控制

- 每个标识保存原始值、类型和用于冲突提示的标准化键；原始值不被标准化键替代。
- 同一类型、同一标准化键的标识，不能同时被确认指向两个不同主体。系统保留冲突候选，要求律师重新核验，不会自行择一。
- 正式身份快照只包含已确认主体、已确认标识和已确认代理关系；任何对象指向未确认主体或存在冲突都会阻断快照。

## 3. 代理关系

- `Representation` 明确区分被代理主体、代理人主体和权限范围：全权、部分、代收文书或其他。它不把律师事务所名称、律师姓名或联系方式推断为“全权代理”。
- 代理关系只记录经律师核验的授权范围和来源位置。是否可代为签署、是否存在期限限制或是否需要另附授权材料，由后续文书与提交校验按具体模板检查。

本模块仅提供结构化案件事实对象；敏感标识符的本机加密、最小展示、访问控制、持久化审计和真实案件接入仍属于后续安全实现，不能由合成 Alpha 替代。
